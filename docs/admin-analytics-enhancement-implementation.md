2026-10-16 KST. 사용자가 [독립 미리보기](admin-analytics-enhancement-preview.md)의 실제 앱 적용을 승인했다. [설계](admin-analytics-enhancement-design.md)와 [추가 검토](admin-analytics-enhancement-review.md)를 반영한 구현이다. 이후 사용자가 최종 검증·버전 관리·운영 배포를 승인하여 v1.13.0으로 릴리스한다. 현재 운영 적용과 복구 경계는 [릴리스 기록](admin-analytics-enhancement-rollout.md)을 따른다.

## 실제 화면과 자료

기존 `/admin/analytics`의 7개 탭과 회원 활동·관리자 조회 이력을 유지한다. 승인된 레이아웃·색상·타이포그래피는 `admin-analytics-enhanced.css`의 `.analytics-enhanced` 내부에만 적용한다. `AnalyticsOverview`는 실제 기존 dashboard/feed API를 사용하며 기존 `AdminDashboard`는 분리 미리보기용 재사용 컴포넌트로 남긴다.

- 공통 기간·채널·직전 비교, 지표 선택·정확한 표·상세 이동·지표 정의 모달을 제공한다. 장기 기간의 확장 분석과 원본 상세는 최근 90일 교집합으로 제한하며 실제 날짜를 표시한다.
- 개요는 날짜별 가용성/수집 공백을 포함한 수집 품질, 회원 수×회원당 채점 분해, 복습·반복 간격, 실제 실행 앱 버전 집계를 추가한다. 기존 PWA 채널 교집합·오늘 잠정 수치·최근 회원 활동도 실제 API로 표시한다.
- 기능은 화면 유형별 사용 가능→실제 노출→실행→성공 결과와 노출 미관측 실행을 구분한다. 기능 교집합은 회원 DISTINCT, 진입별 도달은 세션에서 처음 수집된 라우트 기준이다.
- 채점은 관찰 종료 입력 흐름/실행, 진행·유예·미확정·연결 불완전, 로그인 완료 실행의 과목별 저장 응답, 기기별 요청/결과, 계산·과목 저장·저장 종료 후 표시 시간을 구분한다.
- 회원/PWA 코호트는 D1·정확한 D7·W1(D+7~D+13)·D30을 제공한다. 첫 채점 후 복습은 정확한 7×24시간을 검사한다. 관찰 미완료·수집 공백·최초 불명은 별도 분모 제외다. 기존 Auth/현재 보관 집계와 설치 신호는 별도 출처로 유지한다. PWA의 푸시 집계는 기존 `PushSubscriberStats`/admin-push 통계 API를 재사용하고 실행 코호트와 합산하지 않는다.

실제 앱에 가상 미리보기 자료나 정상/오류 상태 선택기를 넣지 않는다. 자료 미가용·미관측·미성숙·필터 미지원·조회 오류를 0으로 대체하지 않는다. 같은 프레임의 탭·기간·채널 변경은 동기적으로 보관한 선택을 합성해 이전 탭/범위가 덮어쓰지 않게 한다. 일시 갱신 실패는 같은 계정·보고서·필터의 이전 자료만 유지하고 이전 조회 시각을 표시한다. HTTP 401/403은 기존 공유 권한 범위에서 모든 탭·선택·개인 행을 제거한다. 개인 검색어·UUID는 공유 URL에 기록하지 않는다.

## 집계 계약과 보관 경계

`GET /admin-analytics/insights`는 기존 JWT 확인·관리자 역할 RPC에 더해 SQL에서 현재 관리자를 재검사한다. `report`와 기존 허용된 비개인 필터만 받으며 기간은 최대 90일이다. service-only SECURITY INVOKER `product_analytics_insights_source`가 한 읽기 스냅샷의 최소 사실을 Edge 내부에 제공한다. `analytics-insights.ts`가 집계 DTO `insights_version=1`만 브라우저에 반환한다. 원본 UUID·이벤트·답안·메모·점수·이메일은 이 DTO에 없다. 개인 상세 조회는 기존 감사 API를 계속 사용한다.

원본은 기존 90일 조회 범위, 장기 그래프는 기존 발행 자료를 사용한다. 원본과 발행 자료를 합쳐 중복 계산하지 않는다. 새 source는 선택 직전 대응 기간부터 조회하되 90일 가용 경계로 제한하고 현재 스냅샷까지 읽어 선택 종료 후 결과·저장·재방문을 연결한다. source는 이벤트/최초 이용 각 20,000행을 넘으면 조회를 실패시키며 10초 제한을 둔다. 부분 원본을 잘라 완전한 비율로 반환하지 않는다. 운영 규모의 부하 검사는 이번 합성 검증에 포함하지 않는다.

관측 가용성은 수집 시작·90일 경계·조회 시각·확인된 중단 구간으로 판단한다. D7은 반환 KST 날짜 전체, W1은 전체 7일 창, 첫 채점 복습은 각 회원의 정확한 후속 구간을 검사한다. 최초 날짜에도 공백이 있으면 제외한다. 알려지지 않은 누락이나 수집 차단까지 완전 관측으로 보장하지 않는다. 집계는 최신 읽기 시점 기준이며 과거 공유 결과의 불변 스냅샷은 추가하지 않는다.

입력 흐름은 행위자+세션+입력 ID, 실행은 행위자+실행 ID로 연결한다. 진행(<30분), 유예(30~45분), 불확실 세션은 확정 퍼널에서 제외한다. 새 결과는 요청과 계산 완료가 연결되어야 도달로 센다. 과목 조건은 입력 시점에 확정되지 않으므로 입력 퍼널에 미지원이며 실행 기준으로 확인한다. 처리 결과 조건은 전체 단계의 분모를 파괴하므로 확장 분석을 제공하지 않고 행동 상세로 안내한다. 코호트는 기간만 지원하며 PWA 코호트는 전체/PWA 채널도 허용한다. 회원 간격은 서로 다른 KST 복습일의 회원별 중앙 간격을 다시 요약하고 한 번만 관측된 회원 수를 함께 표시한다.

## 추가 계측

수집 wire `metric_version=1`과 기존 이벤트 의미는 유지하고, 새 속성·이벤트를 명시 허용 목록으로 검증한다. `app_version`은 package.json 버전의 숫자 3항 형식이다. 구버전 이벤트는 미확인으로 남긴다.

| 신호 | 조건·중복 기준 |
|---|---|
| tool_available | 기능 권한·자료가 준비된 문맥. 화면 진입+결과 문맥+도구 |
| tool_exposed | visible 문서에서 실제 조작 요소가 IntersectionObserver로 관측됨. 동일 문맥 중복 제거 |
| tool_used / tool_result | 명시적 조작의 UUID. 결과는 동일 문맥·operation_id로 연결된 성공만 완료 |
| client_timing | 실행+구간+과목. performance.now의 전체/visible 시간, 최대 1시간 |
| grading_validation_failed | 빈 입력으로 조기 반환하는 기존 검증의 허용 코드 EMPTY_INPUT |

`ResultTelemetryProvider`/`useToolTracking`은 새 결과·과거 결과·예시·기출을 구분하고 문항별 신호를 과목 문맥으로 중복 제거한다. 문항별 스크롤 로그나 원본 입력은 보내지 않는다. 계정 세대 또는 화면 진입이 바뀐 뒤 늦은 결과는 새 사용자에게 귀속하지 않는다. 답안 수정·분야 펼침·분포 열기·메모 저장의 기존 동작은 유지한다. 메모의 예시 결과는 분석에서 제외한다.

사용 가능·노출·시간 신호는 실제 조작이 아니므로 클라이언트 무활동 시간을 연장하지 않으며 SQL에서도 active/core와 세션 활동 상태를 갱신하지 않는다. 기존 수집 off/origin 제한·관리자 제외를 유지한다. 이 추가 이벤트를 보내기 전에 새 DB/Edge가 준비되어야 한다. 과거 기능 노출·시간·앱 버전은 소급 생성하지 않는다. 저장 응답은 클라이언트 관측이며 서버 저장 확정을 추가하지 않았다. 저장 병렬화나 결과 선표시도 하지 않는다.

## 마이그레이션과 적용 순서

Supabase CLI 2.119.0으로 생성한 `20261016121746_analytics_insights.sql`은 기존 `_v1` 수집 베이스 함수에 수동 조작 없는 신호의 active 제외와 의미 중복 키를 추가한다. 기존 공개 ingest wrapper의 활성 계정 확인·`user_data_analytics` advisory lock·삭제 tombstone 처리는 교체하지 않는다. 기존 report에는 반환 날짜의 가용성/공백 검사를 보완하고 새 source RPC만 추가한다. 새 테이블·클라이언트 정책·데이터 수정·수집 활성화·발행·정리·예약 작업은 없다.

원격 스키마·RLS·RPC grants와 마이그레이션 이력을 읽기 전용으로 확인했다. `20261005052901_admin_user_data`의 wrapper와 `_v1` 베이스가 있는 상태를 전제로 하며 선행 함수가 없으면 마이그레이션을 실패시킨다. 새/수정 함수는 anon·authenticated·PUBLIC EXECUTE를 차단하고 service_role만 허용한다.

사용자의 운영 적용 요청에 따라 현재 함수 정의·운영 이력을 다시 대조하고, DB → usage-events/admin-analytics → 웹 순서로 적용한다. 함수는 기존 배포 경로를 사용하며 복제된 `src/supabase/functions/server`를 배포하지 않는다. 적용 전 정의를 보존하고 문제가 생기면 웹/Edge를 이전 버전으로 되돌린 뒤 DB 함수 정의를 검토해 복구한다. 실제 적용·검증 결과는 [릴리스 기록](admin-analytics-enhancement-rollout.md)을 따른다.
