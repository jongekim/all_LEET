# all LEET GEO 개선 설계

기준은 2026-11-11 운영 v1.13.1의 공개 응답이다. 먼저 로컬에서 검증한 HTTP 응답과 커뮤니티 HTML 개선을 배포 후보로 검토한다. 이어 기출문제에서 공개 데이터 기준 문서를 열고, 환산표에서는 표준점수와 백분위를 숫자로 표시한다. [GEO 점검 보고서](../all-leet.vercel.app-audit/geo-2026-11-11/GEO-AUDIT-REPORT.md)

## 1차 배포 후보 · HTTP 응답과 커뮤니티

기존 [비화면 SEO 구현](seo-nonvisual-improvements.md)을 v1.13.1 기준으로 격리해 다시 검증한다. 기출 학년도 링크, 홈 답안 라벨, 커뮤니티 첨부 미리보기처럼 이미 배포된 변경을 포함한 상태에서 검사한다.

| 요청 | 목표 응답 |
|---|---|
| 없는 경로·없는 자산 | HTTP 404 |
| 로그인·회원가입·비밀번호 재설정 등 유효한 인증 경로 | HTTP 200 및 최초 응답의 경로별 제목과 `noindex` |
| 기출 학년도·과목·문형 조합 | HTTP 200, 해당 시험 본문, 기존 정규 URL 규칙 |
| 커뮤니티 목록·공개 글 | HTTP 200, 첫 HTML에 공개 본문과 경로별 제목·canonical |
| 없는 커뮤니티 글 또는 비정상 ID | HTTP 404 |
| 커뮤니티 공개 조회 실패 | HTTP 503 및 `Retry-After` |

커뮤니티는 기존 Vercel Node 함수의 요청별 익명 SELECT와 공개 RLS를 사용한다. 최초 HTML과 브라우저 전환에 비공개 데이터가 섞이지 않는지 확인하고, 삭제·공개 상태 변경이 오래된 캐시에 남지 않도록 기존 `no-store` 계약을 검증한다. 배포 후보의 기준 화면은 v1.13.1로 잡고 320px·390px·1280px에서 기출과 홈, 커뮤니티 화면을 비교한다. 운영 상세 검사는 브라우저의 조회수 증가가 발생하지 않는 HTTP GET으로 한다.

## 2차 배포 후보 · 데이터 기준 문서와 환산표

### 기출 화면 제안

기출문제의 **시험 선택 카드 아래에 ‘기출 데이터 기준’ 링크**를 추가한다. 정답표를 펼치기 전에도 보이는 위치다. 기존 ‘통계 집계 기준’과 ‘점수 환산 기준’ 모달에는 각각 문서의 해당 절로 가는 링크를 추가한다. 환산표의 세 열에는 맞은 개수, 표준점수, 백분위를 표시한다.

```text
기출문제·정답표
  시험 선택
  학년도별 기출 ▾
  기출 데이터 기준 →

정답표·점수 환산표 [보기]
  점수 환산 기준
  맞은 개수    표준점수    백분위
  21개         54.3        29.3
```

표의 예시는 실제 2027학년도 추리논증 데이터다. 등록 값이 없는 셀에는 기존 `—`를 표시한다. [2027학년도 데이터 근거](grading-2027.md)

### 공개 문서 구성

제안 URL은 `/past-exams/data-guide`이고, 페이지 제목은 **기출 정답·정답률·점수 환산 기준**이다. 상단 목차를 통해 각 절로 바로 이동할 수 있게 한다.

| 절 | 공개할 내용 |
|---|---|
| 정답과 문제지 `#answer-keys` | 학년도·과목·문형을 맞춰 확인하는 방법, 기존 채점에 쓰는 정답과 정답표의 관계, 확인 가능한 출처·권리 표시 |
| 문항별 정답률 `#question-statistics` | 분모는 집계 대상인 저장 풀이 기록, 분자는 해당 문항 정답을 고른 기록이다. 반복 저장 풀이를 포함하고 미응답은 분모에 포함한다. 홀짝 공통 문항의 합산, 실제 시험 응시자 모집단과의 차이, 통계 미제공·표본 없음 상태의 의미를 설명한다. |
| 표준점수와 백분위 `#score-conversion` | 2027학년도 환산표의 자료 출처와 표준점수·백분위 산출 방법을 설명한다. 발행 기관을 확인하지 못한 자료는 그 확인 범위를 명시한다. |
| 정정 문의 `#corrections` | 기존 문의 주소와 함께 학년도·과목·문형·문항 번호 또는 맞은 개수를 전달하는 방법을 안내한다. |

공개 문서의 갱신일은 문서 편집 이력을 뜻한다. 집계 건수, 집계일, 개별 풀이 정보는 기존 비공개 범위를 따른다. 문구는 [문항 통계 v2](question-statistics-v2.md)와 [2027학년도 채점 데이터](grading-2027.md)를 근거로 검토한다.

### 구현 연결

- `src/pages/`의 정적 안내 페이지를 `src/App.tsx` 및 `src/utils/appRoutes.ts`에 등록한다. `src/utils/pageSeo.ts`의 공개 경로와 페이지 메타데이터에 추가하고, 기존 사전 렌더링·Vercel rewrite·사이트맵 생성 경로로 제공한다. 사이트맵의 수동 경로 배열도 같이 갱신해 누락을 방지한다.
- `PastExamsPage`는 공개 문서 링크를 제공하고, `DataMethodDialog`의 두 설명창은 해당 앵커로 연결한다. 브라우저 직접 진입과 앱 내 이동에서 모두 앵커가 동작하고, 뒤로 가면 기존 학년도·과목·문형 URL이 복구되도록 확인한다.
- `ScoreConversionTable`은 표준점수와 백분위를 소수점 첫째 자리까지 표시한다. 화면, 최초 HTML, 보조기술에서 같은 숫자를 제공한다.
- 기존 로컬 `WebPage` JSON-LD를 공개 문서에도 적용한다. 공통 `WebSite` 식별자, 홈의 `WebApplication`, 검증된 운영 주체 정보는 실제 공개 콘텐츠와 대조한 뒤 보강한다.

## 검증과 배포 순서

1. **비화면 변경 검증** · 깨끗한 릴리스 사본에서 `npm run check`를 실행한다. 운영 배포가 요청되면 실제 Vercel에서 404, 인증 `noindex`, 커뮤니티의 공개 본문·캐시 헤더, 기출 canonical을 읽기 전용으로 확인한다.
2. **화면 승인** · 기출 링크 위치, 두 모달의 문서 링크, 공개 문서 문구, 환산표 셀 표기를 실제 코드 기반의 별도 미리보기로 검토한다. 승인 범위에 맞춰 앱 화면을 수정한다.
3. **콘텐츠 변경 검증** · JavaScript 없이 문서가 HTTP 200이고 H1·본문·self-canonical·사이트맵 항목이 일치하는지 본다. 2027 추리논증 21개 행에 54.3과 29.3이 표시되는지, 자료 없는 셀과 320px 표 배치, 키보드와 뒤로 가기, 기존 홀짝 링크를 확인한다. 표준점수·백분위 숫자는 승인 전 기준과 대조한다.
4. **운영 효과 측정** · 접근 권한이 있는 경우 Search Console에서 홈·기출·안내 문서의 색인과 생성형 AI 노출을 확인하고, Bing AI Performance에서 인용 URL을 본다. 배포 전 기준과 28일 후를 비교한다. [Google 보고서](https://developers.google.com/search/blog/2026/06/gen-ai-performance-reports), [Bing AI Performance](https://blogs.bing.com/webmaster/2026/2/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview/)

`llms.txt`는 별도 소비자와 관리 목적이 확인되면 검토한다. 현재 우선순위는 잘못된 HTTP 200과 공개 데이터 설명을 개선하는 것이다. [Google AI 검색 가이드](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)
