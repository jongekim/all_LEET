# 자동 알림 팝업 표시 규칙

2026-10-13 사용자 요청에 따라 자동 팝업을 최초 동의 가능한 상태에만 제한했다. v1.12.1의 네이버앱 제외는 유지한다. 설치 필요·권한 차단·웹 알림 미지원 안내와 허용 후 등록 재확인 안내는 자동 팝업에서 제거했다. 녹색 PWA 설치 버튼의 수동 안내와 관리자 알림 등록 UI는 별도 흐름이며 유지한다.

## 표시 조건

아래 조건을 모두 만족할 때 일반 서비스 화면에서 약 3초 뒤 표시한다. 관리자 화면·네이버앱은 진입 단계에서 제외한다.

1. 프론트 기능 스위치와 현재 origin이 허용됨.
2. 실제 웹 알림 등록을 지원함.
3. 현재 브라우저 알림 권한이 `default`임. `granted`와 `denied`는 제외.
4. 브라우저에 알림 허용 이력이 없음.
5. 구독 상태가 `active`나 `pending`이 아님.
6. ‘나중에’·X·Esc·바깥 클릭으로 저장한 7일 유예가 끝남.
7. 현재 팝업 인스턴스에서 이미 동의를 완료하지 않음.
8. 현재 탭이 보이며 다른 dialog가 열려 있지 않음. 다른 dialog는 1초 간격으로 대기.

팝업은 홈 화면 실행 여부로 문구나 설치 안내를 선택하지 않는다. 지원 여부는 `usePushSubscription`이 판단한다. 기존 API 존재·secure context와 실제 등록 가능 조건을 함께 사용하며, iOS의 홈 화면 미설치 상태는 기존 `subscribe()`가 실행되지 않는 환경이므로 미지원으로 취급한다. iOS 일반 브라우저에 일부 API 이름만 노출되어도 실행 불가능한 허용 버튼을 보여주지 않는다.

표시 가능한 경우에는 기존 “all LEET 소식을 놓치지 마세요”와 동의·나중에 버튼만 제공한다. 화면이 열린 뒤 권한·지원 상태·등록 상태가 제외 조건으로 바뀌면 즉시 숨긴다.

## 허용 이력과 유예

- `all-leet:push-permission-granted:v1`: 값 `1`은 허용 이력이 있음을 뜻한다. 자동 만료시키지 않는다. 사용자 ID나 서버 구독 상태를 저장하지 않는다.
- 현재 `granted` 권한을 관찰했거나 기존 로컬 설치 증명 또는 서버 상태를 확인하면 허용 이력을 보완한다. 실제 동의에서 허용한 경우에는 서버 등록 요청보다 먼저 기록한다. 기존 설치 증명은 권한 허용 후 `registerPush`에서 생성되므로 과거 허용의 근거로 사용한다.
- 허용 후 등록이 실패해도 새로고침·재접속·7일 경과 뒤 자동 팝업으로 재등록을 요청하지 않는다. 현재 권한이 `default`로 초기화되어도 보존된 허용 이력이 있으면 제외한다.
- 기존 `all-leet:push-prompt-snooze:v1`에는 닫은 시점부터 7일 뒤의 시각을 유지한다. 허용 이력과 7일 유예는 별도 키이며 동의로 닫을 때 유예를 기록하지 않는다.
- 같은 origin의 탭 간 storage 이벤트와 화면 복귀 때 이력·유예를 재확인한다. 다른 탭에서 허용하면 열린 팝업도 숨긴다.
- 이력은 해당 브라우저 저장소 범위다. 사이트 데이터 삭제·저장 차단 및 이미 초기화된 과거 권한 이력의 소급 복원은 보장하지 않는다. 저장 실패가 실제 권한 요청·서버 등록을 막지는 않는다.

## 검증과 적용 범위

`PushConsent.test.tsx`는 표시/제외 조건·허용 후 실패/권한 초기화·교차 탭·7일 유예·상태 변경 후 즉시 숨김을 검사한다. `pushInstallation.test.ts`는 기존 설치의 서버 조회 실패 이전 이력 보존을 확인한다. `usePushSubscription.test.tsx`는 현재 허용/기존 설치의 이력 보완·등록 실패 이전 기록·저장 차단·iOS 실제 지원 판단을 확인한다. `e2e-push/push.spec.ts`는 모든 Supabase API를 모의 처리하여 허용·차단·미지원·iOS 일반 브라우저·보존 이력·네이버앱·직접 진입·새로고침을 확인한다. 실제 OS 권한 및 운영 등록/발송은 실행하지 않는다.

DB·Auth·RLS·Storage·Edge Function 계약과 배포 설정은 변경하지 않는다. 사용자의 명시적인 배포 요청에 따라 v1.12.2 PATCH 릴리스로 반영한다. 버전 검증과 전체 품질 게이트를 통과한 뒤 관련 변경만 커밋하여 main push로 웹을 배포하며, 배포 성공과 실서비스 표시 조건을 읽기 전용으로 확인한다.

2026-10-13 v1.12.2 릴리스 검증: 버전 일치 검사와 전체 `npm run check`가 종료 코드 0으로 통과했다. lint 오류 0개/기존 경고 52개, typecheck·문항 레지스트리·SQL/Edge 모의 검사, 전체 단위 검사 318개, 푸시 화면 검사 22개, 기존 화면 검사 96개, fixture HTML 검사 10개, 테스트 빌드 및 최종 운영 공개 GET 빌드를 확인했다. 운영 빌드는 공개 페이지 83개와 공개 문항 통계 38개 조합·발행본 1을 생성했다. 실제 등록·발송은 실행하지 않았다.

초기 검사에서 발생한 ENOSPC는 디스크 공간 확보 후 해결했다. 기존 설치의 서버 조회 실패 검사는 별도 route의 모의 503 응답을 직접 기다리도록 보완하여 요청 집계 경로 차이와 비동기 완료 시점에 영향을 받지 않는다. 최종 검사는 원래 Playwright 설정(화면 워커 2개·실패 시 trace 유지)으로 실행했다. Vitest 워커만 환경 변수로 최대 2개로 제한했고, 임시로 조정했던 화면 검사 설정은 모두 복원했다.
