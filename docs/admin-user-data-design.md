# 관리자 사용자 데이터

작성·구현 기준: 2026-10-05, v1.7.0. 사용자 정책 답변과 개발 요청을 반영한 구현 계약이다. 과거 검토는 [개발 전 검토](admin-user-data-review.md), 검증과 운영 절차는 [구현·운영](admin-user-data-implementation.md), 실제 배포 상태는 [운영 적용 기록](admin-user-data-rollout.md)을 참고한다.

## 화면과 데이터 범위

기존 관리자 메뉴에서 `/admin/user-data`에 진입한다. 이름·이메일 부분 검색과 UUID 검색, 드롭다운으로 모든 현재 계정을 선택한다. 관리자·테스트 계정을 제외하지 않는다. Auth 계정이 없어도 영구 지원 분석이 남아 있는 UUID는 선택할 수 있다. 새로고침 시 선택·편집 입력을 초기화한다. 검색어·선택 UUID·개인 기록을 URL이나 브라우저 영구 저장소에 넣지 않는다.

실제 관리자 인증은 유지한다. 선택 사용자로 로그인하거나 AuthContext의 사용자를 바꾸지 않는다. 일반 사용자 페이지의 입력·문구·레이아웃·이동·동작은 유지한다. 관리자 영역에서 기존 표시 컴포넌트에 데이터와 관리용 콜백을 주입한다.

| 영역 | 조회·표시 | 변경 범위 |
|---|---|---|
| 기출 채점·성적 추이 | `HistoryPage`, `TrendChart`, `ResultPage` 재사용 | 답안·정답 수·표준점수·백분위·보정 점수 직접 수정, 항목별 선택 재계산, 삭제 |
| 사설 성적·추이 | `HistoryPage`, `MockTrendChart` 재사용 | 시험일·시험사·회차·과목 점수 수정, 삭제 |
| 문항 메모 | 결과 패널과 독립 목록 | 내용 수정·삭제. 기출 삭제 시 정확한 회차·과목 메모 함께 삭제 |
| 지원 분석 | 실행 목록과 `AdmissionResultPage` 재사용 | 입력 수정 시 현재 기준 재계산, 삭제 |
| 게시글·댓글 | `CommunityPostBody`와 관련 댓글 | 선택 사용자 본문·분류 수정, 기존 이미지 제거·새 이미지 추가, 삭제 |
| 좋아요·신고·공지 참여 | 원본 개인 행 | 좋아요·신고 삭제, 공지 댓글 내용 수정·삭제 |
| 저장 이미지 | 소유 경로의 파일 목록·미리보기 | 고아 이미지 삭제. 게시글에서 참조 중이면 단독 삭제 차단 |
| 채팅 | `ChatMessageList`로 선택 사용자 말풍선·대화 맥락 표시 | 선택 사용자 메시지 내용 수정·삭제, 닉네임 변경 시 과거 메시지 닉네임도 변경 |
| 이용 원본 | 관측 이벤트 목록·상세 | 조회·삭제만 허용. 날짜·행동 종류·내용 편집 없음 |
| 이용 파생 자료 | 일별 이용·최초 이용·발행 사실·세션 상태·채팅 제한 | 조회 전용. 원본 이용 삭제 시 서버가 관련 파생 자료 처리 |
| 계정 | 이름·이메일·생년월일·대학교·가입/인증 시각·UUID | 이름만 수정. 닉네임은 별도 채팅 프로필에서 수정 |
| 관리자 감사 | 사용자 데이터 감사와 기존 통계 조회 감사 | 조회만 허용 |

기출의 학년도·문형·과목·회독·timestamp·groupTimestamp는 변경하지 않는다. 이메일·비밀번호·권한·계정 차단/탈퇴 기능을 제공하지 않는다. 타인 댓글·채팅 맥락은 조회 전용이다. 게시글 삭제에 포함되는 타인 참여는 승인 영향에 포함한다.

서버에 남아 있는 실제 자료만 표시한다. 관리자 이력 0건에는 예시를 넣지 않으며, 일반 사용자 예시 동작은 유지한다. 삭제되거나 저장되지 않은 데이터·입력 중 상태·과거 브라우저 지원 분석을 복원하지 않는다. 과거 기기 상태를 재연하는 기능은 아니다.

## 조회 계약

관리자용 `admin-user-data` Edge Function이 매 요청 JWT의 실제 사용자를 검증하고 현재 관리자 여부를 확인한다. service role 전용 SQL RPC도 `private.admin_roles`를 재검사한다. anon/일반 회원은 개인 관리자 RPC와 신규 private 테이블에 접근할 수 없다. 브라우저에는 기존 anon 키만 사용한다.

회원·관계형 원본 목록은 서버에서 50건씩 반환한다. 차트용 기출·사설 요약은 전체 범위의 최소 필드를 반환하고 답안·정답·분야 분석은 상세 요청에서만 반환한다. 관리자 이력 목록은 페이지당 최대 50개 묶음이다. 선택 대상 또는 탭 변경 시 이전 요청을 취소하고 늦은 응답을 폐기한다. 401/403이면 선택·개인 자료·편집·승인 상태를 지우고 추가 조회를 중단한다.

서명 참조는 관리자·대상 UUID·영역에 묶는다. 기출은 전체 배열 스냅샷 해시와 정확한 배열 위치를 포함하고 관계형 자료는 키와 행 해시를 포함한다. 클라이언트가 임의로 참조를 다른 사용자나 영역에 옮길 수 없다. 게시글 관련 댓글은 상세에서 50건씩, 채팅 맥락은 선택 메시지 전후 5분 안에서 가까운 최대 100건을 표시한다. 제한은 관리자 상세에 표시한다.

조회 감사에는 대상·영역·반환 건수·상태를 남기고 검색어·답안·본문·GPA 전체를 복구용으로 보관하지 않는다.

## 수정·삭제 승인

1. 수정 입력 또는 삭제 선택으로 서버 `prepare`를 호출한다. 실제 자료는 바꾸지 않는다.
2. 확인창에 대상, 선택한 원본 식별 정보(최대 20개), 적용할 patch, 연결 자료 영향 항목·건수, 현재 계산 규칙 버전을 표시한다.
3. 매번 `이 과정은 데이터 수정을 수반합니다. 정말로 진행하시겠습니까?`를 표시하고 관리자가 `승인`을 직접 입력한다. 붙여넣기·드롭 입력은 막고 한글 조합 중 적용하지 않는다.
4. 서버 `commit`은 정확한 문자열·실제 관리자·작업 소유자·유효 시간·원본과 연결 자료의 동일성을 다시 확인한다.
5. DB 변경·작업 소비·감사는 같은 트랜잭션에서 실행한다. 같은 작업 재전송은 DB 변경을 반복하지 않는다. 바뀐 원본은 충돌로 반환하고 다시 조회·승인한다.

prepare 유효 시간은 10분이다. 원본 이전 값·복구 백업·soft delete·휴지통은 없다. 완료된 작업의 제안 patch는 비운다. unknown 외부 작업은 결과 대조에 필요한 제안 값/파일 manifest만 유지한다.

기출은 수동 입력과 재계산을 각 항목별로 선택한다. 같은 필드를 둘 다 지시하면 오류다. 정답률은 `correct/total` 표시 파생값이다. 정답표·정답 수·분야 분석·표준점수·백분위·보정 점수를 개별 선택하며 선택하지 않은 값은 유지한다. 점수 계산은 선택된 정답 수 또는 현재 저장 정답 수를 기준으로 현재 서비스 점수표를 사용한다. 계산 자료가 없으면 임의 추정하지 않는다. 관리자 수정은 기존 공개 문항 통계 발행본을 자동 재발행하지 않는다.

모든 KV 변경자는 `user_history_mutate`의 같은 키 advisory lock을 사용한다. 커뮤니티·채팅·메모·공지 참여의 기존 소유자 쓰기도 statement trigger로 같은 관계 잠금을 잡아, 승인 검사 뒤 타인 댓글 추가와 같은 경합을 직렬화한다. 연결 행의 내용/식별자가 바뀌었으면 건수가 같아도 충돌한다.

## 이미지와 외부 작업

이미지는 기존 사용자 압축 유틸리티를 재사용한다. JPEG·PNG·WebP·GIF 입력 파일 20MB 이하, 압축 후 5MB 이하, 합계 최대 5장이다. 선택 시 브라우저 blob 미리보기만 만들며 prepare에는 파일 이름·크기·타입·SHA-256 manifest를 보낸다. 서버가 대상 사용자/게시글 아래 새 UUID 파일 경로를 정한다.

승인 후 multipart의 실제 바이트·타입·매직 헤더·SHA-256을 검증하고, 영속 실행 의도를 남긴 뒤 Storage 업로드한다. 업로드 파일을 다시 읽어 hash를 확인한 뒤 승인 당시 게시글이 그대로일 때 URL을 적용한다. 응답 유실/일부 업로드는 unknown으로 표시한다. 같은 작업 상태를 확인하거나, 파일이 현재 브라우저에 남아 있으면 새 `승인` 입력으로 같은 경로 업로드를 재시도한다. 새로고침 후 자동 재업로드하지 않는다.

게시글 삭제/첨부 제거와 파일 정리 outbox 등록은 한 DB 트랜잭션이다. 다른 게시글에서 같은 파일을 참조하면 물리 삭제하지 않는다. 삭제 대기 URL을 새 게시글 첨부로 연결하지 못하도록 DB에서 차단한다. 고아 파일도 같은 정리 경로를 사용하며 `storage.objects`를 직접 삭제하지 않는다. 정확한 프로젝트·버킷·대상 소유 경로를 검증한 Storage API로만 삭제한다. 외부 파일 정리가 실패하면 부분 완료로 표시하고 동일 승인 범위의 미처리 파일만 재시도한다. 공개 CDN/브라우저 캐시 무효화 시점까지 즉시 삭제되었다고 보장하지 않는다.

이름 변경도 Auth 외부 작업이다. 실행 의도를 먼저 기록하고 실제 metadata의 name만 변경한다. 다른 metadata를 보존한다. unknown 상태에서 같은 이름 변경을 자동 반복하지 않고 현재 Auth 이름과 대조한다.

## 이용 원본 삭제

삭제 이벤트 UUID와 actor_scope+semantic_key의 비복구성 해시를 tombstone에 남겨 늦은 재수신이 원본/집계를 되살리지 못하게 한다. 원본 이벤트, 영향 일자별 활동·발행 사실·세션 pending 목록·최초 이용을 같은 트랜잭션에서 처리한다. 수집과 발행도 공통 잠금을 사용한다.

원본이 보존된 영향 날짜는 현재 집계 규칙으로 재생성한다. 삭제한 최초 이용 근거를 전체 기간에 대해 복원할 수 없으면 known=false로 유지한다. 90일 밖 발행 날짜는 partial로 표시해 완전한 장기 복원을 주장하지 않는다. accepted/duplicate/rejected 등 과거 접수 품질 사실은 현재 남은 이벤트 개수로 덮어쓰지 않는다.

## 지원 분석 보관

로그인 사용자가 유효한 분석을 실행할 때마다 headless `admission-history/save` 요청을 보낸다. 결과 계산·sessionStorage·기존 결과 이동은 즉시 유지하며 저장을 기다리지 않는다. 같은 execution UUID 재전송은 중복 저장하지 않는다. 실제 소유자는 JWT로 결정하고 서버가 프론트엔드와 공유한 현재 `lawschool` 기준으로 결과를 계산한다.

지원 분석은 `private.admission_history`에 입력·결과·규칙 버전을 영구 보관한다. Auth FK/cascade를 두지 않아 계정 탈퇴 후에도 UUID 기준으로 남는다. 관리자 수정/삭제는 허용하며 tombstone으로 지연 원본 전송의 덮어쓰기/재생성을 막는다. 기존 브라우저 결과를 소급 이관하지 않는다.

저장 실패에도 일반 사용자 화면에 새 알림·문구·목록을 넣지 않는다. 관측된 실패는 관리자 전용 diagnostics에 실행 ID와 안전한 코드만 기록한다. 오프라인·탭 종료·서비스 전체 장애로 서버에 도달하지 않은 실행은 서버 실패 기록도 보장할 수 없다. 개인정보 로컬 영구 재전송 큐는 만들지 않는다. 분석 보관은 통계 수집 중단·관리자 제외 정책과 독립적이다.
