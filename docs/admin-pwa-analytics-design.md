# 관리자 PWA 이용 통계 설계안

작성일: 2026-10-03 KST. 상태: **최초 출시 중심 로컬 구현 / 운영 미적용**.

검토 반영: 2026-10-03 사용자의 요청에 따라 [설계 검토 결과](admin-analytics-review.md)의 긴 입력 세션 유지·흐름 연결·수신/활동 시각 구분·기간 비교·수집 품질과 관리자 조회 이력을 이 문서와 전체 설계에 반영했다. 설계의 로컬 적용 상태는 아래 구현 상태와 [구현·운영 문서](admin-analytics.md)를 따른다. 운영 DB에는 아직 적용하지 않았다.

재검토 반영: 같은 날 확인한 세션 관찰 종료·새 세션의 답안 재개·회원 지표 기준일·최초 이용일 요약을 전체 설계와 같은 계약으로 반영했다. 시간·보존 값은 설계 제안이며 운영에는 적용하지 않았다.

2026-10-04 통합 재검토 반영: [최신 검토](admin-analytics-review-20261004.md)의 일평균/기간 DISTINCT 구분·정확한 12개월 구간·감소 우선 선정·인증/권한 거절 자료 제거를 [대시보드](admin-dashboard-design.md)와 동일한 계약으로 적용한다. 이번 반영은 설계 문서이며 앱·예시 HTML·운영에는 아직 미적용이다.

[관리자 이용 통계 설계](admin-analytics-design.md)의 실행 채널 확장이다. PWA를 통한 사용자가 얼마나 있고, 어떤 기능을 쓰며, 얼마나 다시 이용하는지 별도로 파악한다. 이번 작업은 문서만 변경하며 기존 설치 버튼·사용자 화면·manifest·서비스 워커·DB를 변경하지 않는다.

추가 확정 요구: PWA 활동도 비식별화하지 않는다. 실제 Supabase `user_id`로 기록을 유지하고 관리자는 이름·이메일과 함께 해당 회원의 PWA·브라우저 활동을 조회한다. 회원별 조회·인가·보존 규칙은 전체 통계 설계와 동일하다.

## 로컬 구현 상태 (2026-10-04)

실행 채널 판별·채널별 세션·회원 교집합·회원 타임라인·설치 신호·PWA 핵심 재방문을 구현했다. 운영 활성화와 실제 기기 설치 검증은 하지 않았다. [구현·운영 문서](admin-analytics.md)에 적용 필터와 후속 범위를 명시한다. 아래 설계 목표 중 DAU/WAU/MAU 별도 카드·장기 집계/작성 확장 등은 후속이며 설치 신호를 전체 설치 인원으로 바꾸지 않는다.

## 1. 핵심 정의: 실제 이용, 설치 관측, 설치 보유를 구분

- **PWA 이용 세션**: 설치형 실행에 해당하는 신호가 관측된 실행 채널에서 이용 이벤트가 발생한 세션.
- **PWA 활성 회원**: 조회 기간에 PWA 채널로 이용한 로그인 회원의 고유 수. 앱과 브라우저에서 같은 계정으로 로그인한 경우 서버가 검증한 실제 `user_id`로 중복 제거한다.
- **설치 이벤트 관측 건수**: 지원 환경에서 `appinstalled` 이벤트를 수신한 건수. 모든 OS의 전체 설치 수나 설치 후 실행 수가 아니다.
- **설치 보유 대수·전체 설치 사용자·삭제 수**: 범용적으로 정확히 확인할 수 없으므로 최초 기능에서 제공하지 않는다. 이벤트가 없다고 미설치로 판정하지 않는다.

설치형 PWA가 있어도 일반 브라우저 탭으로 이용한 행동은 브라우저 이용이다. 한 회원은 두 채널을 모두 사용할 수 있다. 모바일 접속·서비스 워커 등록·앱 설치 버튼 클릭만으로 PWA 이용자로 분류하지 않는다.

## 2. 설계 시점 앱에서 확인한 기반 (2026-10-03)

- `src/public/manifest.json`: `display: standalone`, `start_url: /`. 실행 출처 쿼리나 별도 `id`는 현재 없다.
- `src/components/PWAInstallButton.tsx`: `display-mode: standalone`과 `navigator.standalone === true`로 설치형 실행 시 버튼을 숨긴다. 이 값은 React 컴포넌트 상태일 뿐 서버의 설치 현황 데이터가 아니다.
- 버튼은 iPhone/iPad에서는 안내 모달, Android에서는 보관된 설치 prompt 또는 브라우저 메뉴 안내, PC에서는 즐겨찾기 안내를 제공한다. 따라서 버튼 클릭을 설치 prompt 표시나 설치 성공으로 집계하면 잘못된 수치가 된다.
- 현재 `beforeinstallprompt`와 `userChoice` 처리는 있지만 `appinstalled` 수집·서버 이용 통계 전송은 없다.
- `src/main.tsx`는 일반 브라우저에서도 서비스 워커를 등록하고 `pageshow`·화면 복귀 때 업데이트를 확인한다. 등록·업데이트·컨트롤러 변경은 설치·PWA 실행 증거가 아니다.
- `src/public/sw.js`에는 fetch 캐시 처리와 별도 오프라인 수집 큐가 없다. 오프라인 실행·이벤트 전달이 보장된다고 가정하지 않는다.

## 3. 관리자 화면 제안

기존 통계 설계의 일곱 탭에 공통 **실행 채널** 필터를 추가하고, 상세 비교용 **PWA 분석** 영역을 제안한다. 메뉴·일곱 탭·필터 범위는 사용자 승인 후 로컬 적용했다.

| 영역 | 제공할 내용 | 운영 질문 |
|---|---|---|
| 이용 현황 | PWA 세션, 활성 회원, DAU/WAU/MAU, 신규 관측 PWA 회원, 일별 비중 | 설치형 이용이 얼마나 늘고 있는가? |
| 기능 이용 | PWA의 채점·기출·문항 통계·성적 이력 이용 순위와 횟수 | PWA에서는 무엇을 주로 사용하는가? |
| 채널 비교 | 같은 OS·기기·로그인 조건의 채점 전환·세션당 이용 횟수 | 브라우저와 이용 방식이 다른가? |
| 재방문 | 최초 관측 PWA 핵심 이용일 기준 D1·D7·D30 | 앱으로 다시 학습하는가? |
| 회원별 활동 | 이름·이메일로 확인하는 PWA 이용 회원 목록과 시간순 이용 기록 | 누가 PWA에서 무엇을 사용했는가? |
| 설치 안내 | 안내 노출·클릭·prompt 선택·설치 이벤트 관측 | 어느 설치 안내 단계에서 멈추는가? |
| 데이터 품질 | 판별 불가 비중·OS별 설치 이벤트 지원 범위·수집 시작일 | 숫자를 어느 범위까지 해석할 수 있는가? |

공통 필터는 전체/PWA/브라우저/기타·판별 불가, iOS·iPadOS/Android/Windows/macOS/기타·미상, 모바일/태블릿/PC/미상, 로그인 여부, 기간이다. OS·기기는 거친 분류이고 오분류 가능성을 표시한다. 모바일 여부나 브라우저 이름으로 실행 채널을 결정하지 않는다.

핵심 카드 추천은 **PWA 활성 회원, PWA 이용 세션, PWA 채점 완료 횟수, PWA 회원 D7 재방문율**이다. 설치 이벤트는 보조 지표로 둔다. 모든 PWA 행동 지표는 자체 이벤트 출처이며, Vercel 방문자 수를 분모로 섞지 않는다.

대시보드의 PWA 건수 곡선은 같은 PWA 필터의 일별 고유 회원/세션·채점 수 합을 구간 전체 완료 일수로 나눈 **일평균**이다. 카드의 기간 전체 DISTINCT와 툴팁의 구간 DISTINCT를 별도로 표시한다. 가용 0건 날짜는 평균 분모에 넣고 자료 누락 구간은 null로 선을 끊는다. WAU/MAU와 D7 재방문율을 일평균이라고 재명명하지 않는다. 7일·30일·6개월·1년의 경계/동일 일수 비교·12개 월 구간은 대시보드 3·7장, 주요 변화 선정은 정책 버전 2를 그대로 적용한다.

PWA 이용 회원 목록에는 이름·이메일·UUID, 마지막 PWA 관측 이용 시각, 이용 세션 수, 채점·기출·이력 이용 횟수를 표시한다. 회원을 선택하면 해당 계정의 전체 활동 또는 PWA 활동만 필터한 타임라인을 제공한다. 각 기록에는 관측 활동 시각과 서버 수신 시각·지연 상태, 기능·시험/파일/문항 등의 대상·처리 결과·실행 채널·OS·기기를 표시한다. 브라우저/PWA 병행 집단에서도 식별된 회원 목록으로 이동할 수 있다.

이름을 모를 때의 탐색은 [공통 회원 선택 목록](admin-member-picker-design.md)을 사용한다. 기본 일반 회원 전체를 검색 없이 가입 최신순 50명씩 표시하고 선택 후 개인 활동에 PWA/기간 조건을 적용한다. 선택한 회원의 PWA 관측 0건과 자료 미가용을 구분한다. 전체 PWA 카드·채널 교집합·코호트를 선택 회원의 지표로 바꾸지 않는다. 이번 항목은 설계이며 앱·예시 HTML에는 아직 미구현이다.

PWA 회원 검색·활동 API는 전체 설계의 관리자 조회 이력 기준을 적용한다. 서버가 확인한 관리자 ID·대상 회원/세션·조회 종류·기간·필터·반환 건수를 기록하고, 캐시 API 응답도 포함한다. 이 기록은 관리자 API 접근 사실이며 이용자 PWA 활성·기능·재방문 수에는 포함하지 않는다.

## 4. 실행 채널 판별 계약

PWA 판별은 앱 공통 수집 계층에서 한 번 구현해 모든 이벤트에 붙인다. 설치 버튼의 표시 상태에 의존하지 않고, 관리자 페이지 제외 여부와도 분리한다.

| 관측 신호 | 채널 분류 | 근거·주의 |
|---|---|---|
| `matchMedia('(display-mode: standalone)').matches` | `pwa` | 현재 manifest의 실행 형태와 일치 |
| `navigator.standalone === true` | `pwa` | Apple 홈 화면 실행 보완 신호 |
| `display-mode: window-controls-overlay` | `pwa` | PC 앱 창 실행 신호; 현재 manifest에서는 요청하지 않음 |
| 위 신호 없이 `display-mode: browser` | `browser` | 설치 보유 여부를 뜻하지 않음 |
| `minimal-ui`, `fullscreen`, `picture-in-picture`만 관측 | `other` | 현재 standalone 설정과 다른 표시 형태, 설치로 단정하지 않음 |
| 미지원·접근 실패·어떤 모드도 확인되지 않음 | `unknown` | 브라우저로 강제 분류하지 않음 |

판별 우선순위는 standalone/Apple 신호 → overlay → browser → 기타 → 미상이다. Fullscreen API로 일반 웹을 전체 화면으로 만들 수 있으므로 fullscreen만으로 설치형 앱을 판정하지 않는다. 일시적인 전체 화면 중에는 최초·직전의 신뢰 가능한 실행 채널을 유지하고 표시 모드만 별도로 기록한다. [MDN display-mode](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/display-mode)

`navigator.standalone`은 타입을 좁혀 읽는 보완 신호로 사용한다. UA만으로 설치 여부를 가정하지 않는다. 웹뷰나 홈 화면 바로가기가 browser로 열리면 브라우저 이용으로 남으며, 설치 보유 인원까지 추정하지 않는다. [Apple 웹앱 문서](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/SafariWebContent/ConfiguringWebApplications/ConfiguringWebApplications.html)

`display_mode`, `detection_method` (`media_query` / `apple_standalone` / `retained_context` / `unknown`), `detection_version`을 함께 기록한다. 분류가 바뀌면 버전을 올리고 과거 수치를 현재 규칙으로 조용히 덮어쓰지 않는다. 클라이언트가 보고한 모드는 분석용 관측값이며 보안 인가나 실제 설치 인증에 사용하지 않는다.

`start_url`에 `?source=pwa`를 붙이는 방식은 최초 범위에 포함하지 않는다. 기존 설치에는 새 manifest가 즉시 반영된다고 보장할 수 없고, URL 복사만으로 오분류될 수 있다. 추후 도입한다면 manifest `id`와 앱 정체성·기존 설치 업데이트를 별도 검토하고 실행 판별의 보조 신호로만 사용한다. [web.dev PWA detection](https://web.dev/learn/pwa/detection)

## 5. 세션·중복·재방문 계산

### 세션과 실행 시점

- 같은 저장소·같은 실행 채널에서 30분 비활동 전에는 같은 세션으로 묶는다. 공유 가능한 같은 채널 탭은 동일 세션을 사용하고, 공유할 수 없는 환경은 별도 세션으로 관측한다.
- 비활동은 서버 전송 간격이 아니라 로컬의 마지막 실제 조작을 기준으로 한다. 화면이 보이는 동안 답안 변경·선택·기능 조작에서 `last_interaction_at`을 갱신한다. 조작 없이 열린 탭·포커스·SW 업데이트는 갱신하지 않는다.
- 서버에서 관찰 종료를 판단하도록 전체 설계의 `session_activity` 최소 상태를 실제 조작이 있을 때 최대 분당 한 번, 기능 이벤트와 함께 전달한다. 개별 답안·클릭·키 입력은 보내지 않으며 상태 보고로 이용 횟수·활성 회원·핵심 재방문을 늘리지 않는다. 단순 전송 중단은 정상 비활동과 구분할 수 없으므로 이것만으로 영구 미확정으로 두지 않는다.
- 서버의 관찰 상태는 전체 설계의 `open|grace|observation_closed|uncertain`을 사용한다. 세션의 모든 문서에서 받은 마지막 새 이용/활동 상태 이후 30분은 open, 추가 15분은 grace, 총 45분 뒤 알려진 수집 장애가 없으면 observation_closed다. 중복 재시도는 시각을 연장하지 않으며 알려진 처리 장애·도달한 누락 보고 등만 uncertain 사유로 삼는다. 늦은 활동은 다시 open으로 바꾸고 재집계한다. 관찰 종료는 실제 PWA 종료·전체 이용 수집을 증명하지 않으며 로컬의 30분 세션 경계를 바꾸지 않는다.
- 세션 저장소 접근에 실패하면 새 관측 세션과 연결 실패 상태로 처리한다. 이전 세션을 임의 복원하거나 동일 인물·새 설치로 해석하지 않는다.
- 브라우저와 PWA가 저장소를 공유해도 `session_id` 저장 키를 실행 채널별로 분리한다. 설치 후 browser → standalone 전환이 확인되면 PWA 세션을 새로 시작하고 브라우저 세션을 소급 변경하지 않는다.
- 페이지 새로고침·SW 업데이트 자동 새로고침·짧은 백그라운드 복귀는 30분 규칙 안에서 새 세션으로 세지 않는다. 30분 뒤 복귀하여 실제 이용 이벤트가 발생하면 새 세션이다. 백그라운드 시간 자체는 이용 시간으로 세지 않는다.
- `pwa_session_started`는 해당 채널 세션의 최초 실제 이용 시 한 번 기록한다. 문서 로드·홈 화면 아이콘 클릭·포커스 횟수와 같지 않으므로 **앱 실행 횟수** 대신 **PWA 이용 세션 수**로 표시한다.
- 모드 변경은 `execution_channel_changed`로 기록하되 그 이벤트만으로 핵심 기능 이용을 늘리지 않는다. 설치 상태 확인, 서비스 워커 업데이트, 단순 visibility 변화도 활성 이용에 포함하지 않는다.
- 브라우저 → PWA 이동의 채점 흐름은 서로 다른 세션이다. 최초 범위의 같은 세션 채점 전환에서는 익명 흐름을 임의 연결하지 않고 채널 이동 가능성을 별도 안내한다.

### 채점 흐름·실제 화면 이용·시각

- PWA에서도 입력 `input_flow_id` → 요청별 `grading_run_id` → 계산·과목별 저장·결과의 연결 계약을 적용한다. 시험 변경·전체 초기화는 새 입력 흐름, 재채점은 새 실행이다. 세션이나 계정 경계가 바뀐 뒤 남아 있는 답안을 실제 수정/채점하면 새 흐름의 `grading_input_resumed`를 실행 전에 한 번 기록한다. 단순 복귀는 재개가 아니다. 입력 답안은 유지하고 전환 분모에는 새 세션을 한 번 포함한다.
- `previous_input_flow_id`는 같은 계정 또는 계속 비로그인인 동일 저장소·채널에서만 연결한다. 로그인/로그아웃·다른 계정·분리된 PWA/브라우저 저장소에서는 이전 흐름을 연결하지 않는다. 새 세션의 결과로 이전 세션을 성공 처리하거나 익명 입력을 새 회원에게 소급 귀속하지 않는다.
- 채점 전환의 분모는 조회 기간에 최초 입력 시작/재개가 관측된 관찰 종료 세션이다. 진행 중·지연 유예·관찰 미확정은 별도로 표시하며 결과 미수신을 의도적 포기로 단정하지 않는다. 조회 종료 이후의 같은 세션·흐름 결과는 가용 관찰 범위 안에서 연결한다.
- 공통 이력 API의 백그라운드 성공은 PWA 이력 이용이 아니다. 해당 이력 화면의 실제 정상 표시만 계측한다. 정상 빈 이력 조회와 기록 보유 여부도 구분한다.
- 결과 `entry_source=new_grading|history|example|unknown`을 전달해 과거 결과·예시·결과 없음이 새 PWA 채점 횟수·결과 전환을 늘리지 않게 한다.
- 모든 이벤트는 서버 `received_at`, 클라이언트 `occurred_at`, 문서 `page_instance_id`, 증가하는 `event_sequence`를 가진다. 타임라인의 활동/수신 시각은 구분하고 시계 오차·수신 지연을 표시한다. 다른 탭의 순서 번호를 직접 비교하지 않는다.
- 최초 일별 이용·회원 활동일·코호트는 KST 서버 수신 시각 기준이다. 홈 화면 실행·백그라운드 복귀 시각을 수신 시각으로 복원했다고 표현하지 않는다.

### 회원과 비로그인

회원 채널 비교는 기간 내 이용 집합을 `P`(PWA), `B`(브라우저)로 만든 뒤 다음과 같이 계산한다.

- PWA만 이용: `P − B`, 브라우저만 이용: `B − P`, 둘 다 이용: `P ∩ B`.
- 두 확인 채널의 회원 합계: `|P ∪ B|`. PWA 회원 수와 브라우저 회원 수를 단순 합산하지 않는다.
- 전체 회원 수에는 기타·미상 채널만 이용한 회원도 포함한다. P/B 비교 표의 합계와 전체 지표의 범위를 구분한다.
- ‘PWA만’은 **조회 기간에 브라우저 이용이 관측되지 않음**이라는 뜻이며 평생 PWA만 사용한다는 뜻이 아니다.

PWA 회원 비중은 `|P| / 전체 활성 회원`, PWA 세션 비중은 `PWA 세션 / 전체 이용 세션`으로 제공하고 기타·미상도 전체 분모에 포함한다. 알려진 두 채널끼리의 비율을 추가 제공한다면 별도 이름과 분모를 명시한다.

세션·회원·채점 실행의 선택 기간 총합은 각 ID를 기간 전체에서 DISTINCT 처리한다. 자정을 넘는 세션의 일별 수를 합산하지 않는다. 로그인/비로그인 부분집합은 같은 세션을 포함할 수 있다. 시험별 비율은 시험 정보가 관측된 세션을 분모로 삼고 전체 페이지뷰와 섞지 않는다.

PWA 지표에도 `available_from`, `available_through`, `coverage_status=complete|partial|unavailable`을 제공한다. 현재와 이전 기간의 정의·필터·전체 자료가 같을 때만 비교하고 미보존/수집 전 구간을 0으로 채우지 않는다. 상세 기록·정확한 세션/실행·전환은 원본 보존 구간, 회원 코호트의 재방문 결과는 회원 활동일 보존 구간의 실제 가용 범위를 따른다. 최초 이용일 요약만 남아 있어도 미보존 D+7 활동을 미재방문으로 판정하지 않는다. 보존 기간은 전체 설계의 제안값이며 이번 작업으로 운영 기록을 연장하거나 삭제하지 않는다.

Safari 탭과 iOS/iPadOS 홈 화면 실행 등은 저장소·로그인 상태가 분리될 수 있다. 공통 localStorage를 가정하지 않고 동일 계정의 **검증된 로그인 이후** 이벤트만 실제 `user_id`로 연결한다. 비로그인 PWA와 브라우저에서 같은 사람이 쓰는지는 연결하지 않으며 전체 고유 인물 수를 추정하지 않는다. 비로그인 기록은 식별된 회원 목록과 구분해 세션별로 조회한다. [web.dev 저장소·세션 설명](https://web.dev/learn/pwa/detection)

### 재방문과 전환

- PWA D7 재방문: 최초 관측 PWA 핵심 이용일 D의 로그인 회원 중 D+7에 다시 PWA로 핵심 이용한 회원 비율. D1/D30도 같은 규칙이며 관찰 기간이 끝난 코호트만 분모에 넣는다.
- PWA 최초 핵심 이용은 전체 설계와 같은 핵심 행동 목록을 채널=pwa로 제한한 것이다. 서비스 전체 재방문의 기준일은 최초 핵심 이용일이고 최초 채점일을 대신 사용하지 않는다. 회원 확인 후 7일 내 첫 채점은 계정 확인 완료 후 7×24시간 기준이며 PWA 여부는 별도 필터다.
- 동일 코호트의 서비스 전체 D7 재방문도 함께 표시한다. PWA로 복귀하지 않았지만 브라우저로 다시 이용한 경우를 구분한다.
- 브라우저 → PWA 전환: 최초 관측 브라우저 핵심 이용 후 7일 안에 PWA 핵심 이용한 로그인 회원 비율. 전체 수집이 시작된 뒤 충분히 관찰된 회원만 포함한다. 원래 설치되어 있었는지 알 수 없으므로 **신규 설치율**로 이름 붙이지 않는다.
- ‘신규 PWA 회원’은 설치일이 아니라 수집 이후 최초 PWA 이용이 관측된 회원이다. 활성 판정 대상의 첫 PWA 이용 시각과 재방문용 첫 PWA 핵심 이용 시각을 구분한다. 회원 최초 이용 요약의 조건별 known 회원만 신규/최초 코호트에 넣고 unknown은 별도 건수로 제공한다. 수집 전 이용 이력은 알 수 없음을 표시한다.
- 최초 이용 시각은 전체 설계의 `product_member_first_usage`에 지표 버전별로 유지한다. 원본 90일/활동일 180일 만료 뒤 복귀해도 기존 최초 시각을 재설정하지 않는다. 요약은 회원 계정 유지 기간에 보존하는 제안이며 이름·이메일·기기 지문을 복사하지 않는다. 요약 유실/중간 도입으로 과거 확인이 불가하면 최근 활동만 보고 신규로 추정하지 않는다. 버전 변경도 기존 회원의 신규 전환으로 세지 않는다.
- 채널별 재방문 차이는 인과 효과로 표현하지 않는다. PWA를 선택한 회원은 이미 자주 이용하던 회원일 수 있다. 동일 OS·기기·회원 경력 조건으로 비교하고, 표본 10명 미만에는 수치와 표본이 적다는 안내를 함께 표시한다. 관리자 회원 목록·타임라인은 표본 크기로 숨기지 않는다.

## 6. 설치 안내 이벤트: 환경별로 분리

| 이벤트 후보 | 수집 시점 | 의미 |
|---|---|---|
| `install_cta_viewed` | 기존 설치 버튼이 실제 보이는 페이지에서 최초 관측 | 안내 노출, 설치 가능 여부는 아님 |
| `install_cta_clicked` | 기존 버튼 클릭 | 관심·안내 진입 |
| `install_guide_opened` | iOS 안내 모달·메뉴/즐겨찾기 안내가 표시됨 | `guide_type`으로 분리, 완료 아님 |
| `install_prompt_available` | `beforeinstallprompt` 수신 | 이번 문서에서 prompt 호출 가능 신호 |
| `install_prompt_requested` | 기존 동작에서 `prompt()` 호출 | `install_attempt_id`당 한 번 |
| `install_prompt_result` | `userChoice` 응답 또는 호출 오류 확인 | accepted / dismissed / error |
| `install_event_observed` | `appinstalled` 수신 | 관측된 설치 이벤트, 실제 이용과 별개 |

노출은 관측 가능한 화면 영역의 기존 버튼에 대해 페이지 진입 ID당 한 번 기록한다. 렌더 횟수로 증가시키지 않는다. prompt와 appinstalled의 관측 리스너는 공통 수집 계층에 두되 기존 설치 UI의 `preventDefault`·prompt 호출·버튼 동작을 바꾸지 않는다. 설치 안내 코드가 늦게 마운트되어 이벤트를 놓칠 수 있으므로 후속 구현에서 초기 리스너 등록 시점도 검증한다.

Chromium의 안내 전환은 **클릭 → 실제 prompt 요청 → accepted/dismissed → 설치 이벤트 관측**을 분리한다. 버튼 클릭 중 안내만 열린 PC/iOS는 prompt 분모에 포함하지 않는다. 각 비율은 이벤트가 연결된 동일 시도/세션만 계산하고 브라우저 메뉴의 직접 설치처럼 시도 ID가 없는 설치 이벤트는 별도 건수로 표시한다.

iOS의 안내 조회·클릭은 관측할 수 있지만 일반적인 `appinstalled` 완료 이벤트를 기대하지 않는다. 최초 PWA 이용이 관측되면 실제 이용에 포함하되 특정 안내의 설치 성공으로 소급 귀속하지 않는다. prompt 미수신도 미설치나 설치 불가의 확정 증거는 아니다. [MDN beforeinstallprompt](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeinstallprompt_event), [MDN appinstalled](https://developer.mozilla.org/en-US/docs/Web/API/Window/appinstalled_event)

Android에서 `appinstalled`가 WebAPK 설치 완료보다 먼저 관측될 수 있으므로 장치 설치 완료나 즉시 실행 가능을 보장하는 지표로 표현하지 않는다. 앱 삭제 이벤트나 수집 이전 설치는 복원할 수 없다. [web.dev 설치 관측 설명](https://web.dev/learn/pwa/detection)

설치 관측 후 7일 내 실제 PWA 핵심 이용 전환을 후속 제공한다면 같은 로그인 회원으로 연결 가능한 설치 이벤트만 분모에 넣고, 성숙 코호트·연결 가능률을 함께 표시한다. 익명 설치와 나중 로그인은 강제로 연결하지 않는다.

## 7. 수집·조회·집계 확장

- 새 수집 서버를 추가하는 대신 기존 관리자 통계 설계의 공통 이벤트 계약에 실행 채널 필드를 확장한다. 채점·기출·이력 이벤트에 동일 기준을 적용한다.
- 논리 객체 `product_usage_events`, `product_usage_daily`, `product_member_activity_days`의 후보 구조에 채널을 포함한다. 원본·회원 활동일의 식별자는 실제 `user_id`로 유지한다. 활동일은 같은 회원·같은 날짜라도 PWA와 브라우저 이용 여부를 모두 유지한다. 전체 고유 회원은 채널을 합친 뒤 다시 DISTINCT 계산한다.
- `product_usage_session_state`에는 공통 관찰 상태·마지막 활동 수신 시각을, `product_member_first_usage`에는 최초 서비스 핵심·채점·PWA 이용·PWA 핵심·브라우저 핵심 시각과 조건별 확인 상태를 유지한다. 이 요약을 1차 수집부터 시작하되 원본/활동일 보존과 분리한다. 실제 테이블/보존 적용은 별도 구현 범위다.
- 관리자 조회 API에 `channel`, `os_family`, `device_class` 필터와 `report=pwa`를 제안한다. 캐시 키·집계 버전·적용 필터·판별 커버리지도 함께 갱신한다.
- 관리자 회원 검색·활동 API에도 동일 채널 필터를 적용하고 필요한 이름·이메일·UUID를 반환한다. 이 정보를 일반 이용자 API나 설치 안내 화면에 노출하지 않는다.
- PWA 집계·회원 목록·활동·조회 이력도 공통 `AdminAnalyticsError`와 `authorization_generation`을 적용한다. 같은 계정·필터·인가 세대의 일시 네트워크/시간 초과·재시도 가능한 5xx에만 이전 성공값을 기준 시각과 유지한다. 현재 계정/인가 세대의 어느 관리자 조회에서든 401/403이면 모든 관리자 통계 자료·회원 선택·검색어·커서를 제거하고 요청을 중단하며 이전 세대의 늦은 성공은 차단한다. 새로운 권한 확인 후에는 새로 조회한다. 상세 오류 기준은 대시보드 7·8장을 따른다.
- 회원 검색·활동·관리자 조회 이력 응답에는 전체 설계의 서버 접근 기록을 적용한다. 조회 이력을 보기 위한 관리자 요청도 요청당 한 번 기록하고 자동 추가 조회를 일으키지 않는다.
- Vercel의 일반 페이지뷰에 자체 실행 채널이 자동으로 들어간다고 가정하지 않는다. 최초 화면에서는 Vercel 전체 방문과 자체 채널별 이용을 출처별로 표시한다.
- 회원 식별과 관리자 인가는 기존 서버 검증을 유지한다. OS·기기·표시 모드는 허용된 분류만 받으며 전체 UA 문자열·기기 지문·지속적인 익명 설치 ID는 저장하지 않는다.
- 오프라인 이용은 온라인 전송이 성공하기 전에는 집계되지 않는다. 이번 범위는 서비스 워커 캐시나 영구 오프라인 큐를 추가하지 않는다. 미수집 구간을 사용 없음으로 해석하지 않는다.
- 배치 응답은 전체 설계의 이벤트별 accepted/duplicate/rejected/processing_failed를 적용한다. HTTP 2xx만으로 전체 성공 처리하지 않는다. 세션 상태와 이용 이벤트는 서로 다른 품질 모수로 집계한다.
- PWA 수집 품질은 서버 제출·수락·중복·거절·처리 실패, 판별 불가 비중, 집계 지연 등 관측 가능한 값만 제공한다. 서버 미도달 PWA 이용의 전체 누락률·차단률은 측정 불가이며 Vercel 방문자와의 차이를 차단률로 쓰지 않는다.

## 8. 구현 순서와 인수 기준

**1차:** 공통 실행 판별·로컬 활동/최소 서버 상태·관찰 종료·세션 분리 → 실제 회원 ID·입력/재개/실행/출처/시각을 유지한 행동 수집과 최초 이용일 요약 → 개요의 PWA 카드·공통 필터·기능/채점 비교·회원별 PWA 기록·관리자 조회 이력·가용 범위·수집 품질. 첫 통계 수집부터 포함해야 이후 PWA 재방문을 분석할 수 있다.

**2차:** 기존 설치 안내의 노출·클릭·prompt·설치 관측과 첫 PWA 핵심 이용 연결 가능률. 브라우저별 지원 범위를 표시한다.

**3차:** PWA D1/D7/D30, 브라우저 → PWA 이용 전환, 회원의 채널 병행 분포. 관찰 기간이 쌓인 뒤 제공한다.

검증 사례:

1. SW가 활성화된 일반 브라우저 → browser. standalone iOS/Android/PC → pwa. API 미지원 → unknown. 일반 페이지의 Fullscreen API → PWA로 승격되지 않음.
2. 같은 회원이 두 채널 이용 → 채널별 각 1명, 전체 1명, 병행 1명. 익명 두 채널은 별도 세션이며 동일 인물로 결합하지 않음.
3. 앱 재렌더·새로고침·SW 갱신·짧은 전면 복귀 → 세션과 설치 관측 중복 없음. 30분 뒤 실제 이용 → 새 세션.
4. browser → standalone 모드 변경 → 새 PWA 세션, 이후 행동만 pwa. 설치 후 브라우저에 남은 행동은 browser.
5. iOS 안내 클릭, PC 즐겨찾기 안내 → 설치 성공·prompt 요청 증가 없음. appinstalled만 직접 관측 → 별도 관측 건수.
6. prompt accepted → 설치 관측 없이 성공 대수로 추정하지 않음. 설치 이벤트와 실행 이벤트가 모두 있어도 서로 다른 단위로 표시.
7. OS·채널 필터, 회원 교집합, unknown 분모, KST 재방문 코호트, 미성숙 코호트, 10명 미만 표본 정책 검증.
8. 모의 Playwright 테스트는 판별 분기·수집 요청·집계·UI를 검증한다. 실제 iOS/iPadOS 홈 화면, Android Chrome 설치형, PC 앱 창의 신호는 실기기로 별도 확인한다. 설치/해제는 격리 환경에서만 수행하고 운영 자동화로 실행하지 않는다.
9. 실기기/로컬 검증의 이벤트 수집과 Supabase 저장을 mock하거나 테스트 환경으로 격리한다. 설치 확인을 위한 운영 채점 저장·회원 생성·이벤트 쓰기를 발생시키지 않는다.
10. 이름·이메일로 검색한 회원의 PWA 기록과 브라우저 기록이 정확히 연결되고, 다른 계정으로 로그인/로그아웃한 뒤 대기 이벤트가 새 계정에 붙지 않는다. 관리자 권한 없는 요청에는 회원 식별 정보와 활동 기록을 반환하지 않는다.
11. 40분 동안 실제 답안 입력을 계속하면 같은 입력 세션이고 40분 방치 뒤 조작하면 새 세션이다. 최소 세션 상태는 실제 기능 이용 수를 늘리지 않는다. 마지막 활동 수신의 30분/45분 경계에서 open/grace/observation_closed, 알려진 장애의 uncertain, 늦은 이벤트 재집계를 검증한다. 전송 중단만으로 영구 미확정 상태가 되지 않는다.
12. PWA 홈의 백그라운드 이력 조회·과거 결과·결과 없음은 새 채점/이력 이용을 늘리지 않는다. 초기화·시험 변경·재채점·자정 이후 완료는 입력/실행 연결과 완료 관찰 기준대로 집계한다.
13. 배치 수신 역전·시계 오차·자정 전 행동의 다음 날 수신은 타임라인과 수신 기준 집계를 구분한다. 기간 비교 미보존·부분 자료·자정 통과 DISTINCT·시험 분모를 검증한다.
14. 관리자 PWA 기록 API의 캐시 응답에도 실제 관리자·대상·반환 건수의 조회 이력이 남고, 이름/이메일 검색어는 복사하지 않는다. 이 기록은 PWA 이용·재방문을 늘리지 않는다.
15. 배치 일부 실패·중복·인증 거절은 항목/요청 단위로 구분한다. 미도달 PWA 누락률을 확정값으로 표시하지 않는다.
16. PWA에서 답안을 남기고 40분 뒤 바로 채점하면 새 세션의 답안 재개 1회·채점 1회다. 이전 세션의 결과는 바뀌지 않는다. 단순 복귀·계정 변경·저장소 분리에서 재개 이벤트/이전 흐름 연결 조건을 검증한다.
17. 기출을 먼저 이용하고 나중에 채점한 회원은 최초 핵심 이용일과 최초 채점일이 다르다. PWA 첫 일반 이용과 첫 핵심 이용, 계정 확인 후 7×24시간 첫 채점의 기준을 혼용하지 않는다.
18. 원본/활동일이 만료된 기존 회원의 PWA 복귀는 신규가 아니다. 요약 유실·과거 확인 불가·버전 변경은 최초 여부 계약대로 처리하고 D+7 활동 미보존은 미재방문으로 표시하지 않는다.
19. PWA의 일정한 일별 이용은 마지막 짧은 구간/월 길이 차이 때문에 급감하지 않는다. 같은 회원의 일평균과 기간 DISTINCT를 구분하고 가용 0건/미가용 날짜를 다르게 처리한다. PWA 증가가 채점 관측률 감소의 우선 자리를 차지하지 않는다.
20. PWA 회원 조회 뒤 다음 페이지나 다른 관리자 블록이 401/403이면 기존 행·선택·커서가 제거되고 늦은 응답이 복원하지 않는다. 503의 이전값 유지에는 계정·필터·인가 세대와 기준 시각이 모두 일치해야 한다.
21. 이름을 모르는 회원도 검색 없이 선택할 수 있고 PWA 활동이 없다고 기본 계정 목록에서 빠지지 않는다. 선택/해제·페이지·모바일/키보드·권한 거절 처리는 공통 회원 선택 기준을 적용한다.

설계 당시 PWA 코드·manifest·서비스 워커와 공식 문서를 대조했다. 후속 로컬 구현은 판별/세션 단위 테스트와 모의 관리자 E2E를 수행하며 아키텍처·DB·도메인·개발 문서를 함께 갱신했다. 실제 기기 설치 검증과 운영 이벤트 수집은 실행하지 않았다.
