## 화면·계산

- `AdminDashboard`: 실제 API와 예시 서비스를 주입할 수 있는 동일 컴포넌트. 6개 카드/작은 곡선, 주요 변화 최대 3개, 기능 행동 비교, 채점 관측률, PWA 중복/세션 비중, 오늘 잠정 현황, 최근 20개 회원 행동과 개별 선택 진입을 제공한다.
- 7일/30일은 일별, 6개월은 7일 구간, 1년은 원래 시작일 기준 월 이동 11개와 실제 종료 경계의 정확히 12구간이다. 종료 경계는 오늘 KST 00시이고 분석에는 어제까지 포함한다. 비교는 같은 일수 및 대응 경계의 직전 기간이다.
- 카드의 회원/세션/실행 수는 기간 DISTINCT, 곡선은 각 완료된 날짜의 DISTINCT 합/구간 전체 달력 일수다. 가용한 0건 날짜도 분모에 포함한다. 부분/미가용 구간은 평균·정확한 구간 총수·일별 합을 null로 반환하고 관측분은 별도 `observed_totals`에 둔다. 신규 확인 회원은 별도 Auth 날짜 출처이고 채널 필터에서는 미지원이다.
- 단조 곡선·현재 실선/이전 점선·누락 구간 단절·실제 시간 간격 X축·0 이상 Y축·정확한 값 표를 사용한다. 추가 이동 평균은 없다.
- 정책 버전 2: 표본 각 50 이상·정확히 3%p 이상인 채점 관측률 감소, 건수 감소, 관측률 증가, 건수 증가 순서다. 건수는 최대값 20 이상·절대 차이 10 이상·이전 양수일 때 20% 이상이다. 후보는 정수 교차곱으로 판정·정렬하고 범주당 1개/총 3개를 고른다.
- 기능 행동은 허용된 완료/열기 이벤트이고 사설 저장은 성공만 포함한다. 실패/미확인 사설 저장은 사실 자료에서 별도 이벤트 종류로 분리하고 최근 피드에는 원래 응답과 결과를 유지한다. 기능 기본 정렬은 행동 세션의 절대 변화다. 커뮤니티/채팅은 화면 진입 정보만 제공한다.
- 전환은 현재 원본 90일 안에서만 지원한다. 6개월/1년은 장기 전환 미지원이다. 최근 피드도 분석 기간과 최근 원본 가용 범위의 교집합만 조회하며 별도 기준 시각·실제 범위를 표시한다.

## API·인가

- `GET /admin-analytics/dashboard?range=7d|30d|6m|1y&channel=...&compare=previous|none`. 명시적 완료 날짜 범위도 최대 366일로 검증하며 range와 날짜를 동시에 받지 않는다. SQL 한 호출의 안정된 읽기 스냅샷으로 현재·이전·오늘 자료를 읽고 서버에서 응답 DTO를 만든다. 내부 사실의 실제 ID는 집계 응답에 반환하지 않는다.
- `GET /admin-analytics/activity-feed?start=...&end=...&channel=...`: 허용된 실제 회원 행동 최대 20개. 현재 이름/이메일과 실제 UUID를 반환한다. 같은 트랜잭션에서 반환 대상 UUID 배열(중복 제거/최대 20개)·반환 수·기간·채널을 감사 기록에 남긴다. 기존 조회 이력의 대상 필터는 이 배열도 검색한다.
- `GET /admin-analytics/member-options?purpose=member_activity|audit_target|audit_actor&query=...&cursor=...`: 분석 날짜/이용 필터와 독립적인 최대 50명 목록. 일반 회원은 가입 최신순+UUID 내림차순, 감사 대상/관리자는 UUID 오름차순이다. 감사 목적에는 현재 계정이 없는 과거 UUID도 포함한다. 조회 시각 이후 새 가입은 중간 페이지에 넣지 않고 이름/탈퇴/역할은 현재 정보로 반영한다.
- 커서는 실제 관리자·목적·trim 검색 조건·정렬 버전에 HMAC-SHA256으로 묶는다. DB 위치와 조회 시각은 서명된 본문에 있고 검색어는 커서 본문·감사 기록에 복사하지 않는다. 비밀값은 함수 런타임의 기존 service role 키만 사용하고 브라우저로 보내지 않는다.
- 실제 JWT/현재 역할 RPC/SQL 역할 재검사를 모두 유지한다. 새 private 객체는 RLS·클라이언트 권한 없음, RPC는 service role 전용 SECURITY INVOKER다. 개인정보 목록/피드 감사 쓰기에 실패하면 성공 응답을 제공하지 않는다.
- `AdminAnalyticsError`는 code/status/retryable을 분리한다. HTML 401/403도 HTTP 상태를 유지한다. 같은 화면의 현재 인가 세대에서 한 요청이라도 거절되면 모든 요청을 취소하고 개인 자료/선택/검색/커서를 제거하며 이후 조회도 중단한다. 같은 계정의 늦은 성공과 폐기된 세대의 거절을 검증했다. AuthContext가 인증/역할 원본이다.

## 장기 자료

추가 마이그레이션 `20261004050638_admin_dashboard_and_member_options.sql`:

| private 객체 | 내용 |
|---|---|
| product_usage_fact_days | KST 날짜·실제 행위자/회원/세션·채널·기능·행동·채점 실행·가산 행동 수. 이름/이메일/답안/점수는 복제하지 않음 |
| product_usage_day_publications | 완료/부분 날짜 발행·지표 버전·세대·발행 시각. 완료 0건과 발행 없음 구분 |

`product_analytics_publish_days`는 현재 관리자 검증 후 원본 가용 90일 안의 완료 날짜만 수동으로 원자 재발행한다. 날짜 advisory lock과 단일 트랜잭션의 사실 교체/발행 갱신을 사용한다. 파생 사실 교체에만 service role DELETE 권한이 필요하며 원본 삭제·자동 삭제·Cron·수집 활성화는 추가하지 않았다. 실패하면 기존 발행을 유지한다. 원본이 만료된 뒤 재집계를 시도하면 거절한다.

조회는 원본이 온전히 가용한 날짜에는 원본, 그 밖에는 최근 25개월 범위의 실제 발행 날짜만 사용한다. 같은 날짜의 원본과 발행을 이중 합산하지 않는다. 발행하지 않은 과거 날짜는 미가용이며 가입일을 이용 시작으로 추정하거나 과거 기록을 생성하지 않는다. **25개월은 조회 논리 범위이고 물리 삭제/보존 자동화가 아니다.** 운영 전 수동 발행 운용 또는 별도 승인된 스케줄러, 부하, 탈퇴/보존 규칙을 확정해야 한다.

## 승인된 실제 UI 연결

`/admin/analytics` 개요를 새 대시보드로 연결했다. 개요는 자체 기간/채널/직전 비교 필터를 사용하고 상세 탭은 기존 최대 90일 필터를 유지한다. 대시보드의 기간·채널·비교 선택은 상세 탭에 이동했다 돌아와도 같은 관리자 화면 메모리에서 유지되며 계정/인가 경계에서는 폐기한다. 새 카드·주요 변화·채점 상세·최근 회원 행동·드롭다운은 해당 상세로 이동한다. 장기 분석에서 이동하면 최근 90일과의 실제 교집합 및 원래 분석 기간을 함께 안내하고 회원 UUID는 URL에 넣지 않는다.

회원 활동에 공통 선택기를 추가하고 기존 기간별 상세 회원 표·검색·비로그인 세션 UUID 조회는 유지했다. 검색어와 목록 페이지 이동은 선택 대상을 바꾸지 않는다. 선택 해제는 이전 개인 활동을 제거하며 전체 회원 활동 요청을 보내지 않는다. PWA 탭의 개인 선택은 PWA 채널과 기존 기능·연도 등 이용 필터를 유지한 회원 활동으로 이동하고 전체 집계·코호트에는 개인 필터를 추가하지 않는다. 조회 이력의 대상/관리자 선택은 기존 UUID 입력과 연동하며 실제 조회는 제출 후 실행한다. 과거 관리자와 삭제된 계정 UUID도 옵션에 제공한다.

권한 거절 시 `AnalyticsContent` 전체를 언마운트하여 상위에 남는 회원 이동 상태까지 제거한다. 새 화면은 AuthContext/공유 인가 세대의 동일한 API를 사용한다. 별도 기능 플래그나 두 번째 인증 상태, 운영 활성화를 추가하지 않았다. 개인 자료는 실제 서버 응답만 사용하고 운영 미연결 시 예시 데이터를 대체 출력하지 않는다.
