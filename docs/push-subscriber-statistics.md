# 푸시 관리자 구독 통계

`/admin/push` 상단의 **푸시 구독 현황**은 새 발송·초안·이력 탭에 공통으로 표시한다. 사용자 요청으로 통계 패널·조회 시각·새로고침을 추가했다. 기존 PWA 이름, 동의 팝업, 작성 내용과 발송 절차는 변경하지 않는다.

## 집계 기준

| 항목 | 기준 |
|---|---|
| 알림 구독 회원 | 등록이 완료된 active 구독에 연결된 유효 회원 ID의 DISTINCT 수 |
| 전체 구독 기기 | 유효 active 구독 수. 회원 연결 기기와 비회원 기기의 합 |
| 회원 연결 기기 | 유효 회원 ID가 연결된 active 구독 수 |
| 비회원 기기 | 회원 연결이 없는 active 구독 수. 비회원 사람 수는 추정하지 않음 |

같은 회원의 여러 구독은 회원 수에서 중복을 제거한다. 동일 물리 기기라도 브라우저·설치 PWA의 구독이 다르면 별도로 센다. 브라우저와 앱이 같은 구독을 공유하면 한 개다. 로그아웃으로 연결이 해제되면 회원 연결 기기에서 비회원 기기로 이동할 수 있다. 따라서 누적 동의 회원 수나 실제 하드웨어 수가 아니다.

등록 대기 요청, disabled 구독, 탈퇴·삭제·현재 차단된 회원의 구독은 제외한다. 로그인 세션 만료 자체는 전체 구독자 발송의 기기 구독 철회가 아니므로 이 집계에서도 제외 사유가 아니다. 전체 회원·선택 회원 발송은 별도로 기존 유효 로그인 세션 규칙을 적용한다. OS 권한 철회·provider 만료는 동기화/발송 응답이 서버에 반영된 뒤 통계에서 제외되며 통계 숫자가 실제 OS 수신을 보장하지 않는다.

## 조회·권한

`admin-push`의 `POST /statistics`는 기존 JWT 검증·관리자 검증 후 읽기 전용 RPC `public.push_subscriber_statistics(p_actor uuid, p_session uuid)`를 호출한다. 클라이언트가 제출한 사용자·세션 ID는 사용하지 않는다. RPC도 관리자 역할·현재 Auth 세션을 재검증하며 SECURITY INVOKER·빈 search_path·service_role 전용 EXECUTE로 제공한다. 기존 private 구독 테이블과 RLS/권한은 변경하지 않는다.

단일 SELECT에서 active 구독과 Auth users를 집계하며 기존 active 부분 인덱스와 회원 기본키를 사용한다. 새 테이블·추적 이벤트·자동 삭제·예약 작업은 없다. 응답에는 집계 숫자 네 개와 조회 시각만 넣고 이름·이메일·회원 ID·endpoint·암호화 키는 반환하지 않는다. 읽기 전용 트랜잭션에서도 동작하며 조회 자체는 감사·receipt·quota 데이터를 쓰지 않는다.

화면 진입 시 조회하고 수동 새로고침으로 갱신한다. 조회 중 숫자는 `—`, 실패는 한국어 오류와 재시도 버튼으로 표시하며 실패를 0으로 대체하지 않는다. 응답 숫자·합계·시각을 검증한다. 통계 요청은 작성·초안·발송 busy 상태와 분리되어 입력값을 유지한다. 미활성 로컬/preview에서는 조회하지 않는다. 401/403이면 기존 관리자 권한 상실 화면으로 전환하고 개인 작성 상태·통계를 제거한다. 계정 변경/언마운트 때 요청을 취소하고 늦은 응답은 사용하지 않는다. 조회 시각은 한국 시간으로 표시한다.

## 검증 및 적용 순서

- `npm run test:push`: 합성 PostgreSQL에서 실제 마이그레이션의 중복 회원·여러 기기·비회원·해지·탈퇴·차단/없는 계정·유효하지 않은 세션·권한 회수·일반 역할 EXECUTE 거절·읽기 전용 실행을 검증한다. Edge 모의 요청에서 익명/일반 관리자 거절, 검증한 신원만 RPC로 전달, no-store 및 worker 기동 없음도 확인한다.
- `npm run test:e2e:push`: 모바일/PC의 숫자·가로 넘침·조회 실패/0/잘못된 응답 구분·새로고침 후 입력 유지·탭 공통 표시·권한 회수를 모의 Supabase로 검사한다. 운영 쓰기는 실행하지 않는다.
- `npm run check`: 표준 전체 품질 게이트를 실행한다.

운영 스키마·RLS·grants·마이그레이션 이력은 2026-10-07 읽기 전용으로 확인했다. 실제 적용은 **신규 마이그레이션 → admin-push 함수 → 웹 배포** 순서다. 사용자의 배포 요청으로 v1.10.0 릴리스를 진행하며 기존 구독·키·기능 스위치 및 일반 캠페인 활성 여부는 유지한다.

2026-10-08 개발 단계 검증: 전체 `npm run check` 통과. lint 오류 0개·기존 경고 69개, typecheck, Vitest 268개, 기존 이력 Edge 100개·사용자 데이터 Edge 21개·통계 Edge 10개·푸시 Edge 12개 및 각 SQL 검증, 푸시 E2E 13개·기존 E2E 84개, 실제 공개 통계를 읽는 빌드·공개 HTML E2E 10개가 통과했다. 모바일/PC 화면을 시각 확인했다. 당시 운영에는 집계와 동일한 SELECT만 읽기 전용으로 실행해 정상 결과를 확인했고 신규 RPC·Edge·웹은 적용하지 않았다. 접근 거절 사례의 테스트 트랜잭션은 savepoint로 격리하여 정상 조회까지 검증한다. React 검토에서 원시 값/안정된 콜백 의존성·요청 취소·계정별 재마운트·응답 검증·통계 상태의 메모리 보관·접근성 제목/상태/오류를 확인했다.

## v1.10.0 운영 적용

2026-10-08 배포 요청에 따라 적용 전 스키마·RLS·grants·마이그레이션 이력·신규 함수 부재·기존 스위치를 재확인했다. `20261007144854_web_push_subscriber_statistics.sql`과 해당 버전 이력을 같은 트랜잭션으로 적용하고 PostgREST 스키마 캐시를 갱신했다. 원문 SHA256은 `2be8e54a9e0d92869d3ae181e0b4d94f1a073b46d730dd9507411877cb62217f`이며 운영 이력에 저장한 SQL 원문과 로컬 파일의 일치를 확인했다. 기존 이력 일괄 db push/repair는 수행하지 않았다.

실제 service_role에서 현재 관리자·유효 세션으로 집계 조회와 합계/응답 계약을 검증했다. 무효 세션은 거절되며 anon/authenticated의 직접 EXECUTE 권한 없음과 STABLE/SECURITY INVOKER를 확인했다. 검증 트랜잭션은 전체 롤백했고 구독 데이터는 변경하지 않았다. 기존 등록/test enabled=true, 일반 campaigns_enabled=false를 유지했다.

DB 적용 뒤 admin-push 함수를 먼저 배포했다. 운영 HTTP에서 익명·무효 JWT는 401, 잘못된 Origin은 403 및 no-store를 확인하고 공개 푸시 설정 조회 200/enabled=true를 확인했다. 웹은 버전 일치·최종 품질 게이트 이후 관련 변경만 main에 커밋·push해 배포한다. 최종 배포 커밋·Vercel READY·GitHub Edge CI 결과와 실제 웹 응답은 최종 작업 보고에 기록한다. 관리자 인증이 없는 브라우저에서는 로그인 경계까지만 확인하고, 운영 초안·발송·등록 쓰기를 테스트하지 않는다.

릴리스 품질 검사에서 기존 디데이 E2E의 첫 서비스워커 활성화 새로고침과 `/login`→`/signup` 이동 경합이 재현됐다. 일정 표시 검증용 비로그인 컨텍스트만 serviceWorkers=block으로 격리했고 5회 반복 통과했다. 제품의 서비스워커·푸시 코드는 변경하지 않았다.

v1.10.0 최종 품질 게이트: `npm run version:verify`와 `npm run check` 전체 통과. lint 오류 0개·기존 경고 69개, Vitest 268개, Edge·SQL 검사, 푸시 E2E 13개·기존 E2E 84개·공개 HTML E2E 10개 및 실제 공개 통계를 읽는 빌드가 통과했다.
