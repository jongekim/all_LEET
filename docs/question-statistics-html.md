# 기출문제 정답률 HTML 생성·갱신

## 범위

기출문제 URL의 초기 HTML에 기존 정답표와 문항별 정답률을 포함한다. 데이터 원본은 DB의 공개 발행 통계이며 코드에 수치를 하드코딩하지 않는다. UI/UX는 유지한다: 기본 접힘, 보기/접기, 시험 변경 후 다시 접힘, 정답률 클릭 시 선지별 응답 분포 모달, 0건/30건 이하/짝수형 안내와 정답 버전 검사를 그대로 사용한다. 집계 날짜·실제 채점 기록 수·선지별 건수는 표시하지 않는다.

원본 개인 답안·회원 ID·성적 이력·공지·인증 데이터는 조회하거나 HTML에 넣지 않는다. DB/정책/Edge Function 변경은 없다. 2026-10-05 읽기 전용 확인에서는 기존 공개 발행본 ID `1`, 76조합(09예비~2026학년도)을 확인했다. 2027학년도에 공개 발행본이 없으면 기존 미준비 안내만 제공하고 수치를 만들지 않는다.

## 생성 구조

1. `npm run build`의 Vite 빌드 뒤 `scripts/prerenderStatistics.ts`가 기존 anon 키로 `question_statistics_snapshots` 전체를 한 SELECT 요청으로 읽는다. RLS가 현재 발행본만 허용한다. 관리 토큰·service role은 필요하지 않다.
2. 전체 응답 건수, 문항별 합계, 시험 조합 중복, 동일 발행 ID·원본 시각·발행 시각을 검증한다. 네트워크 요청은 15초 제한이고 redirect와 캐시 사용을 금지한다. 실패하면 빌드가 실패하며 이전 통계 파일로 대체하지 않는다.
3. 빌드 전용 Context가 통계를 기존 Hook에 제공한다. React 렌더링 자체는 외부 네트워크·인증·쓰기를 금지한 상태에서 실행한다. 기존 표의 문항별 퍼센트와 안내를 출력하며 전체 통계 JSON·집계 건수·시각은 직렬화하지 않는다.
4. `PastExamReview`는 같은 정답표를 forceMount하고 닫힌 상태에 `hidden`을 적용한다. 사용자가 펼쳐 보는 실제 표를 HTML에 보관하며 화면 디자인·초기 접힘을 유지한다. 검색엔진만을 위한 별도 숨김 본문은 추가하지 않는다.
5. 브라우저가 시작하면 기존 방식으로 앱을 마운트하고 사전 HTML을 제거한다. 빌드 통계를 브라우저의 초기 캐시에 넣지 않는다. 통계는 기존 DB 공개 조회·5분 공유 캐시·포커스 재조회·오류 재시도를 사용한다. 접힌 표가 페이지와 함께 마운트되므로 조회는 표를 열기 전부터 시작하며 사용자에게는 기존 펼침 동작으로 노출된다.

## 데이터 갱신과 재배포

**DB 공개 발행본 갱신 → Vercel 최신 Production 배포 Redeploy → HTML 응답 확인** 순서다. 이 기능이 포함된 코드를 처음 배포한 이후, 기존 지원 범위의 통계 값 갱신만을 위해 코드 수정·새 커밋·push를 할 필요는 없다.

1. [통계 수동 갱신](question-statistics.md)의 prepare·검토·publish·status 절차를 수행한다. 공개 스냅샷 행을 직접 수정하거나 단순 채점 이력 추가만으로 공개 통계가 자동 재집계된다고 가정하지 않는다.
2. DB 발행 후 브라우저 통계는 새 조회/캐시 만료로 바뀌지만, 이미 배포된 HTML은 빌드 때 읽은 값으로 유지된다.
3. Vercel 프로젝트의 `Deployments`에서 **이 기능이 포함된 최신 Production 배포**를 선택하고 `Redeploy`한다. Build Cache 사용을 해제한다. 기존 산출물을 재사용하는 Promote/Rollback은 HTML을 다시 생성하지 않는다.
4. Build Command는 `npm run build`여야 한다. 빌드 로그의 공개 문항 통계 조합 수·발행 ID와 새 배포의 Ready 상태를 확인한다. 조회 실패로 빌드가 실패하면 기존 배포를 유지하고 원인을 해결한 뒤 재시도한다.
5. 대표 기출 URL의 HTTP 200, 원본 HTML의 문항별 정답률·canonical·제목, 기본 접힘·펼치기·모달·모바일 화면을 확인한다. HTML만 갱신되고 Google 검색 결과는 즉시 바뀌지 않을 수 있다. Search Console의 실제 URL 테스트 후 재크롤링 결과와 최근 크롤링 날짜를 별도로 확인한다.

새 학년도·정답·문항 수·집계 규칙을 추가하는 일은 단순 값 갱신과 다르다. 현재 코드/DB의 지원 범위를 먼저 확인하고 관련 개발·검증·문서화·배포를 수행해야 한다. 특히 2027 통계 생성/발행 확대는 이번 HTML 작업에 포함하지 않는다. 배포와 push는 사용자의 명시적 요청 후에만 실행한다.

## 검증

- 단위 테스트는 GET/anon 권한, 오류·네트워크 실패, 부분 응답, 중복·혼합 발행본, 문항 합계, 정답 버전 불일치, 미발행 시험, 실제 SSR 정답률·기본 접힘·개인정보/원본 통계 비포함을 검사한다.
- `npm run build:test`는 고정 공개 집계 파일로 운영 네트워크 없이 HTML을 생성한다. CI는 이 빌드와 `npm run test:prerender`를 사용한다. Vercel 환경에서는 fixture 옵션을 거절한다. 테스트 빌드를 실서비스에 배포하지 않는다.
- Playwright는 JavaScript가 없는 최초 HTML의 정답률/기본 접힘과 앱 시작 후 최신 DB 모의 응답·모달·포커스 복귀·다시 접기를 검사한다. 브라우저 Supabase 요청은 모의 응답으로 격리하고 운영 쓰기는 없다.
- `npm run check`는 표준 품질 게이트를 수행하며 build 단계에만 기존 공개 통계를 읽는 GET이 필요하다. 실패 시 확인하고 재실행한다. 실제 배포 전에 production build의 공개 통계 조회와 HTML 검증을 확인한다.

Vercel 재배포와 캐시 설정은 [공식 배포 관리 문서](https://vercel.com/docs/deployments/managing-deployments)를 따른다. 초기 HTML 포함은 Google의 색인·순위·검색 결과 노출을 보장하지 않는다.

## 2026-10-05 로컬 검증 결과

- lint 오류 0건(기존 경고 70건), typecheck와 단위 테스트 21파일/220개 통과. 신규 공개 통계·SSR 검사 12개가 포함된다. 기존 Edge/통계/디데이 격리 검사도 통과했다.
- 실제 anon 공개 통계를 읽는 production build 성공: 공개 HTML 83개, 기출 HTML 78개 중 76개에 문항별 정답률 포함. 미발행 2027 두 URL에는 임의 정답률 없음.
- 실제 production build와 고정 파일을 사용한 CI build 각각에서 HTML Playwright 10개 통과. 초기 HTML의 정답률, 최신 DB 모의 응답으로 교체, 기본 접힘·모달·포커스 복귀, 375px/1280px의 기존 앱 시작 방식과 스크린샷 일치를 확인했다.
- 최초 `npm run check`는 기존 화면 E2E 72개 중 관리자 뒤로가기 취소 검사 1개가 실패했다(71개 통과). 미저장 문구가 초기값으로 돌아오는 같은 실패를 변경 전 HEAD 코드에서도 재현했다. 이후 사용자의 수정 요청으로 아래 이동 취소 오류를 해결하고 전체 게이트를 다시 통과했다.
- 운영 DB/정책/Edge Function 변경, commit, push, Vercel 배포는 실행하지 않았다. 빌드 산출물은 현재 공개 발행본으로 다시 생성했다.
