# 관리자 이용 통계 구현·운영

현재 운영 적용 상태는 [v1.5.0 운영 기록](admin-analytics-rollout.md)을 따른다. 아래 초기 구현·미적용 설명은 개발 당시 기록이며, 신규 DB와 두 통계 함수는 2026-10-04 사용자 배포 요청에 따라 적용했다.
구현일: 2026-10-03~04 KST. **운영 DB·함수 적용 완료. 수집 개시·웹 배포 검증은 [운영 기록](admin-analytics-rollout.md)을 따른다.** [전체 설계](admin-analytics-design.md)와 [PWA 설계](admin-pwa-analytics-design.md)의 1A/1B를 중심으로 구현했다. 사용자가 별도 미리보기를 확인하고 관리자 메뉴 카드, `/admin/analytics`의 7개 탭·필터 적용을 명시적으로 승인했다.

## 화면과 제공 자료

- `/admin` → 이용 통계 → `/admin/analytics`: 개요, 기능, 채점, 회원/재방문, 회원 활동, PWA, 관리자 조회 이력.
- 자체 활성 회원·세션·채점 완료·새 결과 조회 세션, 일별 이용, 기능별 회원/세션/행동, 관찰 종료 세션의 입력→결과 전환, 과목별 완료·저장 응답, 수집 품질을 제공한다.
- 계정 검색은 이름·이메일·실제 UUID, 목록은 가입·확인·기간 내 마지막 이용·세션·채점·기출·이력 행동·채널을 제공한다. 회원 활동은 수신 시각 역순 커서로 조회하고 비로그인은 입력한 세션 UUID의 익명 행만 조회한다. 회원 목록은 UUID 순 커서이며 일반 필터가 전체이면 활동 없는 계정도 보인다.
- 회원 ID는 비식별화하지 않는다. 이름·이메일은 조회 시 현재 Auth 계정에서 읽으며 이벤트마다 복제하지 않는다. 수정 가능한 표시 이름은 React 텍스트로 출력한다. 검색어·대상 ID를 화면 URL이나 영구 클라이언트 캐시에 저장하지 않는다.
- 채점 계산 완료·로그인 상태의 과목별 저장 응답·결과 화면은 별도 이벤트다. 응답 미확인을 확정 실패로 바꾸지 않는다. 답안·점수·GPA·메모·게시글/채팅 본문·원본 UA·전체 외부 URL을 추가 수집하지 않는다.
- PWA 탭의 카드·일별·기능 이용은 PWA 실행만 집계한다. 채널 교집합 표는 공통 필터에 맞는 회원 중 PWA만/브라우저만/둘 다/기타만을 구분한다. 같은 회원을 전체에서 중복 합산하지 않는다. 설치 버튼·안내·프롬프트·appinstalled는 별도 신호이며 설치 보유 인원으로 표시하지 않는다.
- 정상 이력 화면과 화면에 실제 들어온 추이, 기출 PDF 클릭·접힌 참고표 열기·문항 분포 열기, 사설 저장 성공·지원 분석 완료/결과를 계측한다. 홈의 백그라운드 이력 로딩은 이력 이용이 아니다. 커뮤니티/채팅은 현재 화면 진입만 계측하며 읽기/작성 완료로 표시하지 않는다.
- 현재 계정 수·확인 완료 계정 및 현재 KV의 유효 과목 기록/시각 그룹·사설 기록/무효 항목은 서버에서 합계만 반환한다. 관리자/테스트 계정과 계정이 없는 KV 키는 제외한다. 기존 공식 그룹은 `groupTimestamp ?? timestamp`의 정확한 값 기준이며 오래된 1초 이내 묶음을 재구성하지 않는다. 누적 이용량과 구분한다.

## 지표 경계와 현재 제한

대시보드 집계·장기 사실 자료/발행, 공통 회원 목록 API, typed 오류·공유 인가 세대, 재사용 화면 컴포넌트와 분리된 예시 미리보기를 로컬 구현했다. [확장 구현·검증](admin-dashboard-implementation.md)에 정확한 API·계산·권한·장기 자료 경계를 설명한다. **사용자가 미리보기 범위의 UI 변경을 명시적으로 승인하여 새 대시보드/드롭다운을 실제 앱에 연결했다.** 기존 7개 탭에 401/403 전체 자료 제거·늦은 응답 차단을 적용했다.

7일·30일·6개월·1년 집계 API는 완료된 달력 기간을 지원한다. 상세 원본은 기존 최대 90일이며 장기는 실제 발행된 사실만 최근 25개월 논리 범위에서 조회한다. 발행 없는 과거 날짜는 미가용으로 표시하고 자동 수집 활성화·발행 예약·원본 삭제는 실행하지 않았다. 신규 확인은 Auth 날짜 출처로 이용 수집과 독립적이다.

공통 `AdminMemberPicker`는 가입 최신순 일반 회원 및 과거 감사 대상/관리자의 UUID 탐색을 구현했다. 선택은 개인 상세/감사 대상만 바꾸며 전체 카드·곡선·코호트의 모수를 바꾸지 않는다. 기존 회원 표와 UUID 직접 입력은 계속 사용할 수 있다.

기간은 KST `[시작일 00:00, 종료일 다음 날 00:00)`이며 자체 이용은 서버 수신 시각 기준이다. 기본 최근 완료된 7일, 최대 90일이다. 일별 회원·세션 합계가 기간 DISTINCT와 같다고 가정하지 않는다. 현재일·수집 시작일·90일 경계·기록된 수집 중단 구간은 부분 자료로 표시하고 이전 동일 길이 기간 비교에서 제외한다. `complete`는 조회 가능한 기간이며 모든 실제 이용 수집이나 무중단 운영을 보장하지 않는다.

- 로그인·채널·OS·기기·시험·기능·처리 결과 필터는 실제 해당 속성을 가진 이벤트에만 적용한다. 예를 들어 시험 필터에서는 시험 정보 없는 페이지뷰가 포함되지 않는다. 과목 `both`는 실제 두 과목 조합이고 언어이해 필터에 두 과목 실행을 자동 합산하지 않는다.
- 입력 시점에는 최종 과목 조합·저장 결과가 확정되지 않으므로 과목/처리 결과 필터에서 입력→결과 전환은 미지원으로 표시한다. 다른 필터는 동일 조건의 최초 입력 시작/재개 세션을 분모로 사용한다. 다른 기능 필터에서는 입력 이벤트가 없을 수 있다.
- 서버 관찰은 모든 문서의 마지막 새 유효 활동 수신 후 30분 `open`, 추가 15분 `grace`, 이후 `observation_closed`다. 알려진 항목 처리 실패는 `uncertain`, 해당 이벤트 ID의 재시도 성공으로 복구한다. 중복 재시도는 활동 시각을 연장하지 않는다. 결과는 같은 실제 행위자·세션·흐름과 요청 실행으로 연결하고 조회 끝 이후 결과도 현재 관측 범위까지 연결한다.
- D1/D7/D30은 최초 핵심 이용일의 정확한 KST 날짜별 재이용이다. PWA는 최초 PWA 핵심 이용일 기준이다. 기간 외 필터가 있으면 코호트 미지원으로 표시한다. 계정 확인 후 첫 채점은 확인 시각부터 정확히 7×24시간이고 미성숙·관측 불가·최초 여부 불명 회원은 성공/실패 비율의 확정 표본으로 쓰지 않는다. 부분 기간에서는 확정 전환을 제공하지 않는다.
- 최초 시각 요약은 원본·활동일 만료로 갱신하지 않는다. 이번 버전은 조건별 상태 대신 보수적인 공통 `first_usage_known`을 사용한다. 기존 계정을 수집 시작 전에 등록하고, 요약 유실 후 이전 180일을 복원할 수 없는 계정·수집 중단 때 아직 미확정인 조건이 있는 계정은 unknown으로 제외한다. 시각 값은 유지하며 알려진 조건까지 새 회원으로 분류하지 않는다.
- 품질 카드의 제출/수락/중복/유효성 거절/처리 실패는 서버에 도달한 기능 항목의 관측값이다. 세션 상태는 별도 카운터다. 채널·시험 필터는 품질 카드에 적용하지 않는다. 인증 실패·서버 전면 장애의 요청 단위는 안전한 오류 코드 로그로만 관측하며 전체 누락률을 산출하지 않는다.
- Vercel 조회 토큰/프로젝트 권한을 연결하지 않았으므로 방문자 지표는 제공하지 않는다. 장기 발행 자동화·공유 캐시·CSV·커뮤니티/채팅 작성·서버 확인 이벤트·첫 채점까지 시간 구간·코호트의 추가 속성 필터는 설계의 후속 범위다.

## 코드·API·권한

- `src/hooks/useUsageTracking.ts` + `src/utils/analyticsClient.ts`: 계정 경계, 실제 조작 최대 분당 한 번 상태 보고, 정규화 경로, 채널별 세션, 문서/진입 ID, 입력/실행 ID, 최소 메모리 큐.
- `src/utils/usageAnalytics.ts`: 운영 빌드/명시 활성화/허용 origin이 모두 맞을 때만 전송. 개발·preview는 기본 수집 없음. 브라우저에는 anon/publishable 키만 있다.
- `supabase/functions/usage-events`: POST `{ events: [...] }`, 최대 50개·64KB, 이벤트별 ACK. 선택 Bearer를 실제 Auth로 검증하며 무효 토큰을 익명으로 재해석하지 않는다. 사용자 ID·출처는 서버가 설정한다.
- `supabase/functions/admin-analytics`: GET `report`, `member-directory`, `member-activity`, `admin-access-history`, `dashboard`, `activity-feed`, `member-options`. 실제 JWT 및 현재 `current_user_is_admin()` 확인 후만 RPC를 호출한다. SQL도 `private.admin_roles`의 실제 요청자 역할을 다시 검사한다.
- 함수 설정의 `verify_jwt=false`는 공개 익명 수집과 애플리케이션의 명시적인 JWT 검증을 위한 설정이다. 관리자 조회 인증 생략을 뜻하지 않는다.
- 새 테이블은 모두 `private`, RLS 활성화·클라이언트 정책 없음·anon/authenticated/PUBLIC grants 없음이다. 서버 service role만 읽고 추가·갱신한다. 공개 스키마의 `SECURITY INVOKER` RPC는 service role에만 EXECUTE를 부여하여 private 스키마를 PostgREST에 노출하지 않는다. 기존 `public.analytics_summary`를 사용하지 않는다.
- 개인 목록/활동/조회 이력 API는 조회당 같은 트랜잭션에서 `product_admin_access_logs`를 기록한다. 실제 관리자·대상·기간·허용 필터·반환 수·응답 제공 상태만 기록하고 이름/이메일 검색어를 복사하지 않는다. 로그 쓰기 실패를 성공으로 숨기지 않는다.
- 모든 관리자 응답 `Cache-Control: no-store`, 클라이언트는 요청 전후 계정을 검사한다. 화면은 계정별로 재마운트하고 뒤늦은 응답은 취소한다. 서버 응답/검색어/토큰/원본 DB 오류를 콘솔에 출력하지 않는다.
- 큐는 메모리 최대 250개·50개 배치·5초 간격이며 미확인 ACK/처리 실패/네트워크만 원본 ID로 최대 2회 재시도한다. 계정 전환 때 이전 큐와 늦은 저장/설치 결과를 버린다. 오프라인 영구 큐·지문·장기 익명 ID가 없다. 저장소 차단 시 문서 내 세션만 유지한다.
- 수집은 클라이언트 보고이며 악의적인 실제 이용 위조를 완전히 차단하지 않는다. 사용자별/익명 요청 주소 기반의 분당 해시 키로 240항목을 제한한다. 원본 IP는 저장하지 않으며 공유 네트워크와 프록시 신호의 한계가 있다.

## 로컬 검증

```sh
npm run test:analytics
npm run test -- src/utils/analyticsClient.test.ts src/utils/adminAnalyticsApi.test.ts
npm run test:e2e -- e2e/admin-analytics.spec.ts
npm run check
```

`test:analytics`는 정확히 고정한 개발 의존성 PGlite 0.5.8의 임시 메모리 PostgreSQL에 합성 계정·역할·KV만 생성한다. 운영 DB/네트워크를 쓰지 않고 마이그레이션 전체 적용·역할별 권한·중복·관찰/복구·최초 요약·집계/감사 등을 검증한다. Deno는 의존성 최초 설치에 네트워크가 필요하며 요청 테스트의 Auth/DB는 모의다. Playwright는 모든 Supabase 요청을 가로채고 통계 GET만 검증한다. 기기 너비/UA 테스트를 실제 PWA 설치 검증으로 해석하지 않는다. 배포 전 iOS/iPadOS·Android·PC 실제 앱 창은 격리 환경에서 확인한다.

## 운영 적용 전 순서

1. 운영 변경 승인 뒤 원격 스키마·기존 관리자 RPC·역할/마이그레이션 이력과 대상 프로젝트를 다시 읽기 전용으로 확인한다. 로컬 마이그레이션 `20261003141220_product_usage_analytics.sql`, `20261004050638_admin_dashboard_and_member_options.sql` 순서로 승인된 검증 프로젝트에서 적용하고 실제 PostgREST·Auth·일반 회원 차단·역할 회수·트리거 권한을 검증한다.
2. 원본/상태 90일·회원 활동일 180일·조회 이력 13개월 등 제안 보존과 탈퇴 처리를 확정한다. **자동 삭제·Cron·탈퇴 cascade는 이번 구현에 없다.** 조회는 90일로 제한되지만 실제 저장 행이 자동 삭제되는 것은 아니다. 최초 요약은 분리 보존한다.
3. DB를 먼저 적용하고 `usage-events`와 `admin-analytics` 두 함수를 별도로 배포한다. 기존 GitHub 배포 워크플로는 `make-server-cd835c22`만 배포하므로 main push만으로 신규 함수가 배포되지 않는다. 함수 경로는 `supabase/functions/`이며 레거시 `src/supabase/functions/`가 아니다.
4. 함수의 기본 Supabase URL·anon·service role 설정과 `ANALYTICS_ALLOWED_ORIGINS`(쉼표로 구분한 정확한 운영 origin)을 확인한다. `USAGE_ANALYTICS_ENABLED`는 기본 false로 둔다. 관리자 조회만 먼저 확인하고 일반 계정에 실제 회원 정보가 반환되지 않는지 확인한다.
5. 수집 승인을 받은 뒤 기존/승인된 테스트 계정 목록을 확인하고 DB `product_analytics_settings`의 최초 `started_at`을 최초 개시 시각으로 설정하며 `collection_enabled=true`, 서버 `USAGE_ANALYTICS_ENABLED=true`, 프론트 `VITE_USAGE_ANALYTICS_ENABLED=true`와 `VITE_USAGE_ANALYTICS_ORIGINS`를 운영 origin에 맞춰 활성화한다. 최초 개시 시각을 재시작 때 바꾸지 않는다. preview를 운영 origin 목록에 넣지 않는다.
6. 중지는 DB `collection_enabled=false`를 먼저 적용하여 알려진 공백을 트리거에 기록하고 서버/프론트 스위치를 끈다. 재개는 서버 준비 후 DB를 다시 활성화하여 공백 끝을 기록한다. 환경 변수만 끈 중단·네트워크 장애의 시간은 DB가 자동 알지 못하므로 운영 확인 없이 완전 관측으로 해석하지 않는다.
7. 기존 공식/사설 이력·공개 문항 통계의 동작, 수집량·DB 증가량·기간별 쿼리 지연을 확인한다. 인덱스만으로 실제 운영 부하를 보장하지 않는다. 스케줄러/삭제·공유 캐시·대규모 발행 집계를 추가하려면 별도 변경 검토를 진행한다.

main push는 Vercel 배포와 기존 이력 함수 배포를 유발할 수 있다. 기능 단위 커밋을 권장하며 push·원격 DB 적용·함수 배포는 별도 명시적 요청 뒤 진행한다.

## 초기 통계 작업 검증 결과 (확장 이전)

최종 `npm run check` 통과: lint 오류 0(기존 경고 유지), TypeScript, Vitest 161개, 기존 이력 Edge 100개, 신규 통계 Edge 7개, 임시 PostgreSQL 통계 검증, 모의 앱 E2E 45개, 빌드·공개 83개 경로 사전 생성, 사전 렌더링 검증 8개. 첫 전체 실행의 기존 정책 화면 이동 시간 초과는 단독 재검증 및 두 번째 전체 실행에서 통과했다. 변경한 기존 TSX의 lint 경고/오류 수가 기준 코드보다 증가하지 않음을 별도로 비교했다. 운영 스키마 읽기 외 운영 데이터 쓰기·배포·수집·push는 없다.
