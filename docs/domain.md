# 도메인

관리자 사용자 데이터의 로컬 목록 확장은 UID를 숨기고 채점·사설 저장 횟수를 표시한다. 두 과목 동시 채점은 1회이며 로그인 유지 재방문을 포함한 마지막 서비스 이용순으로 정렬한다. 일반 사용자 UI는 유지한다. 전체 이력 탈퇴 보관 정책·운영 미적용 상태는 [회원 목록 확장](admin-user-data-member-list.md)을 따른다.

## 채점

홈과 기출문제를 포함한 공개 정적 화면은 기존 UI를 유지하면서 최초 HTML에도 본문과 검색 메타데이터를 제공한다. 검색 제목·설명에서 채점, 문항별 정답률, 기출문제를 강조한다. 기출문제의 최초 HTML에는 빌드 시 공개 발행된 문항별 정답률을 기존 접힌 정답표 안에 포함한다. 브라우저 앱에서 사용하는 실제 문항별 정답률과 선지별 응답 분포는 기존 공개 통계 조회를 사용한다. DB 통계 갱신 뒤 정적 HTML까지 갱신하려면 재빌드·재배포가 필요하며 코드 수정이나 새 push는 필요하지 않다. [HTML 갱신 절차](question-statistics-html.md)를 따른다.

홈에서 연도, 시험 유형(홀수형/짝수형), 언어이해·추리논증 답안을 받아 즉시 채점한다. `src/utils/grading.ts`가 `answerData.ts`와 `scoreData.ts`를 사용해 정답 수, 표준점수, 백분위, 영역 분석, 보정 점수를 포함한 `GradingResult`를 만든다.

결과 페이지는 과목별 결과·답안·오답을 보여 준다. 로그인 사용자는 결과의 문항별 메모를 `grading_notes`에 저장할 수 있다.

### 문항별 공개 정답률

짝수형 정답률 영역과 응답 분포 모달에는 "짝수형은 다회독 데이터가 많아 실제 정답률보다 높게 나타나는 경향이 있습니다."라는 안내를 제공한다. 집계 일자는 사용자 화면에 표시하지 않으며 DB와 개발자 갱신 도구에만 유지한다.

채점 후 결과 화면과 펼친 기출문제 정답표에서 문항별 정답률 버튼을 눌러 1~5번 선지·미응답의 비율(퍼센트)만 확인한다. 채점 기록 수와 선지별 응답 건수는 사용자 화면·접근성 라벨에 표시하지 않는다. 미응답은 오답에 포함하고 재채점 기록도 포함하며, 학년도·과목·홀수형/짝수형별로 분리한다. 표본 크기와 무관하게 비율은 제공하되 30건 이하에는 기존 데이터 부족·정확도 안내를 유지한다. 0건은 미계산(`—`)이다. DB/개발자 갱신 도구에는 계산·검증용 건수를 유지한다.

최초 집계한 DB 발행본을 두 화면에서 조회하고 개발자가 필요할 때만 수동 갱신한다. 기존 2초 정답 보기·메모·정답표 접기·시험 선택·환산표는 유지한다. 정답 버전이 다른 과거 개인 결과에는 현재 통계를 섞지 않는다. [설계](question-statistics-design.md)와 [갱신 규칙](question-statistics.md)을 따른다. 2026-09-17 DB 구조/최초 발행은 적용했으며, 화면 기능은 v1.2.0 릴리스에 포함한다. 웹 배포 시 DB 마이그레이션 재실행이나 Edge Function 배포는 필요하지 않다.

## 기출문제 파일

기출문제 탭에서 09예비~2026학년도 두 과목의 홀수형·짝수형 76개 및 2027학년도 단일 문형 2개를 로그인 없이 제공한다. 총 78개 모두 하단에 `리트 채점은 all LEET` 워터마크를 넣은 PDF이며, Supabase 공개 Storage에서 브라우저 열기·다운로드를 지원한다. 출처 링크·HWP 안내는 표시하지 않는다. 전개년·전과목 PDF 제공과 법학전문대학원협의회 저작권을 안내한다. 학년도 드롭다운 및 과목·문형 선택 버튼과 문제지·정답표·환산표 카드의 디자인을 통일한다. 2027학년도는 단일 문형으로 표시하며 정답·환산표와 홈 채점을 제공한다. 홈 기본 학년도는 2027이다. 제공된 환산값 외 구간은 추정하여 0개~만점을 지원하고, 사용자가 제공한 시행결과에 따라 두 과목의 70문항을 각각 5개 분야로 분석한다. 데이터 출처와 추정 방식은 [2027 채점 데이터](grading-2027.md)를 따른다. 파일 등록은 [기출문제 문서](past-exams.md)에 기록한다.

## 공식 시험 이력과 성적 추이

로그인 사용자의 채점 결과는 Edge Function을 거쳐 KV 저장소에 기록된다. 같은 시점의 두 과목은 `groupTimestamp`로 묶인다. 이력 화면은 회독, 연도, 과목 조합을 사용해 표준점수·백분위·정답률 추이를 시각화한다.

비로그인 채점은 저장 요청 없이 결과를 제공한다. 로그인 상태에서 저장이 실패해도 채점 결과와 답안을 표시하고 과목별 저장 실패 안내를 제공한다. 조회 오류는 빈 이력과 구분하며 다시 불러오기 버튼을 제공한다. 조회 중이거나 오류가 난 상태에서 전체 삭제는 비활성화한다. 응답을 확인하지 못한 쓰기는 중복 저장 방지를 위해 자동 반복하지 않는다.

## 사설 모의고사

시험일, 기관, 회차, 과목별 표준점수·백분위를 입력한다. `MockExamRecord`는 Edge Function 경유 KV에 저장되며, 이력 화면에서 기관 필터와 추이 차트를 제공한다.

저장 성공을 확인한 경우에만 이력 화면으로 이동한다. 저장 실패 시 입력 화면과 현재 입력값을 유지한다. 입력값의 새로고침 복구나 영구 초안 저장 기능은 제공하지 않는다.

## 로스쿨 지원 분석

LEET 합산 표준점수와 GPA를 받아 `src/utils/lawschool.ts`의 학교별 기준으로 지원 가능성을 계산한다. 결과는 적정·소신·불가로 나뉘며, 입력과 계산 결과는 화면 이동 및 새로고침 복구를 위해 `sessionStorage`에도 저장된다.

## 커뮤니티

커뮤니티는 게시글, 댓글, 좋아요, 신고, 조회 수, 이미지 첨부를 제공한다. 게시글 이미지는 `community-post-images` Storage 버킷에 업로드하고, 공개 URL 배열을 `community_posts.image_urls`에 저장한다. 화면 구현은 `CommunityPage.tsx`, `CommunityPostPage.tsx`에 있다.

`src/utils/communityStorage.ts`에는 localStorage 기반의 과거 커뮤니티 구현이 남아 있지만, 현재 커뮤니티 페이지는 Supabase 테이블을 직접 사용한다.

## 전체 채팅

전역 room ID는 `global`이다. 비로그인 사용자는 공개 메시지를 읽을 수 있고, 로그인 사용자는 자동 생성된 고유 닉네임으로 작성한다. `ChatPage.tsx`와 `RecentChatBanner.tsx`는 `chat_messages` INSERT 이벤트를 Realtime으로 구독한다.

## 공지

홈 공지는 `home_announcements`에서 읽어 배너로 순환 노출한다. 운영자는 `/admin/announcements`에서 제목·본문·배너 문구, 발행 상태, 홈 배너 노출 여부와 순서를 관리한다. 상세 운영 절차는 `docs/admin-announcements.md`를 따른다.

## 관리자 디데이 설정

승인된 관리자 메뉴에 `/admin/dday`를 추가했다. 시험일과 공통 표시 문구를 함께 편집하고 `{date}`·`{dday}`를 치환한 홈·로그인·회원가입 미리보기를 확인한다. 입력을 검증한 뒤 한 번에 저장하며 충돌에는 최신 값을 확인하고 입력을 유지한다. 응답이 유실된 저장은 반복하지 않고 서버 설정을 읽어 확인한다. 권한 상실·계정 전환에는 편집 상태를 제거한다.

승인된 홈·로그인·회원가입은 같은 날짜·템플릿을 사용하며 한국 시간 자정과 복귀 시 디데이를 다시 계산한다. 관리자 저장 응답은 현재 앱에 즉시 반영하고 다른 열린 화면은 정상 네트워크에서 최대 60초 뒤 반영한다. 치환자는 선택 사항이며 일반 문구만 표시할 수도 있다. 조회 실패에도 주요 기능은 사용할 수 있고, 캐시가 있으면 마지막 설정임을 안내한다. 초기 HTML에는 조회 중 상태만 기록한다. 운영 DB의 설정 테이블은 v1.6.0 릴리스 요청에 따라 적용했다. 구현 범위·운영 적용 경계는 [디데이 설계](admin-dday-design.md)를 따른다.

## 관리자 이용 통계

승인된 관리자 메뉴의 이용 통계에서 개요·기능·채점·회원/재방문·회원 활동·PWA·관리자 조회 이력을 제공한다. 실제 회원 ID·현재 계정 이름/이메일로 누가 어떤 기능을 이용했는지 조회하며 비로그인 기록은 세션 단위다. 다른 회원 로그인 이후 익명/이전 계정 기록을 소급 귀속하지 않는다.

자체 이용은 KST 서버 수신 기준의 회원/세션 DISTINCT다. 화면 조회와 실제 행동, 채점 계산과 저장 응답, 과거/예시 결과와 새 결과를 구분한다. 전환은 동일 세션/입력/실행의 관찰 종료 표본이며 진행·유예·미확정은 별도 표시한다. 재방문은 최초 핵심 이용일의 정확한 D1/D7/D30이고 PWA는 최초 PWA 핵심 이용을 사용한다. 설치 신호와 PWA 이용은 별개이며 현재 보관 이력을 누적 채점량으로 해석하지 않는다.

표시 값은 클라이언트 관측 자료이고 수집 전·미보존·수집 중단·오류를 실제 0건과 구분한다. 관리자 및 테스트 계정 제외, 지원하지 않는 지표별 필터, Vercel 방문 자료 미연결, 실제 기기 검증/후속 범위는 [통계 구현·운영](admin-analytics.md)을 따른다. 운영 DB·함수·수집 설정은 [v1.5.0 운영 적용](admin-analytics-rollout.md)에 따라 적용한다. 과거 관측을 생성하지 않으며 수집 개시 이후의 실제 이용만 기록한다.

[변화 대시보드](admin-dashboard-design.md)의 로컬 API/재사용 컴포넌트/장기 사실 자료와 [공통 회원 선택기](admin-member-picker-design.md)의 API/컴포넌트/분리 미리보기를 구현했다. 곡선은 구간 일평균이고 카드의 기간 DISTINCT와 구분한다. 주요 변화는 정책 2의 감소 우선·범주당 1개/총 3개다. 오늘은 별도 잠정이다. 장기 발행이 없는 날짜는 미가용이며 이전 이용을 복원/추정하지 않는다.

회원 목록은 실제 일반 회원의 가입 최신순 탐색이며 수집 전/미활동 계정도 포함한다. 감사 목적은 현재/과거의 실제 UUID를 탐색하며 현재 계정 정보 유무와 현재 관리자 역할을 구분한다. 선택은 개인 조회·감사 대상에만 적용하여 전체 통계 모수를 바꾸지 않는다. 새 대시보드/선택기는 승인된 실제 앱에 연결했으며 구현·검증·운영 경계는 [확장 구현 문서](admin-dashboard-implementation.md)를 따른다.

## 관리자 사용자 데이터 (v1.7.0)

기존 관리자 모두 `/admin/user-data`에서 관리자·테스트 계정을 포함한 사용자를 선택한다. 기존 성적 이력·결과·지원 분석 화면과 게시글/채팅 표시를 데이터 주입 방식으로 재사용한다. 빈 관리자 이력은 실제 0건이며 일반 사용자 예시는 유지한다. 매 변경·삭제는 지정 경고와 `승인` 직접 입력을 거친다. 기출 식별/회독/시각과 이메일은 읽기 전용, 이용 원본은 조회·삭제, 관리자 감사와 파생 이용 자료는 조회 전용이다. 이름·채팅 닉네임, 점수/답안/선택 재계산, 메모, 커뮤니티·채팅 내용과 이미지 변경을 지원한다. 영구 삭제 전 타인 참여와 연결 메모의 영향을 확인한다.

지원 분석은 기존 사용자 화면 변경 없이 실행마다 서버에 입력·결과를 저장한다. Auth 계정 탈퇴 뒤에도 영구 보관하며 관리자 개별 삭제는 허용한다. 저장 실패는 관측 가능할 때 관리자 영역에만 표시한다. 자세한 계약과 제한은 [사용자 데이터](admin-user-data-design.md)를 따른다.

## 웹·PWA 수동 운영 알림

푸시 관리자에서는 등록 완료 구독의 중복 없는 회원 수와 전체·회원 연결·비회원 기기 수를 확인한다. 비회원 사람 수와 물리 기기 수를 추정하지 않는다. 해지/만료 구독과 탈퇴·차단 계정은 제외하고 조회 실패는 0으로 표시하지 않는다. [푸시 구독 통계](push-subscriber-statistics.md)의 집계 기준을 따른다.

비로그인도 명시적 최초 동의와 기기 수신 확인 뒤 구독할 수 있다. 별도 알림 설정·종류 토글은 없다. 관리자는 전체 구독자(비로그인 포함)·전체 회원·선택 회원을 구분하고 본인 현재 브라우저 한 기기로 테스트한다. 발송마다 공개 내부 이동 주소를 지정한다. 전체 구독자/전체 회원은 같은 제목·본문·주소의 기기 테스트 접수와 실제 표시·클릭 확인이 필수다. 초안은 관리자별 서버 저장·불러오기이며 수동 저장이다.

서비스 최초 안내는 팝업이다. 회원·비회원 구분 없이 일반 서비스 접속 후 3초 지연 자동 표시하며 실제 브라우저 권한은 동의 버튼 클릭에서만 요청한다. ‘나중에’·닫기·Esc·바깥 클릭은 해당 브라우저에서 7일 동안 자동 안내하지 않는다. 별도 재진입 링크 없이 팝업으로만 진행하며, 등록 완료·등록 대기·7일 유예 중과 관리자 작업 화면에는 자동 표시하지 않는다. 미동의·미등록은 서버 오류와 관계없이 안내하고, 차단·미지원·설치 필요는 해당 안내를 자동 표시한다. 로그인/설치만으로 구독시키지 않는다. 브라우저에서 허용을 선택하거나 이미 허용한 기기에서 등록을 시작하면 팝업을 즉시 닫고 서버 등록은 계속한다. 허용 후에는 같은 서비스 방문 중 자동으로 다시 열지 않고, 7일 나중에 유예를 기록하지 않는다. 실패한 미등록 기기는 다음 접속에서 팝업으로 다시 안내한다.

푸시 서비스 접수와 실제 표시·읽음을 구분한다. 철회·계정 전환·중단·TTL을 존중하며 unknown은 자동 재발송하지 않는다. 미전송 중단은 이미 접수한 알림을 회수하지 않는다. 푸시 기록 자동 삭제, 공지 연결, 앱 기능 자동 알림, 예약 발송은 없다. 승인된 관리자/홈 UI를 구현했다. 기본 off이며 v1.9.0에서 운영 등록·현재 기기 테스트를 먼저 활성화한다. 일반 전체/선택 발송 개방 전 실제 기기와 처리량을 확인하는 단계는 [운영 기록](push-notifications-rollout.md)을 따른다. [설계](push-notifications-design.md)와 [구현 경계](push-notifications-implementation.md)를 따른다.
