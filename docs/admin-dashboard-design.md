# 관리자 변화 대시보드 설계

작성일: 2026-10-04 KST. 상태: **서버·계산·재사용 컴포넌트·분리 미리보기 로컬 구현 / 실제 앱 UI 연결 완료 / 운영 DB·함수 적용 / 웹 배포는 [운영 기록](admin-analytics-rollout.md) 참조**.

추가 요구 반영: 시간에 따른 변화는 막대 대신 **곡선으로 이어지는 선 그래프**를 사용하며, **7일·30일·6개월·1년**을 선택한다. 장기 자료·정확한 고유 수·동일 길이 비교 계약을 아래에 함께 정의했다. 기간 선택이 동작하는 분리된 가상 미리보기를 갱신했으며 새 UI는 실제 앱 연결을 완료했으며 DB는 운영 미적용이다.

통합 재검토 반영: [2026-10-04 검토](admin-analytics-review-20261004.md)의 네 보완안을 아래 계산·선정·API·인수 기준에 반영했다. **아래 설계 계약은 로컬 서버·계산·컴포넌트에 반영했다. 실제 앱의 새 UI 연결은 사용자 승인 뒤 완료했다.** 구현과 현재 검증은 [확장 구현 문서](admin-dashboard-implementation.md)를 따른다.

기존 [이용 통계 설계](admin-analytics-design.md)의 개요를 확장하여 운영자가 최근 변화를 빠르게 파악하는 화면을 만든다. 기존 7개 상세 탭은 분석·확인에 사용한다. API·로컬 마이그레이션·분리된 구현 미리보기를 준비한 뒤 사용자의 명시적 UI 변경 승인을 받아 실제 관리자 화면에 연결했다. 초기 개발에서는 운영을 변경하지 않았으며, 이후 사용자 배포 요청에 따른 적용 상태는 [운영 기록](admin-analytics-rollout.md)을 따른다.

## 1. 목적과 화면 위치

운영자가 화면을 열고 다음 세 가지를 확인할 수 있어야 한다.

1. 최근 이용이 얼마나 늘거나 줄었는가?
2. 어느 기능·채널·채점 흐름에서 변화가 컸는가?
3. 어떤 회원이 최근 무엇을 했으며, 더 확인할 기록은 어디에 있는가?

`/admin/analytics`의 기존 **개요**를 대시보드로 확장하는 안을 제안한다. 별도 관리자 메뉴나 유사한 통계 화면을 중복 추가하지 않는다. 기본 기간은 최근 완료된 7일이며 같은 길이의 직전 기간과 비교한다. 오늘은 미완료 기간이므로 별도의 잠정 현황으로 제공한다.

일차 출시에는 사이트 이용·채점·기능별 변화·PWA·최근 실제 회원 활동을 포함한다. 현재 보관된 성적 총량, 관리자 감사 목록, 설치 안내 신호, 복잡한 재방문 코호트는 기존 상세 탭에서 확인한다.

## 2. 화면 구성

```text
이용 통계 / 개요
최근 완료된 7일 ▼  전체 채널 ▼                 새로고침
분석 기간 · 비교 기간 · KST 수신 기준 · 조회 기준 시각
자료 가용 상태 / 부분 기간·비교 불가 안내

활성 회원       이용 세션         채점 완료
결과 조회 세션  PWA 활성 회원     신규 확인 회원
각 카드: 현재 값 / 이전 값 / 절대 변화 / 증감률 / 작은 곡선 그래프

이번 기간 주요 변화 (최대 3개) → 같은 조건으로 상세 보기

이용 추이 (곡선 선 그래프)       기능별 변화
7일 / 30일 / 6개월 / 1년        회원·세션·행동 / 이전 대비
한 지표 선택 + 이전 기간

채점 입력 → 결과 관측            PWA 이용
종료 표본·진행·유예·미확정        세션 비중·회원 중복·이용 추이

최근 회원 활동                  오늘 잠정 현황
이름·이메일·행동·채널·시각        세션·채점·마지막 수락 관측
→ 해당 회원 활동                기간 완료 전 증감·주요 변화 제외
```

- 데스크톱은 핵심 카드 3열, 본문 2열, 모바일은 1열이다. 카드와 표를 같은 읽기 순서로 배치한다.
- 추이는 **일평균 활성 회원 / 일평균 이용 세션 / 일평균 채점 완료** 중 하나를 선택한다. 현재는 곡선 실선, 이전 기간은 곡선 점선으로 연결하고 실제 기간·날짜·정확한 값은 툴팁·표에 제공한다. 단위가 다른 지표를 같은 축에 겹치지 않는다. 작은 카드 그래프에도 같은 일평균 계산과 선 표현을 사용한다. 카드 본문은 기간 전체 값이고 작은 그래프는 일평균 추이라는 차이를 명시한다.
- 곡선은 일평균 집계점을 지나는 단조 보간으로 그리며 관측값 사이에 새로운 최대/최솟값·음수·과장된 봉우리가 생기지 않게 한다. 일평균은 고정 구간의 집계이며 이동 평균이나 추가 평활화는 적용하지 않는다. 미가용·부분 자료 구간은 `null`로 선을 끊는다. 점이 하나면 점만, 가용한 모든 값이 0이면 0선으로 표현한다.
- 색은 수치 방향을 보조하고 `증가`, `감소`, `비교 불가` 문구를 함께 쓴다. 이용 증가를 자동으로 정상, 감소를 자동으로 장애라고 표시하지 않는다.
- `—`는 미관측·미지원·비교 불가이고, 가용한 기간의 실제 0건은 `0`이다. 부분 일자의 그래프는 끊거나 부분 표시를 하며 완전한 0으로 채우지 않는다.
- 별도 [예시 미리보기](previews/admin-dashboard.html)의 숫자와 이름은 전부 가상 자료다. 실제 앱 변경이나 운영 연결의 증거가 아니다.

## 3. 핵심 지표와 변화 계산

| 카드 | 기준 | 비교·상세 이동 |
|---|---|---|
| 활성 회원 | 기존 `is_active` 이용 이벤트의 실제 `user_id` 기간 DISTINCT | 이전 동일 기간 / 회원 탭 |
| 이용 세션 | 로그인·비로그인 포함 기존 활성 이용의 `session_id` 기간 DISTINCT | 이전 동일 기간 / 기능 탭 |
| 채점 완료 | `grading_completed`의 `grading_run_id` 기간 DISTINCT | 이전 동일 기간 / 채점 탭 |
| 결과 조회 세션 | 새 채점의 정상 `grading_result_viewed`가 있는 세션 DISTINCT | 이전 동일 기간 / 채점 탭 |
| PWA 활성 회원 | 실제 PWA 실행의 활성 회원 DISTINCT | 이전 동일 기간 / PWA 탭 |
| 신규 확인 회원 | 해당 기간 계정 확인이 완료된 회원 수 | 전체 채널일 때만 제공 / 회원 탭 |

기존 활성 판정·제외 계정·실제 회원 식별·중복 제거는 [구현·운영](admin-analytics.md)을 따른다. 활성 회원은 핵심 학습 행동 회원과 다른 정의이며, 설치 안내·세션 상태 보고만으로 증가하지 않는다. 두 과목 채점은 완료 1회이고 과거 결과·예시 결과는 새 결과 조회가 아니다.

- 수치 변화: `현재 - 이전`, 증감률: `(현재 - 이전) / 이전 × 100`.
- 이전이 0이고 현재가 양수이면 `이전 0 → 현재 N`, 현재·이전이 모두 0이면 `변화 없음`이다. 무한대·100% 성장으로 대체하지 않는다.
- 비율 변화는 퍼센트포인트(`%p`)로 표시하며 분자·분모를 함께 제공한다. 예: `72/100 → 68/100, -4%p`.
- 현재와 이전 모두 가용한 완료 기간, 같은 정의 버전·필터·모수일 때만 비교한다. 첫 수집 주간·보존 경계·확인된 중단·부분 기간은 비교와 주요 변화에서 제외한다.
- 기간 회원·세션 수는 전체 기간 DISTINCT다. 일별/주별/월별 값을 더해서 카드 합계를 만들지 않는다. 곡선은 아래의 일평균, 툴팁·표의 구간 고유 수는 해당 구간 DISTINCT, 카드 본문은 선택 기간 전체 DISTINCT다. 서로 다른 값을 같은 지표 이름으로 표시하거나 곡선 합으로 카드 값을 복원하지 않는다.
- 신규 확인 회원은 현재 Auth 계정 기준이다. 탈퇴 처리 등으로 과거 값이 바뀔 수 있으며 과거 시점 계정 스냅샷으로 표현하지 않는다.

### 곡선의 일평균 계산 기준

집계 구간을 `B`, 포함된 KST 달력 일자 수를 `N`, 각 날짜의 활성 회원 집합을 `U_d`, 활성 세션 집합을 `S_d`, 채점 완료 실행 집합을 `G_d`로 둔다. 동일한 활성 판정·제외 계정·채널 필터·지표 버전을 적용한다. 모든 일자가 완료·가용한 구간에서만 아래 평균을 계산한다.

| 표시 | 계산 | 의미 |
|---|---|---|
| 일평균 활성 회원 곡선 | `sum(count(DISTINCT U_d)) / N` | 평균적으로 하루에 이용한 회원 수 |
| 일평균 이용 세션 곡선 | `sum(count(DISTINCT S_d)) / N` | 평균적으로 하루에 관측된 활성 세션 수 |
| 일평균 채점 완료 곡선 | `sum(count(DISTINCT G_d)) / N` | 평균적으로 하루에 완료된 채점 실행 수 |
| 구간·기간 고유 회원 | 해당 구간·기간의 `count(DISTINCT user_id)` | 기간 안에서 한 번 이상 이용한 회원 수 |
| 구간·기간 고유 세션/실행 | 해당 구간·기간의 `count(DISTINCT session_id / grading_run_id)` | 자정·구간 경계와 무관하게 중복 제거한 수 |

한 세션이 자정 전후에 활동하면 두 날짜의 일별 세션 수에는 각각 포함되지만 기간 카드에서는 한 번이다. 채점 완료 실행은 중복 수신과 무관하게 최초 수락된 완료 이벤트의 KST 일자 하나에 귀속하여 일별 합에 중복되지 않게 한다. 다른 카드의 작은 그래프도 카드와 동일한 모수의 일별 고유 수/횟수로 평균을 구한다. 신규 확인 회원은 확인 완료 KST 일자를 사용하고 지원하는 날짜 범위에서만 표시한다. 비율 지표가 추가되면 이 건수 평균을 재사용하지 않고 별도 분자/분모 계약을 정의한다.

- `N`은 해당 구간 전체의 달력 일수다. **가용한 0건 날짜도 포함**한다. 날짜별 자료가 전부 가용하고 완료된 구간에서만 평균을 발행한다.
- 6개월의 마지막 1~6일 구간은 자료가 모두 가용하면 정상 완료 구간이다. 실제 일수로 나눠 연결하며 `마지막 짧은 구간 / N일`을 표시한다. 자료 누락 때문에 부분인 구간과 구분한다.
- 수집 전·확인된 공백·발행 실패·보존 경계·오늘 등으로 한 날짜라도 미가용/미완료이면 구간 평균은 `null`이다. 관측된 날짜만 분모에 남기거나 0으로 채우지 않는다. 툴팁·표에는 전체 일수, 가용 완료 일수와 상태를 제공하고 부분 관측값에는 `관측분`을 명시한다.
- 서버는 반올림 전 평균과 근거 일별 수 합을 반환한다. 표시만 소수 첫째 자리까지 반올림하며 비교·후보 선정에는 반올림 전 원자료를 사용한다. 기간 주요 변화는 일평균 점 사이의 증감이 아니라 기간 카드/정의된 전환 분자·분모로 계산한다.
- 예: 매일 같은 회원 10명·채점 10회라면 7일과 마지막 1일의 곡선은 모두 `10.0`이다. 7일 회원 고유 수는 10명이고 7일 채점 총수는 70회로 별도 표시한다. 7일 중 하루가 가용한 0회이면 채점 평균은 `60/7`, 하루가 미가용이면 `null`이다.

## 4. 이번 기간 주요 변화

최대 3개의 짧은 문장으로 변화를 강조한다. 서버의 규칙 계산 결과를 사용하며 생성형 AI·원인 추정·자동 외부 알림은 일차 범위에 포함하지 않는다.

예시:

- `기출문제 행동 세션 120 → 180개 (+60개, +50%). 기출문제 이용 보기`
- `PWA 활성 회원 48 → 62명 (+14명, +29.2%). PWA 보기`
- `입력→결과 관측률 72/100 → 68/100 (-4%p). 채점 흐름 보기`

초기 표시 기준은 통계적 유의성 검정이 아닌 운영용 기준이며, 이번 수정안을 `dashboard_policy_version=2`로 정의한다. 기본 이벤트·기간 고유 수 정의는 유지하고 그래프 표현·선정 정책의 버전을 구분한다.

| 유형 | 주요 변화 후보 기준 |
|---|---|
| 건수 | 현재·이전 중 큰 값 20 이상, 절대 변화 10 이상, 이전이 양수이면 증감률 절댓값 20% 이상 |
| 이전 0 | 현재 20 이상일 때 `이전 0 → N`으로 후보 등록 |
| 비율 | 현재·이전 분모 각각 50 이상, 변화 절댓값 3%p 이상 |

후보는 이용량(회원·세션), 기능, PWA, 채점 관측률 네 범주다. 현재·이전 모두 완료·가용·지원되고 같은 정의/필터인 후보만 선정한다. 채점 관측률의 분모는 관찰 종료 표본이며 진행·유예·미확정을 확정 표본에 넣지 않는다. 장기 기간 미지원 전환은 후보에서 제외한다.

아래 순서로 후보를 정렬한 다음 위에서부터 **범주별 최대 1개, 전체 최대 3개**를 선택한다. 이미 선택한 범주는 건너뛴다. 기존의 고정 범주 순서로 먼저 세 자리를 채우지 않는다.

| 순위 | 후보 | 같은 순위 안의 정렬 |
|---|---|---|
| 1 | 채점 관측률 감소: 두 분모 각각 50 이상, 변화 `-3%p` 이하 | 감소 %p 절댓값 내림차순 |
| 2 | 건수 감소: 위 건수 후보 기준 통과 | `abs(현재-이전) / max(이전, 20)` 내림차순 |
| 3 | 채점 관측률 증가: 두 분모 각각 50 이상, 변화 `+3%p` 이상 | 증가 %p 내림차순 |
| 4 | 건수 증가·이전 0: 위 후보 기준 통과 | `abs(현재-이전) / max(이전, 20)` 내림차순 |

건수 점수의 분모 하한 20은 작은 기준값과 이전 0의 정렬을 위한 정책이다. 이전 0의 실제 증감률로 표시하지 않는다. 같은 순위·점수의 동률은 건수의 절대 변화 내림차순, 마지막은 고정 `metric_key` 사전순으로 결정한다. 비율과 건수는 별도 순위 안에서 정렬하므로 건수와 %p를 직접 비교하지 않는다. 점수는 변화 발견용이며 장애 판정·통계적 유의성을 뜻하지 않는다. 모든 후보와 선정 여부는 기능/채점/PWA 등 대응 상세 변화 표에서 확인할 수 있게 한다.

표시용 반올림과 이진 부동소수점 오차가 후보 경계를 바꾸지 않도록 원래 정수 분자/분모의 교차 곱 또는 정확한 decimal 계산으로 임계값·동률을 판정한다. 예를 들어 건수 20% 기준은 `100 × abs(현재-이전) >= 20 × 이전`, 관측률 3%p 기준은 `100 × abs(현재분자×이전분모 - 이전분자×현재분모) >= 3 × 현재분모×이전분모`다. 순위 1/3의 방향은 부호로 따로 확인한다. 표시에 반올림한 3.0%p를 그대로 후보 기준으로 사용하지 않는다.

예: 회원·기능·PWA 증가 후보와 채점 관측률 `72/100 → 40/100`이 함께 있으면 관측률 감소가 첫 자리를 확보하고 다른 범주 두 개를 위 순서로 선택한다. 문구는 `입력→결과 관측률 감소 (-32%p), 흐름 확인 필요`처럼 관측 근거만 표현한다. 표본 `49` 또는 미가용 기간이면 우선 후보가 아니며 별도의 표본/자료 안내를 표시한다. 저장 실패 악화는 아직 후보에 추가하지 않는다. 추가하려면 확정 응답의 분자·분모·미확인 제외·지원 기간과 새 정책 버전을 먼저 정의한다.

해당 기준을 통과한 변화가 없으면 `설정한 기준을 넘는 변화가 없습니다`라고 표시한다. 표본 부족·자료 미가용은 별도 상태이며 같은 문구로 숨기지 않는다. 데이터 부분/비교 불가 안내는 변화 목록 위에 먼저 표시하고, 변경 원인을 특정 회원·홍보·배포 때문이라고 단정하지 않는다.

## 5. 기능·채점·PWA 상세 요약

### 기능별 변화

행마다 현재/이전의 행동 세션·행동 회원·행동 횟수를 제공하고 기본 정렬은 행동 세션의 절대 변화 크기다. 증가/감소를 모두 보여 주며 페이지 진입은 별도 열·상세 정보로 구분한다.

기존 `features.sessions/members`는 화면 진입도 포함하므로 **그 값을 그대로 실제 행동 세션/회원으로 이름만 바꾸면 안 된다.** 대시보드 집계에는 페이지뷰를 제외한 행동 세션/회원 필드를 추가한다. 채점 완료, PDF 링크 클릭, 정답표/환산표 열기, 문항 분포 열기, 정상 이력·추이 조회, 사설 저장 성공, 지원 분석 완료/결과를 허용된 행동 목록으로 명시한다. 채점 입력·요청은 채점 흐름 요약에 두며 완료 행동 횟수에 섞지 않는다. 한 기능 안의 회원·세션은 다시 DISTINCT한다.

커뮤니티·채팅은 현재 화면 진입만 계측하므로 `화면 진입`으로 표시한다. 읽음·작성·채팅 전송 완료 지표와 행동 순위 후보에 포함하지 않는다. PDF는 링크 클릭 관측이고 다운로드 완료가 아니다. 서로 다른 행동을 묶은 기능별 행동 횟수는 그 기능 내부의 비교에 쓰고 기능 간 성과 우열로 해석하지 않는다.

### 채점 흐름

관찰이 종료된 입력 시작/재개 세션 중 같은 행위자·세션·입력·요청 실행에 연결된 새 결과를 본 세션 비율을 제공한다. 관찰 종료 규칙(30분 + 15분 유예)과 알려진 처리 실패의 미확정은 기존 구현을 따른다. 진행·유예·미확정 수는 별도로 표시한다.

입력·계산·결과를 서로 다른 기간의 독립 건수로 나열하고 퍼널로 오인하게 만들지 않는다. 일차 화면은 **종료 입력 세션 → 결과 관측 세션의 두 단계**만 연결하고 완료 실행 수는 별도 수치다. 저장 응답은 성공·실패·미확인 과목별 시도 수를 보여 주며, 단순히 응답이 없다고 확정 실패로 만들지 않는다. 관측률·저장 변화의 이전 기간 분자/분모는 추가 집계가 필요하다.

### PWA 이용

- PWA 활성 회원·세션·채점 완료 및 이전 대비를 제공한다.
- 세션 비중은 `PWA 활성 세션 DISTINCT / 전체 활성 세션 DISTINCT`다. 분모에는 기타·미확인도 포함하며 이들의 세션 수와 비중을 함께 표시한다. 단순 채널별 일별 합계로 계산하지 않는다.
- 전체 회원과 PWA 회원은 중복 가능한 관계다. PWA 전용 / 브라우저 전용 / 둘 다 / 기타·미확인만의 회원 구분을 기존 정의로 표시한다. PWA와 브라우저를 모두 쓴 회원은 전체에서 한 번만 센다.
- PWA 회원은 설치 보유 인원이 아니다. 설치 안내와 설치 관측은 기존 PWA 상세 탭으로 연결한다.
- 전체 채널일 때 채널 비교를 제공한다. PWA 채널을 선택하면 `PWA 필터 적용 중`으로 표시하고 전체 대비 비중·교집합·주요 채널 변화는 제공하지 않는다. 브라우저/기타/미확인 선택에서는 PWA 고정 카드도 미지원 상태로 표시한다.

## 6. 최근 회원 활동과 오늘 현황

### 최근 회원 활동

선택 분석 기간·채널 안의 실제 로그인 회원 기능 행동을 서버 수신 시각 역순으로 최근 20개 조회한다. 기본은 5개 표시, 펼치면 20개까지 제공하고 더 오래된 가용 상세 자료는 회원 활동 탭으로 이동한다. 선택 기간이 원본 상세 가용 범위를 넘으면 피드에 별도의 실제 조회 기간(최대 최근 90일과 선택 기간의 교집합)·부분 자료 상태를 표시한다. 전체 1년의 상세 활동을 볼 수 있다고 표현하지 않는다. 교집합이 없으면 미가용이다. 페이지뷰·설치 안내·세션 상태 보고는 기본 목록에서 제외한다. 실패/미확인 저장 응답도 허용된 행동 목록에 포함해 확인할 수 있게 한다.

표시 값은 현재 이름·이메일, 실제 `user_id`, 행동, 학년도·과목 등 허용 대상 정보, 결과, 실행 채널, 수신 시각이다. 활동 시각은 펼친 상세에서 클라이언트 관측값임을 표시한다. 이름/이메일이 없거나 계정이 삭제되어 연결이 안 되면 실제 UUID와 `계정 정보 없음`을 표시하고 다른 사람에게 재귀속하지 않는다. 이벤트 UUID와 실제 회원 UUID는 상세에서 확인한다. 예시는 가상 이름이지만 실제 서비스 기록을 가명으로 바꾸지 않는다.

회원 클릭은 동일 기간·채널을 유지한 회원 활동 탭으로 이동한다. 선택 UUID는 화면 메모리 상태로 전달하고 URL에 쓰지 않는다. 단일 회원 기존 API는 전체 회원 피드를 제공하지 않으므로 새 피드 조회가 필요하다. 각 피드 조회도 실제 관리자·종류·필터·반환 수를 같은 트랜잭션에서 감사하며, 반환한 실제 회원 UUID 목록(최대 20개, 중복 제거)을 기록한다. 이름/이메일은 감사 로그에 복제하지 않는다.

피드에 아직 보이지 않는 회원은 [공통 회원 선택 목록](admin-member-picker-design.md)의 `회원 선택`으로 찾는다. 검색 없이 일반 회원 전체를 가입 최신순 50명씩 탐색하고 선택한 UUID를 같은 기간·채널의 회원 활동 탭으로 전달한다. 선택기는 피드의 최근 20명만을 후보로 삼지 않고 활동 없는 계정도 포함한다. 선택으로 전체 카드·곡선·주요 변화의 모수를 바꾸지 않는다. 이는 신규 설계이며 앱·예시 HTML에는 아직 적용하지 않았다.

### 오늘 잠정 현황

KST 오늘 00:00부터 조회 기준 시각까지의 이용 세션·채점 완료와 마지막 새 이벤트 수락 시각을 제공한다. 분석 기간과 별개의 `오늘 / 잠정 / 전체 채널` 표제를 붙이고 주요 변화 계산에 사용하지 않는다. 현재일 포함 사용자 지정 기간도 잠정 상태로 두고 비교·주요 변화에서 제외한다.

마지막 수락 시각이 오래되었다는 사실만으로 서버 장애를 선언하지 않는다. 실제 이용이 없는 경우도 가능하다. 서버 조회 실패는 `불러오기 실패`, DB 수집 스위치가 꺼진 경우는 `수집 비활성`, 알려진 중단은 `수집 중단 구간 있음`으로 표시한다. 개시 전은 `수집 시작 전`이다. 서버가 모르는 프론트/환경 스위치와 미도달 요청까지 정상 운영으로 보장하지 않는다.

## 7. 필터·갱신·데이터 상태

- 빠른 기간: **7일 / 30일 / 6개월 / 1년**. 기본은 최근 완료된 7일이다. 사용자 지정은 대시보드 집계에서 최대 1년(365/366일)이며 기존 상세 원본 조회 API의 최대 90일은 유지한다. 긴 기간은 장기 집계가 준비된 경우에만 제공하고 미준비 상태를 원본 90일로 몰래 축소하지 않는다.
- 대시보드 상단 필터는 기간·채널로 제한한다. OS·기기·시험·과목·처리 결과는 기존 상세 탭에서 분석한다. 비교 근거를 복잡하게 만들지 않으면서 PWA 구분을 쉽게 한다.
- 신규 확인 회원은 날짜만 지원한다. 채널 필터를 적용했을 때 전체 신규 확인 수를 채널별 신규 회원처럼 보여 주지 않고 해당 카드만 미지원으로 표시한다.
- 상세 이동은 해당 지표가 지원하는 기간·채널만 전달한다. 90일을 넘는 기간의 원본 상세 이동에는 실제 가용 기간을 명시하고 그 범위로 이동한다. 원래 1년 지표를 최근 90일로 재해석하지 않는다. 활성 회원처럼 다른 모수의 상세 화면에는 카드 정의를 함께 안내한다.
- 최초 진입·기간 변경·수동 새로고침에 조회한다. 자동 폴링은 일차 범위에서 제외한다. 개인 피드 조회가 주기적으로 감사·부하를 늘리지 않게 한다.
- 부분 실패를 전부 0으로 만들지 않는다. 일반 실패는 집계 영역·피드 영역을 독립적으로 표시하며 이전 결과 유지 여부는 아래 오류 분류를 따른다. 다른 필터·계정·인가 세대의 자료는 섞지 않는다.
- 메모리 외 개인 자료 캐시, localStorage 저장, 공개 캐시, 정적 HTML 사전 생성을 사용하지 않는다. 기존 계정 전환·요청 취소 처리에 **같은 계정의 인가 거절 뒤 자료 제거와 응답 차단**을 추가하는 설계다. 공유 인가 세대·typed 오류는 기존 승인된 통계 화면에 구현했으며 아래 인수 기준으로 검증한다.

### 오류 분류와 이전 자료 처리

| 상황 | 표시·자료 유지 기준 |
|---|---|
| 네트워크 단절·시간 초과·일시 서버 5xx | 같은 관리자 계정·필터·인가 세대의 이전 성공값만 실제 기준 시각과 `이전 조회 / 갱신 실패`로 유지 가능. 성공한 다른 영역은 유지 |
| 현재 인가 세대 요청에서 HTTP 401 또는 403 | 모든 관리자 통계 탭·집계·피드·회원 목록·활동·조회 이력과 그 메모리 결과를 즉시 제거. 선택 회원·검색어·페이지 커서도 초기화하고 추가 조회 중단 |
| 로그아웃·계정 변경 | 이전 계정의 관리자 자료와 선택/조회 상태를 즉시 제거 |
| 잘못된 필터 등 400, 그 밖의 확정 요청 오류 | 실패한 조회 영역을 비우고 수정 안내. 이전 자료를 해당 요청의 결과처럼 유지하지 않음 |
| 응답 형식 오류·분류 불가 오류 | 실패 영역 오류로 표시하고 이전 자료 유지 대상에서 제외. 안전 코드 없이 권한 상태를 추측하지 않음 |
| 의도한 요청 취소·이전 계정/인가 세대의 늦은 응답 | 자료와 오류 상태에 반영하지 않음 |

401은 기존 인증 상태의 세션 재확인, 403은 기존 관리자 라우트의 접근 거절 안내로 연결한다. 해당 거절은 피드/집계의 일반 부분 실패로 격리하지 않고 같은 관리자 통계 화면 전체에 전달한다. 서버가 권한을 거절한 사실을 새로운 조회에서 알게 된 시점의 처리이며, 자동 폴링이나 이미 전달된 자료의 소급 회수를 보장하는 설계는 아니다.

공유 조회 상태에 `authorization_generation`을 두고 로그아웃·계정 전환·401/403 때 증가시킨다. 이 상태는 관리자 통계 화면 범위에 두며 로그인/역할의 원본은 기존 `AuthContext`/`useAuth()`만 사용한다. 기존 인증 상태가 관리자 권한 없음으로 갱신되어도 같은 자료 제거·세대 증가를 적용한다. 진행 중인 관리자 통계 요청을 취소하고 각 응답의 계정·세대·조회 키를 확인한다. 같은 계정이라도 이전 세대의 성공 응답은 자료를 되살릴 수 없다. 필터를 바꾼 이전 요청의 401/403도 **현재 계정·인가 세대**이면 전체 거절에 반영한다. 재인증과 관리자 권한 확인이 모두 성공한 이후에만 새 세대에서 새로 조회하며 제거했던 캐시를 복원하지 않는다.

### 기간과 그래프 간격

빠른 기간은 KST 완료 일자를 기준으로 오늘 00:00를 배타적 종료 경계로 사용한다. 사용자 지정은 선택한 마지막 날짜 다음 날 KST 00:00가 종료 경계이며 현재일 포함이면 잠정 상태다. 6개월·1년은 180일/365일 고정 약칭이 아닌 달력 기준이며, 시작일 계산은 달/연도 이동 후 해당 월의 마지막 날짜로 보정한다. 일차 비교는 **선택 기간 바로 앞의 동일 일수**이고 상단에 두 날짜 범위와 일수를 항상 표시한다. `직전 기간 비교`를 켜거나 끌 수 있으며 다른 길이의 비교 기간을 임의로 섞지 않는다.

| 선택 | 기간 정의 | 기본 집계점 |
|---|---|---|
| 7일 | 종료 경계 직전 7개 완료 일자 | 일별 7점 |
| 30일 | 종료 경계 직전 30개 완료 일자 | 일별 30점 |
| 6개월 | 종료 경계 날짜에서 달력 6개월 이전부터 | 선택 시작일부터 7일씩, 마지막 구간은 남은 일수 |
| 1년 | 종료 경계 날짜에서 달력 1년 이전부터 | 아래 경계 배열로 정확히 12개 구간 |

예시 기준일 2026-10-04: 7일은 9/27–10/3, 30일은 9/4–10/3, 6개월은 4/4–10/3, 1년은 2025/10/4–2026/10/3이다. 윤년에는 1년이 366일일 수 있다.

1년 시작 경계를 `S`, 실제 종료 경계를 `E`로 두고 경계 배열을 `[S, shiftMonths(S,1), …, shiftMonths(S,11), E]`로 만든다. 각 월 이동은 **원래 S의 날짜**를 기준으로 대상 월 말일에 보정하며 앞서 보정한 경계를 다시 한 달씩 이동하지 않는다. 인접 경계 쌍 12개로 집계하며 `S+12개월`을 추정 종료점으로 사용하거나 남은 하루를 13번째 구간으로 추가하지 않는다. 모든 경계가 증가하고 첫 경계=S·마지막 경계=E·빈 구간/중복/누락 없음이 조건이다. 예: `E=2024-02-29`, `S=2023-02-28`이면 마지막 구간은 `[2024-01-28, 2024-02-29)`의 32일이다. 이 경우도 일평균으로 표시하여 다른 월 구간과 합계 길이 차이를 혼동하지 않는다.

이전 곡선은 현재 구간의 시작/끝 일자 오프셋을 이전 기간에 적용해 **동일 일수의 대응 구간**으로 집계한다. 월간 대응 구간은 이전 달의 정확한 달력 월과 일치하지 않을 수 있으므로 두 실제 날짜 범위를 표시한다. 첫/마지막이나 월별 구간 길이가 달라지면 툴팁에 일수를 표시하고 길이가 다른 인접 구간의 건수만으로 주요 변화를 판정하지 않는다. 이전 기간 비교는 각 대응 구간 길이가 같고, 주요 변화는 선택 전체와 동일 길이 이전 전체로 계산한다.

곡선의 X축은 실제 구간의 중앙 날짜를 사용한다. Y축과 범례에는 `일평균 … (명/일·세션/일·회/일)`을 표시한다. 툴팁·접근 가능한 표에는 현재/이전의 실제 날짜 범위, 전체/가용 완료 일수, 일평균, 해당 구간 고유 회원·세션/채점 총수를 별도 항목으로 제공한다. 범위 변경 시 카드·기능·PWA·비교·주요 변화도 같은 범위로 재조회한다. 오늘 잠정 현황은 별도 범위를 유지한다.

### 장기 자료와 보존 설계

원본 조회는 90일, 회원 활동일 조회는 180일을 기준으로 한다. **1년과 직전 1년** 비교를 위해 대시보드의 장기 사실 자료 조회 범위는 **25개월**로 정했다. 완료 날짜의 원자 발행·실제 회원/세션 DISTINCT 집계와 해당 조회 범위를 로컬 코드·마이그레이션에 구현했으며 운영에도 적용했다. 25개월은 논리 조회 범위로, 물리 보존·삭제 자동화나 예약 발행은 별도 운영 결정과 적용이 필요하다. 상세 구현은 [구현 문서](admin-dashboard-implementation.md)를 따른다.

- 일별 숫자만 보관하면 연간 고유 회원·세션·실행 수를 복원할 수 없다. 장기 최소 자료에는 KST 일자, 실제 `user_id`(비로그인은 null), `session_id`, 실행 채널, 기능/허용 행동 종류, 채점 행동의 `grading_run_id`, 해당 셀의 중복 제거된 행동 횟수와 지표 버전을 유지하는 **집계용 사실 자료**를 제안한다. 세부 키는 구현 시 원격 상태와 부하를 확인해 확정한다.
- 실제 회원 ID를 가명·해시로 대체하지 않는다. 이름/이메일·답안·점수·본문·이벤트별 상세 속성은 장기 집계에 복제하지 않는다. 회원 정보는 기존 권한 경계에서 현재 계정과 연결한다. 익명은 세션 단위이며 장기 개인 식별자를 새로 만들지 않는다.
- 기간 DISTINCT와 채널 교집합은 사실 자료의 실제 ID로 다시 계산한다. 기간별 행동 횟수는 중복 제거가 끝난 가산 셀만 합산한다. 일별/주별/월별 회원 숫자의 합 또는 근사 고유 수로 정확한 카드를 대체하지 않는다.
- 장기 자료는 기존 원본으로 동일 버전의 일별 구간을 다시 만드는 방식으로 발행한다. 고유 구간 키·발행 세대·가용 범위·확인된 수집 공백·수정 시각을 유지하고 재실행은 기존 구간을 원자적으로 교체한다. 원본과 집계의 경계에서 중복 합산하지 않는다. 확인된 지연 자료는 해당 구간을 재집계한다.
- 상세 원본의 향후 삭제 정책을 적용하기 전에 집계 발행·수량/고유 수 검증이 성공해야 한다. 실패한 날짜를 0으로 발행하거나 원본부터 삭제하지 않는다. 스케줄러 도구·주기·권한은 구현 단계에서 확인하며 지금 Cron·자동 삭제를 만들지 않는다.
- 25개월은 회원 ID가 있는 장기 사실 자료와 그 가용 상태의 보존 제안이다. 상세 행동 타임라인까지 25개월로 늘리는 의미는 아니다. 탈퇴/관리자·테스트 계정 제외 변경·지표 버전 변경에 따른 재집계 가능 범위와 기록 처리도 운영 적용 전에 확정한다. 원본이 없으면 새 정의로 과거를 복원했다고 주장하지 않는다.
- 과거 1년 기록이 없는 첫 활성화에서는 모든 날짜가 완료·가용한 집계 구간만 곡선을 그리고, 일부 날짜가 빠진 구간의 평균과 이전 1년 비교는 미가용이다. 현재 부분 기간의 카드에는 실제 가용 범위를 표시하고 연간 전체 수치처럼 표현하지 않는다.
- 입력→결과 관측률·과목별 저장 시도 등 세밀한 흐름은 현재 90일 원본 기반이다. 장기 기간에서 같은 정확도를 지원하는 별도 자료가 준비되지 않으면 해당 블록은 `장기 기간 미지원`으로 두고 최근 90일 상세로 연결한다. 이용 추이·기능·PWA 그래프는 장기 사실 자료로 제공한다.

## 8. 서비스와 API 확장안

아래는 **신규 제안 계약**이며 현재 운영 또는 로컬 API가 제공하는 것으로 가정하지 않는다.

| API 제안 | 책임 | 반환 항목 |
|---|---|---|
| `GET /admin-analytics/dashboard?start=...&end=...&channel=...&compare=previous\|none` | 최대 1년, 동일 DB 스냅샷으로 기간·이전 기간·오늘 집계 | 카드·일/주/월 구간 현재/이전·기능 변화·지원되는 전환 분자/분모·PWA·주요 변화·수집 상태 |
| `GET /admin-analytics/activity-feed?start=...&end=...&channel=...` | 기간 내 회원 행동 최근 20개와 조회 감사 | 실제 계정 정보·허용 행동·대상·시각·채널·반환 대상 UUID 감사 |

집계에는 기존 조회 API·SQL의 지표 정의와 필터 판정을 재사용한다. 프론트가 7개 탭 API를 모두 호출하거나 회원 목록 전체를 순회하지 않는다. 현재 비교 응답은 핵심 카드만 있고 기능별 이전 값·이전 일별·전환 비교·최근 전체 회원 피드는 없으므로 이 부분을 추가해야 한다. 신규 확인 회원·PWA 카드 비교도 같은 기준 시각으로 포함한다.

집계 계약에 다음을 포함한다.

- `metric_version`, `dashboard_policy_version=2`, `snapshot_at`, `generated_at`, KST 분석/비교 날짜·일수·적용 필터, `bucket_unit=day|week|month`, 구간별 시작/배타적 끝 경계와 대응 비교 경계.
- 블록/지표별 `coverage_status`, `support_status`, `comparison_status`, `reason_code`. 가용 여부와 지원 여부는 별개다.
- 카드: 기간 전체 현재/이전 값·단위·절대 변화·증감률 또는 %p·분자/분모. 비교 꺼짐은 별도 상태로 표시한다. 일평균 시계열을 기간 고유 수 필드에 넣지 않는다.
- 곡선의 각 구간: `calendar_days`, `available_complete_days`, `coverage_status`, `series_value`(반올림 전 일평균 또는 null), `series_unit=members_per_day|sessions_per_day|runs_per_day` 등 지표별 일평균 단위, `daily_count_sum`(완전 가용 구간만), `bucket_total`(구간 DISTINCT/정확한 총수)와 그 가용 상태. 부분 구간의 관측분은 별도 `observed_total`과 상태로 반환하고 완전 값 필드와 섞지 않는다. 현재/이전 대응 구간의 일수는 같아야 한다.
- 주요 변화: 고정 지표 키·범주·현재/이전 근거·변화·`selection_priority`·`rank_score`·선정 여부·안내 유형·상세 탭 키. 4장의 계산을 서버에서 실행하며 프론트가 임의로 순위를 다시 만들지 않는다. 임의 HTML·외부 이동 URL을 반환하지 않는다.
- 기능별 `view_sessions`, `action_sessions`, `action_members`, `actions`와 각각의 이전 값. PWA는 전체와 채널별 DISTINCT 자료를 제공한다.
- 관측 자료가 없으면 `null + unavailable`, 완전 가용한 날짜에 행이 없으면 0이다. 오늘은 비활성/미개시를 구분한 잠정값이다.

집계는 한 SQL 호출의 일관된 읽기 스냅샷과 기준 시각을 사용한다. 늦게 도착한 자료와 관찰 종료 판정으로 과거 값이 후속 조회에서 달라질 수 있음을 정의한다. `snapshot_at`은 해당 조회의 기준이고 마지막 이벤트 시각·모든 사용자 자료의 신선도를 보장하지 않는다. 피드는 별도 조회 시각을 표시하며 집계와 정확히 같은 순간이라고 주장하지 않는다.

기존 Edge Function 인증 → 실제 JWT/관리자 역할 검사 → service-role 전용 RPC → SQL 실제 관리자 재검사를 유지한다. 브라우저가 관리자 ID를 지정하지 않는다. 피드 감사 쓰기 실패는 개인 자료 응답 실패로 처리한다. `Cache-Control: no-store`, 한국어 안전 오류·민감 정보 없는 로그를 유지한다.

조회 API/클라이언트 오류 계약은 `AdminAnalyticsError { code, status: number|null, retryable }`로 제안한다. HTTP 상태는 실제 응답에서 보존하며 401/403은 코드와 무관하게 전체 거절로 판정한다. 네트워크/시간 초과는 안전한 코드와 `status=null`, 재시도 가능한 5xx는 `retryable=true`, 확정 요청 오류·형식 오류는 false다. 상태·코드·재시도 정책의 허용 목록으로 분류하고 한국어 문구·원본 DB 오류 문자열을 비교하지 않는다. 권한 거절 판정은 다른 오류 처리보다 우선한다. 재시도 가능 표시는 수동 새로고침 허용을 뜻하며 자동 폴링/무제한 재시도를 추가하지 않는다. 기존 탭 API에도 같은 오류 분류와 공유 인가 세대가 필요하다.

새 이벤트 수집이나 새로운 분석 플랫폼은 필요하지 않다. 90일 이내 기본 집계는 준비된 private 이벤트·세션 상태·Auth·수집 설정/공백을 사용한다. **6개월·1년에는 위 장기 사실 자료·가용 구간 발행 저장 구조가 추가로 필요**하다. 모두 비노출 private·RLS·클라이언트 권한 없음·service-role 전용 검증된 읽기/발행 경계로 설계한다. 최근 피드의 다중 대상 감사도 기존 감사 객체 확장이 필요하며 구현 전 실제 스키마·권한·마이그레이션 이력을 다시 확인한다. 운영에 적용된 객체로 취급하지 않는다.

## 9. 구현 순서와 검증

1. 문서·분리된 미리보기로 화면 범위를 검토하고 실제 UI 적용 승인을 받는다.
2. 기존 지표 재사용과 누락 집계(행동 세션/회원, 이전 추이/기능/전환, 신규 확인·PWA 비교, 수집 상태)의 API·합성 SQL 검증을 추가한다.
   6개월·1년 지원에는 장기 사실 자료의 발행·25개월 보존 제안·기간 DISTINCT·비교 가용 범위 검증을 포함한다. 원본 90일 조회 제한을 단순히 풀어서 대체하지 않는다.
3. 최신 회원 피드의 제한 조회·실제 회원 연결·다중 대상 감사·권한 회수·감사 실패 차단을 검증한다.
4. 개요 화면에 적용하고 기존 상세 탭으로 기간/채널/회원 상태를 전달한다. 일반 사용자 화면·수집 방식은 유지한다.
5. 모의 Supabase E2E와 `npm run check`를 수행한다. 운영 DB 적용·함수 배포·수집 활성화·push는 별도 명시적 요청과 기존 운영 적용 절차를 따른다.

인수 기준:

- 조회 후 카드·변화·그래프·상세 이동이 같은 기간/정의/필터를 사용한다.
- 7일/30일/6개월/1년 및 윤년·월말에서 시작/종료·월간 구간·동일 일수 비교가 일치한다. 1년은 항상 12개 구간이며 `E=2024-02-29`, 2/28·30/31일·윤년 전후에도 실제 E를 마지막 경계로 사용한다. 주/월 고유 수와 기간 전체 고유 수를 일별 합산으로 계산하지 않는다.
- 일정한 일별 회원·세션·채점 수는 6개월의 마지막 1일/1년의 다른 월 길이 때문에 급감하지 않는다. 하루 가용 0건은 분모에 포함하고 하루 미가용은 평균 null·선 단절이다. 같은 회원/자정 초과 세션의 일평균과 기간 DISTINCT가 다를 수 있음을 확인한다.
- 곡선이 실제 점을 통과하고 구간 누락을 연결하지 않으며 음수/새 극값으로 과장하지 않는다. PC·모바일 기간 전환, 비교 켜기/끄기, 구간 날짜/값 표시를 검증한다.
- 장기 발행 재실행/지연 재집계/원본 경계에서 중복이 없고 집계 실패·가용 자료 미성숙은 0 또는 전체 완료로 보이지 않는다. 긴 기간에서 세밀한 흐름/최근 피드의 실제 가용 범위를 표시한다.
- 자정 초과 세션·두 과목 채점·중복 이벤트에서 DISTINCT가 유지된다.
- 이전 0건·현재 0건·수집 개시/중단·90일 경계·현재일·미지원 채널에서 잘못된 증감/0/정상 표시가 없다.
- 실제 행동 집계에 페이지뷰·백그라운드 조회·상태 보고가 섞이지 않는다. 기능별 이전에만 있던 행도 누락하지 않고 감소로 표시한다.
- 비율 분모가 0·소표본·진행/유예/미확정이면 확정 전환/주요 변화로 과장하지 않는다.
- 회원·기능·PWA 증가와 `72/100 → 40/100`이 동시에 있으면 관측률 감소가 첫 번째다. 분모 49/50·변화 -2.9/-3%p, 건수 큰 값 19/20·절대 변화 9/10·증감률 19.9/20%, 이전 0, 정렬 동률을 경계 검증한다. 범주 최대 1개·전체 최대 3개가 유지되고 반올림 때문에 후보가 달라지지 않는다.
- PWA/브라우저 교집합 회원은 전체 한 명이고, 기타·미확인 세션은 비중 분모에서 사라지지 않는다.
- 피드 최대 20개·실제 대상 감사·이름 없는 계정·HTML 텍스트 표시·인가 실패·계정 전환·늦은 응답을 검사한다. URL/공개 캐시에 개인 정보가 남지 않는다.
- 회원 선택 목록은 최근 피드에 없는 회원도 제공한다. 선택 후 상세의 실제 기간/채널을 유지하고 전체 대시보드 집계는 바뀌지 않는다. 이름 없는 계정·선택 해제·페이지 탐색·공통 권한 거절 제거를 회원 선택 설계 기준으로 검증한다.
- 일시 피드 실패 시 정상 집계는 남고, 일시 집계 실패 시 이전 시각을 숨긴 최신 자료처럼 보이지 않는다. 503/네트워크의 이전 자료 유지는 같은 계정·필터·인가 세대에 한정한다.
- 목록/피드 조회 성공 뒤 다음 페이지·다른 블록에서 401/403을 받으면 모든 관리자 자료·회원 선택·검색어·커서가 제거된다. 같은 계정의 취소 불가한 늦은 성공도 이전 인가 세대이면 복원되지 않는다. 이전 계정의 늦은 거절은 새 계정 상태를 훼손하지 않는다. 새 권한 확인 후에도 이전 캐시를 되살리지 않는다.
- 데스크톱/모바일에서 수치·비교 기간·자료 상태를 읽을 수 있고 표/그래프 접근성을 제공한다.

## 10. 후속 판단

일차 범위만으로 최근 변화와 개별 이용 확인을 달성한다. D7 재방문 요약, 배포/홍보 시점 표시, 오늘의 같은 시각 대비 비교는 자료 성숙·필터·시간 절단 기준을 추가 검증한 뒤 필요한 경우 확장한다. 현 단계에서 자동 알림·예약 보고서·실시간 접속자·회원 이용 점수·개인 순위·설치 보유 추정은 추가하지 않는다.

이전 미리보기 작성 때 예시 HTML은 외부 요청을 차단한 Playwright로 1280px/390px에서 4개 기간·3개 지표·비교 켜기/끄기 **48가지 조합**을 확인했다. 당시의 기간 전환·스크립트·화면 검증 기록이며, 이번 일평균·윤년 경계·선정·권한 오류 기준을 통과했다는 뜻은 아니다. 최신 개발 미리보기와 코드 검증은 별도 [확장 구현 문서](admin-dashboard-implementation.md)를 따른다. 예시 HTML도 실제 적용 승인 전에 새 기준으로 수정·재검증한다.

이번 반영은 문서의 계산·정렬·오류 기준을 대조하고 합성 자료로 일평균·기간 경계·선정 경계값을 확인했다. 1999~2030년의 **11,688개 종료 날짜**에서 1년의 12구간·365/366일·동일 일수 비교·경계 누락/중복 없음을 검사했다. 6개월 마지막 7일/1일의 일정한 일평균, 가용 0건/미가용 날짜, 후보의 20건·10건·20%·분모 50·3%p 경계와 감소 우선·범주 중복·고정 키 동률을 확인했다. 관련 문서 6개의 로컬 링크 43개·형식과 `git diff --check`도 통과했다. 이는 설계 계산의 확인이며 앱의 구현·권한 처리 검증은 아니다. 앱 코드가 바뀌지 않아 전체 빌드/서버 쓰기 테스트는 수행하지 않았다. 문서 단위 커밋을 권장하며, 문서만 포함해도 main push는 실서비스 배포를 유발하므로 별도 요청 전 실행하지 않는다.
