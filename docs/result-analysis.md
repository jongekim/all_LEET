# 결과 화면의 분야별 분석·문항 정답률

사용자가 승인한 `output/previews/field-analysis-preview.html`의 UI를 실제 결과 화면에 반영했다. 성적 요약 카드와 기존 답안 수정·메모 동선을 유지하며 분석 영역만 줄인다.

## 분야별 분석

- 기본 화면에서는 기존 순서로 모든 분야의 이름, 정답 개수/전체 문항 수, 개인 정답 비율과 막대를 표시한다. `내 답안 기준`으로 공개 문항 통계와 구분한다.
- 한 번에 한 분야만 펼친다. 상세에는 정답·오답·미응답 개수와 상태 기호를 붙인 문항 버튼이 있다. 같은 행을 다시 누르면 닫힌다.
- 제목 우측에서 분석 전체를 접고 펼친다. 다시 펼칠 때는 요약만 보이며, 두 과목의 펼침 상태는 독립적이다. 결과를 새로 열면 기본 상태로 시작한다.
- 문항 선택은 URL 이동 없이 같은 과목의 답안표 문항으로 스크롤하고 키보드 포커스를 옮긴 뒤 3.5초 동안 강조한다. 접근성 안내와 모션 감소 설정을 지원한다. 클릭만으로 답안·메모를 수정하거나 정답을 노출하지 않는다.
- 모바일은 분야명·수치를 첫 줄, 막대를 둘째 줄에 배치한다. 조작 영역은 최소 44px이고, 정오답을 색상과 기호로 함께 구분한다.
- 초안 편집 중 분석은 마지막 반영 결과를 유지한다. `수정 반영`의 성공 결과로 `GradingResult`가 교체되면 요약 수치와 열린 문항 상태도 함께 바뀐다. 분석 조작과 정답률 전환은 답안 편집을 재마운트하지 않는다.

`FieldAnalysis`는 기존 `fieldAnalysis`, `userAnswers`, `correctAnswers`만 사용한다. 과거 기록에 답안·정답 자료가 없으면 문항을 `결과 없음`으로 표시하고 정오답 합계를 추정하지 않는다. 0문항 분야의 비율은 `—`이며 문항·분류 자료가 없으면 기존 안내를 제공한다.

## 문항별 공개 정답률 설정

`ResultRateVisibilityProvider`를 `ResultPage`에만 적용한다. 기본값은 숨김이며 `allleet:result:question-rate-visible:v1`에 boolean 문자열을 저장한다. 로그인·비로그인 공통인 해당 브라우저의 표시 선호이고 개인 성적 데이터는 저장하지 않는다.

두 과목의 스위치를 동기화하고 다음 채점·새로고침·다른 탭에도 선택을 반영한다. 브라우저 저장소가 차단되면 현재 화면의 선택만 유지한다. 숨길 때 정답률 버튼과 안내·모달을 DOM에서 제거하며, 개인 점수와 분야별 비율은 유지한다. 기출 정답표는 이 Provider 바깥이므로 기존 표시·조회·사전 HTML 동작을 유지한다.

`QuestionStatistics`는 기존 `useQuestionStatistics(selection, compatible && visible)`을 사용한다. 표시를 켜면 기존 공개 SELECT·양 과목 공유 캐시·정답 버전 호환 검사·조회 오류/재시도가 적용된다. 숨김 상태에서는 해당 결과의 공개 통계 조회를 시작하지 않는다. 진행 중인 조회 결과도 숨김 상태에 노출하지 않는다.

## 데이터·운영 경계

이 UI 변경은 테이블·정책·스키마·Edge Function·기존 이력/메모 API를 수정하지 않는다. 정답률 선호는 DB에 저장하지 않고 분야 분석을 별도 저장·재집계하지 않는다.

작업 트리에 함께 있는 답안 수정 기능은 별도 [DB/API 적용 순서](answer-edit.md)가 필요하다. 이 UI 변경에 DB 변경이 없다는 사실이 답안 수정 migration과 Edge Function의 운영 적용을 대체하지 않는다. 함께 릴리스하면 DB → 이력 Edge → 웹 순서를 지키고 명시적 배포 요청 후 진행한다.

## 검증 방법

```sh
npm run test -- src/components/FieldAnalysis.test.tsx src/components/QuestionStatistics.test.tsx
npm run test:e2e -- e2e/field-analysis.spec.ts e2e/question-statistics.spec.ts e2e/answer-edit.spec.ts
npm run check
```

단위 검사에서는 한 분야 펼침·전체 접기·정오답/미응답·누락된 과거 데이터·재계산과 설정 공유·복구·저장소 차단을 확인한다. Playwright는 모든 Supabase 요청을 모의 응답으로 대체한다. PC/모바일에서 요약·문항 이동·포커스·초안 유지·수정 반영 후 갱신·회독/시각/메모/다른 과목 보존·정답률 조회 합치기·분포 모달·설정 기억·기출 정답표·가로 넘침·런타임 오류를 확인한다. 운영 연결 브라우저에서 저장을 실행하지 않는다.

스크린샷은 `output/previews/field-analysis-implemented-*.png`와 `field-analysis-implemented-expanded-*.png`에 생성한다. 실제 사용자 데이터·인증 없이 모의 결과로 촬영한다. 전체 품질 게이트의 빌드 단계는 기존 공개 통계를 읽기 전용으로 조회하며 운영 데이터는 변경하지 않는다.

## 2026-10-09 검증 기록

사용자가 결과 화면에서 분야를 선택해 기존 개인 채점 결과를 확인하고, 문항 선택으로 같은 과목의 답안표에 이동하며, 공개 정답률을 켜고 답안을 반영한 뒤 갱신된 분석을 확인하는 흐름을 검증했다.

| 경계 | 확인한 근거 |
| --- | --- |
| 결과 → 분야 요약·상세 | 1280/390/320px에서 요약·한 분야 펼침·전체 접기·정답/오답/미응답 및 가로 넘침 검사 통과. 실제 스크린샷 직접 확인 |
| 문항 선택 → 답안표 | 양 과목에서 같은 번호의 문항을 구분하여 포커스·스크롤·강조 처리. 수정 중 초안 유지 |
| 정답률 설정 → 공개 조회 | 기본 숨김에서 조회 0회, 표시 후 양 과목 공유 조회 1회. 70개 버튼·모달·설정 복구 및 기출 정답표 유지 |
| 수정 응답 → 분석 갱신 | 모의 PUT 1회 후 24→25 정답, 사회 8/12→9/12 및 문항 상태 갱신. 시각·회독·묶음·메모·다른 과목 보존 |
| 기존 학년도 | 2027학년도 두 과목의 기존 분야별 정답 개수를 새 요약 행에서도 동일하게 검증 |

최종 `npm run check` 종료 코드 0. lint 오류 0개(기존 경고 52개), 타입 검사, 단위 31파일/280개, SQL·Edge 회귀, 일반 화면 94개, 푸시 화면 13개, 공개 HTML 10개 검사 및 프로덕션 빌드가 통과했다. 빌드는 공개 76조합/발행본 1을 읽고 83개 HTML과 `build/index.html`·assets를 재생성했다. `git diff --check`도 통과했다. 운영 DB·Edge Function 적용, 커밋·push·배포는 실행하지 않았다.

## v1.11.0 릴리스

이후 사용자의 명시적 배포 요청으로 서비스 버전을 v1.11.0으로 올리고 전체 품질 게이트를 다시 통과했다. 답안 수정 migration과 이력 Edge v21을 먼저 운영에 적용·검증한 뒤 웹을 릴리스한다. [DB·Edge·웹 적용 순서와 복구](answer-edit-rollout.md)를 참고한다. PC·모바일 운영 화면 확인은 합성 결과를 브라우저에만 주입하고 모든 비조회 요청을 차단하여 제출·저장 없이 검증한다.
