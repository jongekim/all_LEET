# 네이버앱 알림·설치 안내 진단

이 문서는 v1.12.1 네이버앱 제외의 진단·릴리스 기록이다. 후속 자동 팝업의 허용 이력·권한·지원 조건은 [현재 표시 규칙](push-consent-rules.md)으로 변경했다. 네이버앱 제외와 PWA 설치 버튼의 별도 흐름은 유지한다.

2026-10-13 사용자 제공 iPhone 네이버앱 스크린샷을 기준으로 확인했다. 스크린샷에는 앱의 설치 필요 알림 팝업이 있으며 런타임 오류 메시지는 없다. 해당 화면만으로 로그인·네트워크 장애까지 단정하지 않는다.

## 확인한 원인

- `usePushSubscription`은 iOS 및 standalone 여부로 `needsInstall`을 정한다. 네이버앱에서도 설치 필요 분기를 사용한다.
- `PushConsent`는 설치 필요 상태에 공유 메뉴에서 바로 홈 화면에 추가하도록 안내한다. 현재 접속한 앱과 외부 브라우저를 구분하지 않는다.
- `PWAInstallButton`도 기기만 구분하여 네이버앱에서 Safari의 공유 버튼 위치를 안내한다.
- 기존 테스트에는 네이버앱 식별 문자열을 사용한 검사가 없어 이 차이를 검출하지 못했다.

[네이버 공식 로그인 가이드](https://developers.naver.com/docs/login/devguide/devguide.md)의 iPhone User-Agent 예제를 기존 조건에 대입하면 `ios=true`, `needsInstall=true`가 되어 스크린샷과 같은 제목을 선택한다. [네이버 오픈메인 가이드](https://developers.naver.com/docs/openmain/)는 공백을 포함한 `NAVER (inapp; ...)`와 Android의 `NAVER (higgs; ...)` 형식도 명시한다. Safari 토큰이 함께 있어도 네이버앱 표식을 우선 구분해야 한다.

[Apple/WebKit 웹 푸시 설명](https://webkit.org/blog/13878/)은 iOS/iPadOS의 홈 화면 웹앱에서 웹 푸시를 지원한다고 설명한다. 외부 브라우저에서 홈 화면 추가를 안내하고 설치된 앱에서 실제 권한을 요청하는 경로가 필요하다. 네이버앱의 모든 버전에서 홈 화면 추가가 불가능하다고 단정하거나 설치 여부를 UA만으로 판단하지 않는다.

## 적용한 수정

사용자가 안드로이드 네이버앱에서도 구독이 되지 않음을 확인하고, 네이버앱에서는 해당 팝업을 표시하지 않도록 명시적으로 요청했다. `src/utils/naverBrowser.ts`는 공식 네이버앱의 `inapp`/`higgs` 표식을 감지한다. 일반 Safari·Chrome·Whale·검색봇은 해당하지 않는다.

`PushConsent`가 네이버앱에서는 알림 hook과 팝업 본문을 마운트하지 않는다. iPhone·Android 모두 서비스 진입·재방문·포커스 복귀에도 자동 팝업을 띄우지 않으며, 이 팝업에서 알림 권한·등록 상태 확인 요청을 발생시키지 않는다. 이 제외를 7일 유예 저장으로 처리하지 않아 다른 브라우저의 정상 안내와 기존 유예를 바꾸지 않는다. hook을 사용하는 내부 컴포넌트를 분리하여 조건부 hook 호출도 피한다.

기존 알림 문구·디자인·PWA 설치 버튼·Safari의 설치 안내는 유지한다. 네이버앱 UA가 없는 일반 브라우저와 홈 화면 웹앱에서는 기존 알림 흐름을 사용한다. 설치 안내 문구를 바꾸는 초기 분리 미리보기는 최종 구현에 사용하지 않았다.

## 검증

- `naverBrowser.test.ts`: 공식 iPhone/Android 표식·공백·대소문자 및 일반 브라우저/Whale/검색봇 오인 방지.
- `PushConsent.test.tsx`: 네이버앱에서 hook 미실행·시간 경과·포커스 복귀·재마운트 시 팝업 없음·유예 키 미기록, 일반 Safari의 기존 설치 안내.
- `e2e-push/push.spec.ts`: Chromium에서 iPhone 네이버앱 및 Android `inapp`/`higgs` UA를 주입해 홈·커뮤니티 직접 진입·새로고침 후 10초 경과에도 팝업이 없고 권한/푸시 API 요청이 없는지 검사한다. API가 있는 모의 환경에서도 제외되므로 기능 지원 감지만으로 우연히 숨겨진 상태와 구분한다. 모든 Supabase 응답은 모의 처리한다.

실제 네이버앱 엔진·OS 메뉴·설치 완료·실제 알림 수신은 이 모의 검사 범위에 포함되지 않는다.

2026-10-13 전체 `npm run check` 통과: lint 오류 0개(기존 경고 52개), typecheck, 단위 검사 306개, 격리 SQL·Edge 검사, 푸시 화면 검사 16개, 기존 화면 검사 96개, 공개 HTML 검사 10개, 테스트/운영 공개 읽기 빌드. 네이버앱 조건의 모바일 스크린샷에서도 팝업이 없음을 확인했다. 운영 등록·발송은 실행하지 않았다. 해당 로컬 검증으로 갱신된 추적 빌드 파일은 작업 전 상태로 복원했다.

v1.12.1 버전 갱신 후 `npm run version:verify`와 동일 전체 품질 게이트를 다시 통과했다. 첫 릴리스 검사에서는 스크린샷/trace 기록의 ENOSPC로 5건이 실패했으며, npm 캐시 검증·여유 공간 회복 뒤 소스 변경 없이 전체 재실행을 통과했다. 최종 빌드는 운영 공개 통계 38묶음·발행본 1로 공개 HTML 83개를 생성했다. 이 릴리스에는 최종 운영 빌드의 추적 HTML·번들을 포함한다.

DB·RLS·인증·Edge Function 변경과 운영 등록·발송은 이 수정에 필요하지 않다. 사용자의 버전 관리부터 배포 요청에 따라 v1.12.1 PATCH 릴리스를 진행한다. 버전 변경 후 전체 품질 게이트를 재실행하고, 관련 수정과 최종 빌드만 커밋해 main push로 웹을 배포한다. 기존 Edge 배포 workflow의 대상 경로는 변경하지 않는다. 최종 커밋·Vercel 상태·공개 화면 확인은 작업 완료 기록에 남긴다.
