# 관리자 공통 회원 선택 목록 설계

작성일: 2026-10-04 KST. 상태: **API·공통 컴포넌트·분리 미리보기 로컬 구현 / 실제 앱 연결 완료 / 운영 적용은 [운영 기록](admin-analytics-rollout.md) 참조**.

사용자 요구: 운영자가 이름·이메일을 미리 몰라도 드롭다운 목록을 열어 어떤 회원이 있는지 확인하고 선택할 수 있어야 한다. 기존 검색은 유지하고 목록 탐색을 함께 제공한다. 실제 회원 UUID·현재 이름/이메일 연결은 유지한다.

관련 기준: [전체 통계 설계](admin-analytics-design.md), [PWA 설계](admin-pwa-analytics-design.md), [변화 대시보드](admin-dashboard-design.md). 아래는 공통 설계 계약이다. 로컬 구현·미리보기·검증 상태는 [확장 구현 문서](admin-dashboard-implementation.md)를 따른다. 이후 사용자 배포 요청에 따른 운영 수집·DB·함수·웹 적용 상태는 [운영 기록](admin-analytics-rollout.md)을 따른다.

## 1. 적용 범위와 현재 구현의 차이

현재 로컬 `MemberExplorer`는 검색 없이도 회원 표를 조회하며 `member-directory`는 50명씩 UUID 순 커서로 제공한다. 이용 속성 필터를 적용하면 그 조건에 활동이 있는 계정으로 후보가 좁혀진다. `AccessExplorer`는 관리자·대상 회원 UUID를 직접 입력한다. **기존 화면과 공통 선택기 준비본을 구분한다.** 공통 선택기는 승인된 회원 활동·PWA 개인 상세·감사 대상/관리자 필터에 연결했다.

공통 선택 UI는 관리자 기능에서 특정 사람을 지정하는 곳에 재사용한다. 기능별 조회 권한·목록 범위와 선택 후 동작은 각 서비스가 정하고, 전체 관리자 화면의 공통 전역 필터로 만들지는 않는다.

| 위치 | 목록과 선택 후 동작 |
|---|---|
| 회원 활동 | 일반 회원 목록에서 선택하면 선택 회원의 활동 조회. 기존 기간·채널·기능 필터 유지 |
| 회원/재방문·PWA의 회원 목록·상세 이동 | 같은 회원 선택 UI로 해당 회원 활동에 이동. 전체 코호트·채널 통계를 한 사람의 통계로 바꾸지 않음 |
| 대시보드 최근 회원 활동 | `회원 선택` 진입에서 선택 후 같은 기간·채널의 회원 활동으로 이동. 전체 카드·곡선·주요 변화에는 회원 필터를 추가하지 않음 |
| 관리자 조회 이력: 대상 회원 | 현재 회원과 감사 기록에 남은 과거 대상 UUID에서 선택. `조회`를 누르면 기존 대상 회원 조건으로 이력 조회 |
| 관리자 조회 이력: 조회한 관리자 | 현재 관리자와 감사 기록의 과거 관리자 UUID에서 선택. 역할이 회수된 관리자도 과거 조회 이력의 필터 대상으로 탐색 가능 |
| 향후 회원을 지정하는 관리자 기능 | 동일 UI와 선택 값 계약을 재사용하되 해당 업무의 별도 권한·목록 범위 검증 |

공지 편집처럼 회원 지정이 필요 없는 화면에는 선택기를 추가하지 않는다. 익명 이용 기록의 세션 선택은 회원 선택과 별도로 유지한다.

## 2. 목록 표시와 조작

```text
회원 선택  [목록에서 선택하거나 이름·이메일 검색 ▾]
           ┌──────────────────────────────────────┐
           │ 이름·이메일·UUID 검색                 │
           │ 일반 회원 전체 · 가입 최신순          │
           │ 예시회원 A  member-a@example.com      │
           │ 가입 2026-10-03 · UUID 확인           │
           │ 예시회원 B  member-b@example.com      │
           │ 가입 2026-10-02 · UUID 확인           │
           │ …                                    │
           │ 1~50번째 회원       다음 50명         │
           └──────────────────────────────────────┘
선택 회원: 예시회원 A / member-a@example.com   [선택 해제]
```

위 이름·이메일은 설명용 가상 값이며 실제 기록을 가명으로 바꾸는 요구가 아니다.

- 검색어가 비어 있어도 목록을 열면 첫 페이지를 조회한다. 일반 회원 목록은 **가입일 내림차순, 동일 가입 시각이면 UUID 내림차순**으로 정렬한다. 첫 회원을 자동 선택하지 않는다.
- 항목에는 현재 이름·이메일·가입일을 표시한다. 이름/이메일이 없으면 각각 `이름 없음`/`이메일 없음`으로 표시하며 실제 UUID를 확인할 수 있게 한다. 동명이인은 이메일과 UUID로 구분한다. 표시 이름은 수정 가능한 텍스트이며 관리자 역할 판정에 쓰지 않는다.
- 이름·이메일은 대소문자 구분 없는 부분 검색, UUID는 완전 일치 검색을 사용한다. 공백 정리 후 최대 120자, 입력 완료 후 300ms 지연 조회를 제안한다. 한국어 IME 조합 중에는 조회하지 않는다. 검색어를 바꾸면 첫 페이지로 돌아가고 이전 검색 결과의 늦은 응답은 차단한다.
- 한 페이지는 최대 50명이다. 팝업 내부에서 목록을 스크롤하고 `다음 50명`/`이전`으로 탐색한다. 이전 페이지는 저장한 커서로 다시 조회한다. 검색 결과 전부를 자동으로 수집하지 않고 화면에는 현재 한 페이지의 옵션만 유지한다. 표시 순번은 탐색 위치이며 전체 회원 수를 추정하지 않는다.
- 선택 값은 이름이나 이메일이 아니라 **실제 `user_id`**다. 선택 회원은 현재 페이지 밖으로 이동하거나 검색어를 바꿔도 별도 표시한다. 다른 이름을 입력했다는 이유로 대상 회원을 바꾸지 않으며 다른 옵션 선택 또는 명시적 해제로만 바꾼다.
- 조회 이력의 기존 UUID 직접 입력은 고급 조회 경로로 유지한다. 직접 입력도 UUID 형식·기간·실제 관리자 권한을 서버에서 확인하며, 선택 목록에 없다는 이유로 가용한 과거 이력 조회 경로를 없애지 않는다.
- 활동 화면에서는 선택 직후 기존 회원 활동 조회 흐름을 사용한다. 조회 이력에서는 관리자·대상 회원을 고른 후 기존 `조회` 버튼으로 적용해 중간 선택마다 이력을 반복 요청하지 않는다.
- 조회 이력의 선택 해제는 해당 조건의 `전체`를 뜻한다. 회원 활동에서 해제하면 이전 회원의 활동을 지우고 선택 안내로 돌아간다. 해제 때문에 전체 회원 활동을 요청하지 않는다.
- 키보드로 열기·방향키 이동·Enter 선택·Esc 닫기와 포커스 복귀를 제공한다. 검색 입력/목록에 접근 가능한 이름, 펼침·선택 상태, 로딩/결과 상태를 제공한다. 모바일에서도 이메일/UUID 확인과 페이지 이동이 가능하게 한다. 구현 시 [WAI-ARIA Combobox 기준](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)에 맞춰 실제 포커스 흐름을 검증한다.

## 3. 회원 목록과 이용 통계의 모수 구분

일반 회원 선택기의 기본 목록은 **현재 등록된 일반 회원 전체**다. 기존 통계의 관리자/승인된 테스트 계정 제외 규칙은 유지하며 `일반 회원 전체` 표제로 범위를 안내한다. 가입만 하고 이용하지 않은 회원, 수집 시작 전 가입 회원, 선택 기간에 활동 없는 회원도 탐색할 수 있다. 기간·채널·시험 필터를 목록에 암묵적으로 적용하지 않는다.

개인 활동 조회에만 기존 기간·채널 등 지원하는 필터를 적용한다. 예를 들어 PWA 화면에서 브라우저만 사용한 회원도 선택할 수 있으며, 해당 기간 PWA 기록이 없으면 **관측된 PWA 활동 없음**으로 표시한다. 자료가 미가용이면 **조회할 자료 없음/미가용**으로 구분하고 회원 자체가 없다고 표시하지 않는다. 1년 대시보드에서 이동하는 상세 활동의 실제 조회 범위는 기존 90일 제한과 교집합 안내를 따른다.

조회 이력의 두 목록은 일반 회원 목록과 다른 목적의 범위다. `조회한 관리자`는 현재 관리자 역할 + 보존된 감사 기록의 요청자 UUID, `대상 회원`은 현재 일반 회원 + 보존된 감사 기록의 대상 회원 UUID를 중복 제거한다. 비로그인 대상 세션은 회원 옵션에 섞지 않는다. 현재 계정과 연결되지 않는 과거 UUID는 `계정 정보 없음`으로 표시하고 새 계정에 재귀속하지 않는다. 과거 관리자에는 현재 역할 확인 결과에 따라 `현재 관리자`/`현재 관리자 역할 없음`을 표시하며 선택 가능 여부와 실제 관리 권한을 혼동하지 않는다.

감사 목적의 목록은 계정 정보 유무와 무관하게 **UUID 오름차순**으로 제공하고 정렬을 안내한다. 계정 연결 정보가 사라졌다는 이유로 다른 정렬 그룹에 재등장하지 않게 한다. 감사 기록의 가용 범위를 목록 응답/안내에 표시하며 보존 기간 밖의 과거 관리자/대상을 모두 복원할 수 있다고 주장하지 않는다. 현재 역할과 이름을 과거 조회 당시 정보로 표시하지 않는다.

## 4. 공통 컴포넌트와 조회 서비스 제안

`AdminMemberPicker`를 공통 선택 UI의 후보 이름으로 둔다. 입력은 목록 목적, 선택 값, 선택 변경 콜백, 조회 서비스이며 화면별 hooks로 팝업·검색어·페이지·선택 상태를 유지한다. 전역 인증 상태는 기존 `AuthContext`/`useAuth()`만 사용한다. 통계 화면의 기존 `authorization_generation` 계약과 연결한다. 다른 관리자 기능에 재사용할 때는 그 업무의 인가/조회 경계에 연결한다.

선택 회원 참조 타입은 UUID·표시 정보 중심으로 `src/types/`의 공용 타입에 제안하고, 행동 합계가 있는 기존 `MemberSummary`와 구분한다. 선택 옵션에 행동 합계가 없다는 이유로 0을 채운 회원 요약을 만들지 않는다. 각 화면은 UUID로 필요한 개인 기록을 조회한다.

기존 회원 상세 표용 API는 기간 필터와 행동 합계를 제공하므로, 날짜와 수집 여부에 종속되지 않는 작은 선택 목록 계약을 별도로 제안한다. 새로운 Auth 데이터 복제 테이블이나 브라우저의 Auth 관리자 API 직접 호출은 필요하지 않다. Auth 스키마는 자동 생성 API에 노출되지 않으므로 현재 서버의 인가된 조회 경계를 유지한다. [Supabase 회원 데이터 접근 문서](https://supabase.com/docs/guides/auth/managing-user-data)

**아래는 신규 제안 API이며 현재 로컬/운영 API에 존재하지 않는다.**

| 계약 | 기준 |
|---|---|
| 요청 | `GET /admin-analytics/member-options?purpose=member_activity\|audit_target\|audit_actor&query=...&cursor=...` |
| 허용 범위 | 목적은 서버 허용 목록으로 검증. 각 요청에서 실제 JWT·현재 관리자 역할 및 SQL 인가 재검사 |
| 반환 | `items` 최대 50개: 실제 UUID·현재 이름/이메일·가입일·계정 정보 가용 상태, audit_actor의 현재 관리자 여부. `next_cursor`, 목록 목적·정렬 버전·조회 기준 시각. 감사 목적에는 감사 자료 가용 범위 |
| 페이지 | 일반 회원은 `(created_at desc, user_id desc)`, 감사 목적은 `user_id asc`. 커서는 목적·검색 조건·정렬 버전·조회 기준에 묶어 서버 검증. 감사 대상 집합의 같은 UUID는 먼저 중복 제거 |
| 신선도 | 조회 기준 이후 새 가입은 페이지 중간에 끼우지 않고 첫 페이지 새 조회 때 제공. 이후 탈퇴/역할/이름 변경은 현재 상태로 반영하며 과거 시점 계정 스냅샷으로 보장하지 않음 |
| 비용 | 이름/이메일 조회와 페이지 크기에 필요한 필드만 반환. 회원별 행동 합계·이력·활동 전수 조회 없음. 전체 회원 수 집계를 페이지마다 실행하지 않음 |
| 감사 | 각 실제 목록/검색/페이지 API 요청을 조회 감사와 같은 트랜잭션으로 기록. 목록 목적·검색 수행 여부/종류·반환 수·기준만 기록하고 이름/이메일 검색어는 복사하지 않음 |

검색 결과 목록 제공은 해당 회원들의 활동 상세를 읽었다는 기록으로 만들지 않는다. 옵션 선택으로 활동 API를 호출한 경우 그 상세 조회가 별도로 감사된다. 새 조회 종류 `member_options`와 목적 필드는 구현 전 기존 감사 객체의 허용 종류/필터 및 마이그레이션을 확인하여 추가한다. 이 문서는 허용 종류·SQL·스키마를 실제 변경하지 않는다.

현재 함수·권한·감사 저장이 준비되면 **행동 수집이 비활성이어도 계정 목록은 제공 가능**하도록 설계한다. API 미배포·인가 실패·감사 저장 실패를 정상 빈 목록으로 바꾸지 않는다. 운영 API/DB 구현 전에는 원격 스키마·권한·마이그레이션 이력을 다시 읽기 전용으로 확인한다.

## 5. 오류와 자료 제거

- 최초 로딩, 목록 전체 0명, 검색 결과 0명, 페이지 끝, 통신 실패, 인가 거절을 구분한다. `검색 결과 없음`을 서버 미연결 상태에 사용하지 않는다.
- 첫 페이지 실패에는 목록 오류·재시도 안내를 표시한다. 다음 페이지의 일시 통신 실패에는 같은 관리자·목적·검색 조건·인가 세대의 현재 페이지를 유지하고 페이지 이동 실패를 표시한다. 재시도는 같은 커서로 수행하고 옵션을 중복 추가하지 않는다.
- `AdminAnalyticsError`의 상태/안전 코드 기준을 재사용한다. 현재 계정/인가 세대의 401/403, 로그아웃·계정 변경에는 목록·검색어·선택 UUID/표시 정보·커서와 기존 통계 자료를 함께 지운다. 진행 요청 취소와 세대 검사로 늦은 목록/선택 회원 응답도 차단한다.
- 탭 간 전달은 필요한 실제 UUID만 메모리 navigation state로 전달한다. 검색어·목록·이메일·대상 UUID를 주소창 URL·localStorage·sessionStorage·공개 캐시에 저장하지 않는다. 관리자 응답은 `Cache-Control: no-store`다.
- 선택 직후에도 서버는 조회 대상과 요청 관리자를 구분해 재검증한다. 목록에 등장하거나 과거 관리자였다는 이유로 조회/수정 권한을 부여하지 않는다. 권한 부여·회원 변경·삭제는 이 선택 기능의 범위가 아니다.

## 6. 구현 순서와 인수 기준

1. 별도 목업에서 회원 활동·PWA 이동·조회 이력 두 선택기를 제시하고 실제 UI 적용 범위를 승인받는다. 기존 통계 7개 탭 승인을 이 새 상호작용 승인으로 확대 해석하지 않는다.
2. 현재 서버의 계정 조회·인가·감사 코드를 재사용해 제한된 선택 목록과 복합 커서 계약을 추가한다. 실제 DB 변경은 원격 상태 확인과 개발 범위 확정 후에만 진행한다.
3. 공통 선택 UI와 화면별 대상 지정 동작을 연결한다. 기존 검색 표·익명 세션 조회·전체 통계의 지표/모수는 유지한다.
4. 모의 API/E2E 및 적절한 품질 검증을 수행한다. 운영 연결 앱에서 실제 계정 조회·개인 조회 감사 쓰기·역할 변경을 시험하지 않는다.

인수 기준:

- 검색어 없이 열면 첫 50명과 다음 페이지 여부를 제공하며 첫 항목을 자동 선택하지 않는다. 활동 없는 회원과 수집 시작 전 가입 회원도 기본 목록에 있다.
- 같은 가입 시각·동명이인·같은 표시 이름/누락 이메일·현재 계정 없는 과거 UUID에서 UUID와 정렬/페이지 경계가 일치하고 같은 자료 상태에서 누락/중복이 없다. 새 가입·탈퇴·역할/이름 변경은 현재 조회 상태로 반영하며 과거 스냅샷을 보장하지 않는다. 검색 조건 변경은 첫 페이지로 돌아가고 계정 연결 정보 변화만으로 감사 UUID 정렬을 바꾸지 않는다.
- 0/1/50/51명, 마지막 페이지, 이전 페이지, 검색 후 첫 페이지 복귀, 120자 제한, 한국어 IME, 검색 응답 역전에서 목록·커서·선택이 혼동되지 않는다.
- 다른 페이지/검색어로 이동해도 명시적으로 바꾸기 전까지 선택한 회원은 유지된다. 해제하면 이전 회원 활동이 제거되며 전체 활동을 자동 조회하지 않는다.
- 회원 선택은 개인 활동/조회 이력 대상에만 적용되고 대시보드 카드·곡선·코호트의 전체 집계는 바뀌지 않는다. PWA 기록 0건과 기록 미가용을 구분한다.
- 과거 관리자의 역할 회수/계정 연결 불가 후에도 가용 감사 기록 필터로 찾을 수 있다. 과거 UUID를 현재 다른 회원에게 연결하지 않는다.
- 다음 페이지 503은 현재 페이지와 선택을 유지할 수 있지만 어느 현재 인가 세대 요청의 401/403도 선택기와 통계 전체 자료를 지운다. 늦은 성공으로 선택/목록이 복원되지 않는다.
- 조회 감사에 실제 요청자·선택 목록 목적·반환 수가 남고 검색어·계정 비밀정보는 없다. 목록 API 실패/미배포를 빈 회원 목록으로 보이지 않게 한다.
- 키보드·스크린리더·모바일에서 목록 열기, 검색, 페이지 이동, 같은 이름 구분, 명시적 선택/해제가 가능하다.

다음은 설계 당시 검증 기록이며 최신 로컬 코드/화면 검증은 [확장 구현 문서](admin-dashboard-implementation.md)를 따른다. 당시에는 현재 검색/목록·직접 UUID 입력·서버 커서/제외 계정 처리와 문서를 대조했다. 관련 문서 6개의 로컬 링크 42개·기본 형식과 `git diff --check`를 확인했다. 같은 가입 시각을 포함한 합성 회원 121명을 복합 커서로 50/50/21명씩 탐색하여 고정 자료에서 누락/중복 없음을 확인했다. 이 검증은 제안한 정렬/페이지 계산의 확인이며 실제 목록 API·공통 컴포넌트·목업은 아직 만들지 않았다. 앱/운영 동작 검증은 수행하지 않았다.
