# 관리자 공지 운영

관리자로 로그인하면 홈의 **관리자 페이지** 버튼이 표시된다. 버튼 → 관리자 홈(`/admin`) → **공지 관리**(`/admin/announcements`) → 공지의 **수정** 버튼 순으로 이동한다. 비로그인 사용자는 로그인 화면으로, 일반 사용자는 서비스 홈으로 이동한다. 기존 RLS도 공지 변경 권한을 확인한다.

목록과 편집 화면은 분리되어 있다. 편집 화면은 PC에서 내용·공개 설정을 2열로, 모바일에서는 1열로 표시한다. 배너 미리보기와 실제 노출 조건을 확인한 뒤 저장한다. 저장 실패 시 입력을 유지하며, 저장하지 않고 목록으로 돌아갈 때는 확인한다.

## 최초 관리자 지정

마이그레이션은 보안을 위해 관리자 계정을 자동으로 만들지 않는다. Supabase Dashboard의 Authentication > Users에서 운영자 계정의 UUID를 확인한 뒤, 권한 있는 SQL Editor에서 다음의 `운영자_UUID`만 실제 값으로 바꿔 실행한다.

```sql
insert into private.admin_roles (user_id, role)
values ('운영자_UUID', 'admin')
on conflict (user_id) do update set role = excluded.role;
```

권한을 부여한 계정으로 로그인한 뒤 `/admin/announcements`에 접속한다. 역할 부여 SQL과 service role 키는 브라우저 코드나 환경 변수에 넣지 않는다.

## 공지 노출 규칙

메모는 선택 입력이며 기존 `content` 필드에 저장한다. 홈 배너에 표시되지 않지만 발행 공지 조회 API에 포함되므로 비밀 정보를 입력하지 않는다.

- `홈에 공지 표시` 하나로 공개와 배너 노출을 제어한다. 저장할 때 기존 `is_published`, `show_in_banner`를 함께 켜거나 끈다.
- 기존 데이터는 두 값이 모두 켜져 있을 때만 표시 상태로 읽는다. 하나만 켜진 공지도 편집 후 저장하면 두 값이 함께 정리된다.
- 배너 표시 순서가 작은 공지가 먼저 표시되며, 순서가 같으면 최신 공지가 먼저 표시된다.
- 비공개로 저장한 공지는 다음 홈 조회부터 표시되지 않는다. 이미 열려 있는 홈은 새로고침해야 반영된다.

화면 회귀 검증은 `e2e/admin-ui.spec.ts`에서 Supabase 요청을 모두 가로채는 모의 응답으로 수행한다. 실제 로그인이나 운영 DB 쓰기는 발생하지 않는다.

공지 작성·수정은 운영 DB를 변경하므로 운영자 계정에서만 수행한다. 실제 입력 검증은 운영과 분리된 Supabase 환경에서 우선 수행한다.
