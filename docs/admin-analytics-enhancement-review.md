# 관리자 이용통계 추가 고도화 검토

후속 상태: 사용자가 미리보기 적용을 승인하여 [실제 앱 로컬 구현·검증](admin-analytics-enhancement-implementation.md)을 완료했다. 아래 내용은 설계/미리보기 작성 당시의 기록이며 운영 반영은 아직 하지 않았다.

작성: 2026-10-16 KST · 설계 검토 및 문서 보완만 수행

대상: [고도화 설계안](admin-analytics-enhancement-design.md), 현재 프론트엔드·통계 계약·로컬 SQL. 운영 상태는 앞선 설계의 2026-10-15 23:08 KST 읽기 전용 확인을 참조하며 이번 검토에서 원격 DB를 재조회하지 않았다.

## 결론

추가 가치가 큰 방향은 **이용 변화의 원인 후보를 좁히는 분석, 기능을 사용할 기회 대비 사용률, 채점 후 복습과 재이용, 결과 도달을 막는 대기 구간**이다. 구현 전에 코호트의 관찰 범위와 지표별 출처를 고정해야 한다. 기존 설계의 주 2일 채점 지표는 대표 지표에서 보조 지표로 조정한다.

| 우선순위 | 추가 제안 | 현재 자료로 가능한 범위 | 추가 수집 필요 |
|---|---|---|---|
| P0 | 코호트 관찰 창·정의·자료 시점 검증 | 기존 최초 이용·활동일·중단 기록으로 대조 | 계산/응답 계약 보완 가능 |
| P1 | 이용량 변화를 이용자 수와 반복 횟수로 분해 | 회원 채점 실행 수·회원 수, 세션별 전환 | 불필요 |
| P1 | 채점 후 복습·재이용 간격 | 과거 결과·기록이 있는 이력 조회·일별 활동 | 새 결과와 복습 도구의 정확한 연결에는 상관 ID 필요 |
| P1 | 계산→저장 대기→결과 표시 진단 | 단계 도달·저장 응답 관측 | 구간별 시간·오류 단계 |
| P1/P2 | 기능 사용 가능·노출·실행 구분 | 현재 행동 건수 | 사용 가능 상태·실제 노출 |
| P2 | 릴리스별 비교와 지표 정의 이력 | 배포 시점 메모를 수동으로 연결 가능 | 실제 실행 앱 버전 |
| P2 | 진입 목적별 첫 가치 도달 | 첫 관측 라우트·같은 세션의 행동 | 외부 유입 출처는 별도 최소 수집 필요 |
| P3 | 운영 검토 요약 | 가용 집계의 규칙 기반 요약 | 초기 외부 메시지·AI 시스템 불필요 |

## 1. 수치 감소를 설명하는 구성 요소

현재 주요 변화는 증감 발견에 적합하지만 대응할 대상을 고르기에는 정보가 부족하다. 예를 들어 채점 횟수 감소를 다음 세 축으로 분리한다.

- 회원 채점 횟수 = 채점한 회원 수 × 해당 회원당 평균 채점 횟수. 같은 기간·동일한 완료 실행·관리자 제외 기준으로 계산한다. 비회원 실행은 세션 기준 별도 표다.
- 채점 입력 세션 감소와 입력 이후 결과 관측률 감소를 나눈다. 전자는 진입/수요 변화, 후자는 흐름/수집/대기 문제를 점검할 근거다. 원인을 확정하지 않는다.
- 채널·OS·과목별 분모와 비율을 함께 본다. 모바일 비중이 커져 전체 관측률이 달라진 것과 모바일 내부 관측률이 달라진 것을 구분한다.

초기에는 한 번에 한 축만 분해하고 표본이 작은 조합을 자동 순위화하지 않는다. 채널별 회원은 겹치므로 단순 합으로 전체 회원 감소 기여도를 계산하지 않는다. 필요한 경우 PWA만/브라우저만/둘 다/기타처럼 상호 배타적인 집단을 쓴다.

**합격 기준:** 실행 수와 회원 수·회원당 실행 수의 계산이 일치하고, 같은 사람이 여러 채널을 사용해도 전체를 중복 합산하지 않는다. 작은 분모·자료 공백이면 '판단 보류'가 된다.

## 2. 기능을 사용할 기회가 있었는지 먼저 측정

기능 클릭 수만으로 선호도를 판단하기 어렵다. 현재 `QuestionStatistics`는 표시 설정·정답 버전 호환·통계 로딩 상태에 따라 사용 가능 여부가 달라진다. 답안 수정에도 저장 여부 등 조건이 있다.

제안하는 단계는 `사용 가능 → 화면에 노출 → 실행 → 결과 확인`이다.

- 사용 가능: 현재 결과/기능 진입에서 권한·데이터·호환 조건이 충족됨.
- 노출: 페이지가 visible이고 조작 요소가 화면에 들어온 것이 관측됨. DOM에 마운트됐다는 사실만으로 노출 처리하지 않는다.
- 실행: 클릭/펼침/저장 요청 등의 명시적 조작.
- 결과 확인: 데이터 표시 또는 저장 결과를 확인한 상태. 화면 열기와 실제 읽기/학습 완료는 구분한다.

예: 문항 분포 사용률의 분모를 전체 방문자 대신 '호환되는 통계가 준비되고 분포 버튼 노출이 관측된 결과 화면 진입 수'로 정의한다. 노출 신호 없이 클릭만 도착하면 '노출 미관측 실행'으로 별도 표시한다. 수집 차단을 사용률 100% 초과로 표현하지 않는다.

새 결과·이력·예시·기출 정답표를 구분한다. 현재 분포 열기 이벤트는 공유 컴포넌트에서 모두 `feature=grading`으로 보내므로, 기능 집계 해석에 실제 `route`와 새 제안 `surface`/결과 문맥이 필요하다. 과거 정의를 소급 변경하지 않는다.

노출 중복 키는 기능·화면 진입·대상 문맥으로 고정하고 문항별 스크롤 이벤트를 모두 수집하지 않는다. 상위 도구 단위로 시작해 이벤트 양을 제한한다. 노출 미수집 과거에는 채택률을 계산할 수 없다.

**운영 판단:** '버튼을 못 봄', '기능이 준비되지 않음', '봤지만 쓰지 않음'을 구분한 뒤 UI 변경안을 결정할 수 있다.

## 3. 채점 횟수와 복습 이용을 분리하고 자연스러운 재이용 간격 확인

초기 설계의 주 2일 채점은 이 서비스에 적합한 대표 지표라는 근거가 아직 없다. 주 1회 모의고사를 채점하고 나머지 날은 기록만 복습하는 사람을 놓칠 수 있다. 주 1회가 실제 대표 패턴이라는 주장도 현재는 가설이다.

기존 데이터로 먼저 나눌 수 있는 관측:

- 채점: 공식 `grading_completed`, 성공한 `mock_saved`.
- 복습: `past_result_viewed` 중 `entry_source=history`, 또는 `history_viewed`/`history_trend_viewed` 중 `has_records=true`.
- 탐색: 예시 결과·빈 이력·단순 페이지 조회. 복습으로 계산하지 않는다.

완료된 7일/28일 내 서로 다른 이용일 수와 다음 이용까지의 날짜 간격을 나란히 본다. 반복 사용이 있는 회원만 간격을 계산할 수 있으므로 반복 회원 수와 한 번만 관측된 회원 수를 함께 표시한다. 아직 돌아오지 않은 사람을 간격 평균에서 조용히 제외해 전체 사용자처럼 설명하지 않는다. 한 회원의 많은 반복이 분포를 지배하지 않도록 회원별 중앙 간격을 요약하는 방식을 검토한다.

'첫 채점 후 7일 내 복습 관측률'을 추가 후보로 둔다. 최초 채점 여부가 알려져 있고, 7×24시간의 후속 관찰을 완료했으며, 해당 구간 자료가 가용한 회원만 분모다. 최초가 불명인 기존 회원은 '기간 내 첫 관측 채점 이후'의 별도 코호트로 다룬다. 예시 결과를 복습 성공으로 세지 않는다.

현재 분포 열기에는 `grading_run_id`가 없으므로 동일 세션에 채점과 분포 열기가 있다는 이유만으로 해당 결과의 복습이라고 연결하지 않는다. 정확한 도구별 여정에는 개인정보 없는 결과 문맥 ID와 `new_grading/history/example` 구분을 추가해야 한다.

재이용 간격을 통해 제품의 사용 주기를 확인하는 방법은 [Amplitude 공식 문서](https://www.amplitude.com/docs/analytics/charts/retention-analysis/retention-analysis-usage-interval)와도 일치한다. 이 문서는 분석 정의 참고이며 SDK 도입 제안은 아니다.

## 4. 결과 표시 지연을 설명하는 최소 계측

확인한 코드: [HomePage](../src/pages/HomePage.tsx)의 `handleGrade`는 계산 후 `for...of` 안에서 과목별 `onAddToHistory`를 기다린 다음 `navigate('/result')`를 실행한다. [historyApi](../src/utils/historyApi.ts)는 요청당 20초 타임아웃을 둔다. 실제 운영 지연은 측정하지 않았으므로 장애 발생으로 단정하지 않는다.

앞선 설계의 '저장 응답과 결과 조회는 독립적으로 발생한다'는 표현은 이 실행 순서를 설명하지 못해 수정했다. 성공/실패라는 집계 분모는 분리하되 다음 대기 구간을 진단한다.

1. 채점 요청→로컬 계산 완료.
2. 계산 완료→각 과목 저장 호출 종료. 성공·실패·미확인과 대상 과목을 구분.
3. 전체 저장 처리 종료→결과의 실제 표시.

현재 수신 시각 차이로 지연을 계산하지 않는다. 새 계측은 동일 문서 단조 시계·실행 ID를 사용하고 전체 경과와 visible 경과를 분리한다. 완료 실행의 p50/p95에는 표본 수를 표시하고 미완료·시간 미측정 실행 비율을 함께 보여 준다. 여러 과목의 시간 합과 전체 시간을 혼동하지 않는다. 원본 답안이나 오류 메시지 전체는 필요하지 않다.

답안 없이 채점하려는 경우 현재 검증에서 `beginGrading` 이전에 반환하므로 요청 이벤트가 없다. 이 마찰을 분석하려면 `empty_input` 같은 허용된 사유의 별도 검증 이벤트가 필요하다. 기존 미관측을 이 검증 실패로 추정하지 않는다.

검증·대기 관측은 P1의 소규모 신규 수집으로 앞당길 가치가 있다. 저장 비동기화·선결과 표시 같은 제품 동작 변경은 이번 통계 설계의 실행 범위가 아니며 측정과 별도 UI 승인을 거쳐 판단한다.

## 5. 지표 정확성을 기능 추가보다 먼저 보완

### 후속 관찰 날짜의 공백

로컬 `product_analytics_report`는 전체 상태를 선택 시작/종료 구간과 수집 중단 기록으로 결정한다. D1/D7/D30 분기는 미래 날짜 성숙 여부와 활동일 존재를 검사하지만, 선택 범위 밖의 반환 날짜에 중단 기록이 있는지 별도로 검사하는 조건은 보이지 않는다.

예를 들어 10/5 최초 이용 코호트를 조회할 때 10/12에 수집이 중단됐다면 D7의 0건을 '미복귀'로 확정하면 안 된다. 이는 **로컬 SQL 정적 검토에서 찾은 검증 필요 항목**이며 운영에서 오류가 발생했다고 확인한 것은 아니다.

P0에 추가할 검증:

- D7은 해당 KST 날짜 전체, W1은 D+7~D+13 전체의 관측 가능 여부를 검사한다.
- 첫 채점 후 7일 분석은 각 회원의 정확한 관찰 구간에 중단이 겹치는지 검사한다.
- 관측 불가·미성숙·최초 불명 회원을 분모에서 분리하고 제외 건수와 이유를 표시한다.
- `first_usage_known` 하나가 여러 최초 조건을 묶는 현재 구조는 유지하되 불명 비중을 보여 준다. 조건별 known 분리는 이력이 충분한지 검토한 뒤 버전 있는 후속 변경으로 한다.

### 조회 시점과 자료 시점

기존 report의 `data_through=now()`는 마지막 수집 시각이 아니다. 새 응답은 `generated_at`, `last_accepted_at`, `coverage_through`, `observation_as_of`, `publication_generation`을 의미별로 구분한다. 아직 구현된 필드라고 가정하지 않는다.

같은 기간을 다시 조회해도 지연 수신·삭제·재발행·관찰 종료로 값이 바뀔 수 있다. 현재값은 최신 관측으로 재계산하되 과거 공유 보고서의 완전 재현은 별도의 집계 스냅샷 없이는 보장하지 않는다. 초기에는 조회 시각·계산 버전·가용 범위 표시부터 제공한다.

**합격 기준:** 반환일에만 중단이 있는 합성 사례에서 확정 0%가 나오지 않는다. 집계 분자≤분모, 기간 DISTINCT 비가산성, 재수신 불변, 원본/발행 중복 없음의 조건을 기존 SQL 검사에 추가한다.

## 6. 릴리스 비교와 기능별 관측 시작일

현재 이벤트 계약에 `metric_version`은 있으나 실제 실행 `app_version`은 없다. 배포일만으로 구버전 탭과 새 버전 이용을 구분할 수 없다.

- 검증된 빌드의 버전 문자열을 이벤트에 제한된 형식으로 추가하는 방안을 P2로 둔다. 구버전은 `unknown`으로 보존한다.
- 기능별 계측 시작일·계산 정의 버전·지원 환경을 관리한다. 전체 통계가 가용해도 새 이벤트를 아직 보내지 않는 클라이언트의 기능 이용을 0으로 표시하지 않는다.
- 배포·정답/통계 발행·수집 중단 같은 운영 변경을 그래프의 주석 후보로 둔다. 시점 일치가 인과의 증거는 아니다.
- 배포 전후 비교는 같은 요일·채널·이용 목적 구성과 분모를 함께 보여 준다. 현재 규모에서 세밀한 교차 필터와 자동 유의성 판정을 먼저 만들지 않는다.

## 7. 진입 목적별 첫 가치 도달

홈 채점을 쓰려는 세션과 기출 PDF를 받으려는 세션의 성공 기준이 다르다. 전자를 모두 가입 전환으로 평가하거나 PDF 클릭 세션을 채점 이탈로 분류하면 판단이 왜곡된다.

기존 페이지뷰로 가능한 범위는 '세션에서 처음 관측된 라우트'다. 이를 실제 최초 방문·외부 유입·검색 출처로 표현하지 않는다. 같은 관측 세션에서 홈→새 결과, 기출→PDF 클릭/참고표, 이력→실제 기록 조회를 나눠 볼 수 있다. PDF 클릭은 다운로드 완료가 아니다.

첫 화면 관측이 누락됐을 수 있음을 표시하고 세션/행위자 경계를 지킨다. 로그인 전후 기록은 현재 정책대로 소급 연결하지 않는다. 검색·광고·공유 출처 분석은 referrer 범주/허용 UTM 값의 최소 수집과 보관 정책을 별도 검토해야 하므로 첫 출시에서 제외한다.

## 8. 운영자가 다음 행동을 고르는 요약

기존 주요 변화 카드의 후속으로 각 항목을 다음 구조로 확장한다.

`관측 변화 → 확인한 분모·집단 → 자료 상태 → 다음에 열 분석`

예시 문구는 실제 수치가 확보된 경우에만 만든다. '결과 관측률 감소, 모바일 표본에서 감소 집중, 저장 응답 미관측도 증가, 채점 진단 보기'처럼 근거를 제시하고 '모바일 장애 발생'이라고 단정하지 않는다. 겹치는 집단의 감소분을 합산하지 않는다.

초기에는 규칙 기반 최대 3개를 유지한다. 자동 원인 진단·자연어 생성·운영자 개인별 자동 메시지는 필요하지 않다. 공유 필터는 비개인 조건만 저장하고 개인 상세나 검색어를 공유 링크에 넣지 않는다.

2. P1: 채점 퍼널과 이용량 분해. 대기시간 최소 계측을 별도 작은 작업으로 설계.

4. 충분한 자료 이후 릴리스 비교·운영 요약·유입 분석 중 필요한 항목을 선택.
