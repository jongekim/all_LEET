# 문형 대응·분야 보정·정답률 통합 확정 설계

확정일: 2026-10-12. **설계 확정 후 2026-10-12 로컬 구현·검증을 완료했다. 운영에는 적용하지 않았다.** 사용자 정책 결정과 [설계 검토](past-exam-form-design-review.md)의 R1~R8을 반영했다. 사용자의 구현 요청으로 앱·로컬 migration·도구·테스트를 개발했다. 운영 DB 적용·통계 발행·배포는 실행하지 않는다. [실제 구현·운영 경계](question-statistics-v2.md)를 따른다.

근거는 [원본 전수 검수](past-exam-form-analysis.md), 현재 코드, 2026-10-12의 [이력 품질 집계](../output/analysis/past-exam-forms/evidence/history-quality-2026-10-12.json)와 [통계 객체 조회](../output/analysis/past-exam-forms/evidence/statistics-schema-2026-10-12.json)다. 운영 조회는 읽기 전용이며 사용자 ID·이메일·개별 답안을 반환하지 않았다. 구현 전 원격 컬럼·정책·grants·함수 정의·마이그레이션을 재대조한다.

## 1. 확정 정책

| 항목 | 결정 |
|---|---|
| 정답률 표본 | 유효한 답안 객체가 있는 정상 저장 풀이를 모두 포함. 같은 사람의 여러 회독 포함 |
| 답안 객체 자체가 누락/null | 통계에서 제외하고 제외 건수를 내부 감사 정보로 보관. 원본 삭제·수정 없음 |
| 일부 문항 키만 누락/null/0 | 해당 문항의 미응답. 정상 표본으로 포함 |
| 빈 답안 객체 {} | 명시적 전 문항 미응답 표본으로 포함 |
| 정답률 분모 | 포함 표본 수. 미응답을 분모에서 빼지 않음 |
| 첫 풀이·고유 사용자 통계 | 이번 구현 제외. 후속 별도 지표로 검토 |
| 통계 갱신 | 기존처럼 개발자 수동 전체 발행. 개인 답안 수정 후 자동 발행하지 않음 |
| 기존 이력 | 원본·답안·정답·점수·회독·시각·묶음·메모 보존 |
| 화면 | 긴 통합 설명을 새로 추가하지 않음. 문항 번호·정답률·선지별 분포 중심 유지 |
| 분야 분석 계산 불가 | 잘못된 분야 수치를 표시하지 않음. 별도 안내 영역을 새로 추가하지 않음 |

표본 정책은 사용자가 직접 선택했다. 화면은 ‘길게 안내할 필요 없이 문항별 정답률을 보면 된다’는 요구를 따른다. 분야 계산 불가 사례는 실제 현재 데이터에서 0건이며, 수치 생략은 향후 예외의 방어 동작이다. 이번 확정은 실제 UI 변경을 실행한 의미가 아니다.

첫 구현은 공통 대응 데이터·공유 분야 계산·과거 분야 표시 보정·통합 통계·조회/HTML 변환이다. 새 문항 편집 화면·메모 통합 UI·오답 추천·최초 응답 복원은 포함하지 않는다.

## 2. 지원 범위와 기준 데이터

| 기능 | 범위 |
|---|---|
| 두 문형 대응 | 09예비 및 2009~2026, 1,350공통 문항·2,700문형 위치 |
| 채점·분야 분석 | 위 범위 + 현재 2027 단일 문형 자료 |
| 새 공개 통계 v2 | 09예비 및 2009~2026, 38학년도·과목 묶음·1,350문항 분포 |

2027은 통계의 명시적 범위 밖이다. 현재 채점·분야표·정답표·PDF는 유지한다. 기존 odd/even 키는 2027에서 단일 문형의 저장 별칭이며 원본 한 건을 두 번 매칭하지 않는다. 누락된 시험을 동일 대응으로 가정하지 않는다. 현재 통계 코드의 80조합과 기존 발행 함수의 76조합은 명시적 카탈로그로 분리한다. 채점 지원 목록을 통계 발행 목록으로 그대로 사용하지 않는다.

기준과 생성 자료의 책임은 다음과 같다.

- 대응 기준은 검수한 1,350행. 분석 자료의 canonical_question_id를 그대로 사용한다. 예: 2025:reasoning:E04, 2009-preliminary:reasoning:E14. 표시 번호가 바뀌어도 동일 문제의 ID를 재발급하지 않는다.
- 실제 정답 기준은 기존 _shared/user-data-rules/answerData.ts의 문형별 정답표. 공통 정답은 여기서 생성하고 별도 수동 수정하지 않는다.
- 과거 분야 기준은 같은 파일의 현재 짝수형 fieldMapping. 공통 ID에 분야를 연결하고 문형별로 조회한다. 2027은 기존 단일 문형 분야표를 명시적으로 조회한다.
- 작은 JSON·TypeScript·DB 등록 카탈로그를 하나의 생성 경로에서 만든다. 원문·OCR·이미지는 앱 번들에 포함하지 않는다. 생성 파일을 독립 수정하지 못하게 검사한다.
- 원본 문서 해시·개정판 관계를 보존한다. 내용이 다른 문제를 같은 번호라는 이유로 묶지 않는다. 이번 자료는 검수한 원본 개정판으로 고정한다.

버전은 mapping_version/mapping_sha256, classification_version, 문형별/공통 정답 버전, catalog_id/catalog_sha256, aggregation_version으로 구분한다. 분야 분류만 바뀌면 분포 건수는 같으므로 분야 버전만으로 정상 통계를 무효화하지 않는다. 통계 호환은 대응·정답·카탈로그·집계 계약으로 판단한다.

## 3. 분야 계산과 과거 이력

공유 함수는 학년도·과목·문형·실제 문항 번호를 받아 **실제 번호 → 공통 ID → 분야**로 조회한다. 분야별 questions는 실제 문제지 번호이며 현재 분야 명칭·순서를 유지한다.

| 학년도·과목 | 홀수형 번호 | 대응 짝수형 번호 | 분야 |
|---|---:|---:|---|
| 2025 추리논증 | 3 | 4 | 과학기술 |
| 2025 추리논증 | 4 | 3 | 법규범 |
| 2025 추리논증 | 19 | 20 | 인문 |
| 2025 추리논증 | 20 | 19 | 사회 |
| 2026 추리논증 | 11 | 12 | 논리학수학 |
| 2026 추리논증 | 12 | 11 | 법규범 |

새 채점·답안 수정·관리자 재계산은 같은 순수 분야 계산 함수를 사용한다. 기존 정답·점수 환산은 교체하지 않는다. 분야 보정으로 전체 정답 개수·환산 점수가 바뀌면 실패다.

과거 보정은 저장 당시 correctAnswers와 userAnswers를 사용한다. 정상 부분 답안의 누락/null/0은 미응답이다. 등록 문항 수·완전한 저장 정답·유효한 답안·답안 기반 정답 수와 저장 correct의 일치를 검사한다. 판정은 ready, missing_answers, missing_answer_key, inconsistent_result, invalid_record, example으로 구분한다. ready만 보정 수치를 제공하고 나머지는 원본을 보존하며 내부 진단한다. 설명용 예시는 실제 이력의 보정 대상과 분리한다.

보정이 필요 없는 기존 정상 분야 자료는 유지할 수 있다. 필요한 보정을 계산할 수 없으면 잘못된 이전 분석을 최신 분류처럼 표시하지 않는다. 총점에 맞춰 답안을 만들거나 관리자 수정 점수를 자동 수정하지 않는다. 전체 성적·답안·메모는 계속 제공한다.

useUserHistory는 저장 원본을 그대로 보관한다. ResultPanel/FieldAnalysis에는 표시 분석을 별도로 전달하고, EditableAnswers·소유자 PUT·관리자 snapshot 비교에는 원본 전체 JSON을 전달한다. 보정 상태·버전을 원본에 덧붙이지 않는다. 수정 성공 후 실제 저장 응답을 원본으로 교체하고 표시 분석을 재계산한다. 전송 중 초안은 반영 결과와 섞지 않는다.

## 4. 표본 검증·분할

기존 KV의 history:% 배열을 DB 내부의 한 읽기 스냅샷에서 검증·집계한다. 개인 원본을 내려받지 않으며 사설 기록·예시 자료는 제외한다.

먼저 JSON 형식·학년도·과목·문형·문항 수·존재하는 답안 객체의 키/값을 검사하고 각 기록을 정확히 한 종류로 분류한다.

| 분류 | 조건 | 처리 |
|---|---|---|
| included | 범위 안 정상 메타데이터 + 유효한 답안 객체 | 공통 집계에 1회 포함 |
| excluded_out_of_scope | 명시적 범위 밖 정상 2027 기록 | 제외 건수 보관 |
| excluded_missing_answers | 범위 안 정상 메타데이터이나 답안 객체 누락/null | 제외 건수 보관 |
| invalid | 알 수 없는 조합·잘못된 형식·문항 수·답안 키/값 | 발행 중단 |

2027도 존재하는 답안이 잘못됐으면 invalid다. 정상 2027은 답안 누락 여부와 무관하게 out_of_scope로만 센다. 범위 안 빈 객체는 전 문항 미응답으로 포함한다. 숫자 문자열·범위 밖 번호·배열/스칼라 답안은 임의 보정하지 않는다. 배열이 아닌 이력 컨테이너는 별도 오류다.

~~~text
source_count = included_count + excluded_out_of_scope_count
             + excluded_missing_answers_count + invalid_count
sum(38개 묶음 sample_count) = included_count
각 문항의 선지 5개 건수 합 + unanswered_count = 해당 묶음 sample_count
~~~

invalid 또는 잘못된 이력 컨테이너가 있으면 발행하지 않는다. 정상 제외는 0건이 아니어도 발행 가능하다. 분할 건수·정책·카탈로그·읽기 시각은 내부 감사 자료에 보관한다. 공개 응답에는 개인 정보·제외 원인별 개인 기록·수행자 정보를 노출하지 않는다.

통계는 현재 승인 정답표로 계산한다. 저장 correct/correctAnswers 불일치는 분야 보정 적합성 문제이며, 정상 답안 객체의 현재 정답 기준 통계에서 자동 제외할 이유는 아니다. 다만 과거 개인 결과의 저장 정답표가 현재와 다르면 그 화면에는 현재 통계를 함께 표시하지 않는 기존 동작을 유지한다.

## 5. 공통 집계·화면 데이터 계약

정책 버전은 **pooled_saved_answers_v2**로 고정한다. 표본 정책과 의미가 달라 기존 all_saved_records_v1로 발행하지 않는다.

1. 원본 문형·실제 번호로 공통 ID를 찾는다.
2. 선택 1~5는 명시적 순열로 기준 선지에 연결한다. 미응답은 그대로 유지한다.
3. 공통 ID·기준 선지별 건수를 합산한다.
4. 공통 정답 건수를 포함 표본 수로 나눈다. 문형별 비율을 평균하지 않는다.
5. 화면에는 실제 문항 번호순으로 문항을 배치하고 선지 건수·정답 번호를 함께 변환한다.

같은 문제의 정답률 동일성은 같은 공통 ID·정답·표본 정책·발행 세대에서 성립한다. 서로 다른 시각/캐시 세대까지 실시간 동일하다고 보장하지 않는다.

다음은 신규 타입 계약이며 현재 API가 아니다.

| 타입 | 내용 | 소비 위치 |
|---|---|---|
| LegacyFormStatistics | 원래 문형·번호·선지 건수·v1 세대 | 오프라인 비교 검증 |
| CanonicalStatistics | 공통 ID·기준 정답·선지 건수·표본 수·세대·카탈로그/대응/정답/집계 버전 | 발행·공통 캐시 |
| FormStatisticsView | 실제 문형·번호·로컬 정답·재배열 선지 건수·공통 ID·기준 버전 | 버튼·모달·공개 HTML |

QuestionRate에 공통 배열을 직접 전달하지 않는다. FormStatisticsView 생성 함수 하나가 번호·선지·정답을 함께 변환한다. 카드·모달·정답표·HTML이 이 함수를 공유한다. PDF·문항 포커스·메모·모달의 번호는 실제 문형 기준이다.

공통 캐시는 학년도·계약·세대·카탈로그/대응 버전으로 공유한다. 화면 결과 키에는 과목·실제 문형·정답 버전을 추가한다. 문형 변경 시 열린 통계 모달의 연결을 초기화하고 늦은 응답을 차단한다. 현재 5분 캐시·포커스 재조회·표시 설정·오류 시 개인 기능 유지 동작을 보존한다.

한 문형의 0표본과 누락을 구분한다. 누락 행을 0건으로 가정하지 않는다. 전체 38묶음·1,350ID를 검증해 부분 발행을 금지한다. 0표본은 기존처럼 —로 표시한다. 30건 이하 경고는 합산 포함 표본 기준이며 고유 사용자 수·통계적 신뢰도를 뜻하지 않는다.

## 6. 저장·권한·발행

2026-10-12 객체 조회에서 다음 v2 객체는 존재하지 않았다. **아래 이름과 책임을 신규 구현 대상으로 확정**한다. 기존 v1 객체·KV는 보존하며 실제 DDL/grants는 구현 전 원격 전체 스키마 대조 후 작성한다.

| 신규 객체 | 책임 |
|---|---|
| private.question_statistics_catalogs_v2 | 승인된 불변 카탈로그: ID·대응·승인 정답·범위·버전·해시 |
| private.question_statistics_runs_v2 | 세대·읽기 시각·건수 분할·검증 파일·수행자/사유·발행/롤백 감사 |
| public.question_statistics_snapshots_v2 | (snapshot_id, year, subject) 기준 38개 공통 분포 |
| public.question_statistics_publication_v2 | 현재 v2 세대 포인터 |
| private.publish_question_statistics_v2 | 승인 카탈로그·검증 파일의 원자 전체 발행 |
| private.rollback_question_statistics_v2 | 지원 가능한 정상 v2 세대로 포인터·감사 원자 변경 |

문항 items는 question_id·기준 정답 선지·5개 선택 건수·미응답 건수를 보관한다. 묶음은 question_count, sample_count, catalog_id/해시, 대응·정답·집계 버전, 원본/발행 시각을 제공한다. 문형별 투영 배열을 공개 저장소에 복제하지 않는다. 내부 검증 파일은 발행 감사·재현을 위해 보존한다.

신규 테이블은 전부 RLS를 적용한다. anon/authenticated는 현재 v2 포인터와 해당 세대의 공개 스냅샷 SELECT만 가능하다. private 카탈로그·원본·감사·과거 세대·발행/롤백 RPC에는 브라우저 권한이 없다. 기존 개발자 Management API를 사용하며 브라우저 service role·신규 공개 쓰기·통계 Edge·Cron·저장 트리거를 추가하지 않는다.

카탈로그는 생성 자료에서 등록하고 불변 보관한다. 발행 파일의 카탈로그와 서버 승인 내용이 일치해야 한다. 문항 ID 집합·번호/선지 순열·정답·안전 정수·선택/미응답 합계·건수 분할식·파일 체크섬을 검사한다. 38라는 숫자뿐 아니라 예상 전체 조합·문항 집합을 검증한다.

발행/롤백은 private SECURITY INVOKER·명시적 권한·예상 현재 세대 검사·트랜잭션 advisory lock을 사용한다. 외부 확인과 준비 계산은 발행 전에 끝낸다. 38묶음·발행 기록·포인터를 한 트랜잭션으로 저장하고 실패 시 기존 세대를 유지한다. 같은 파일 재실행은 기존 결과를 식별하며 과거 파일 재공개는 명시적 롤백이다.

과거 카탈로그·매핑·정답은 세대와 함께 보존한다. 새 버전은 새 불변 카탈로그로 등록하고 지원 가능한 버전만 표시·롤백한다. 오류가 확인된 카탈로그는 롤백 대상에서 제외한다. 현재 자료에 없는 개정판·답안을 자동 편입하지 않는다.

## 7. 구버전 호환·운영 전환

**v1을 새 앱의 통합 정답률 fallback으로 사용하지 않는다.** v1 공개본에는 답안 객체 누락 표본을 제외할 정보가 없어 v2 정책을 복원할 수 없다. v1은 같은 원본 읽기 시각의 오프라인 비교에만 사용한다. 문형 통합·미기록 답안 제외·신규 기록의 영향을 구분해 검증한다.

1. v1 테이블·포인터·발행본을 보존하면서 v2 객체·승인 카탈로그를 추가한다.
2. v2 클라이언트·HTML 생성기를 검증한다. v2 미발행/미지원은 통계 미가용 상태이며 개인 채점·답안·메모는 제공한다.
3. 읽기 전용 prepare 검증 후 v2 전체 세대를 원자 발행하고 새 DB 공개 읽기·권한·빌드를 확인한다.
4. 새 웹·HTML을 배포한다. 기존 탭/PWA는 갱신 전 v1을 유지할 수 있으며 갱신 후 v2를 사용한다. 강제 로그아웃·개인 이력 삭제·화면 전체 차단은 하지 않는다.
5. v1 경로는 이번 릴리스에서 제거하지 않는다. 후속 명시적 작업 전까지 동결 보존하고 자동 갱신하지 않는다.

구버전과 새 버전의 일시적 차이는 전환 경계다. 새 버전의 두 문형은 같은 v2 세대를 쓴다. 새 배포 실패 시 기존 앱을 유지한다. 정상 이전 v2 세대가 있으면 v2 롤백을 사용하고, 첫 발행에서 문제가 있으면 웹 전환을 중단한다.

공개 HTML은 빌드에 사용한 통계 세대·매핑을 고정한다. DB 발행 후 재빌드·배포해야 HTML이 갱신된다. 브라우저의 더 최신 세대 조회는 정상 갱신이며 오래된 HTML 값과 합쳐 한 분포를 만들지 않는다.

## 8. 사용자 화면

문항 번호·정답률 버튼·5선지/미응답 분포·정답 강조·시험 선택·접힘·표시 설정·메모·PDF·문항 이동을 유지한다. 긴 통합 원리 설명·대응표·집계 버전을 새로 표시하지 않는다.

통합값에 맞지 않는 짝수형 전용 다회독 문구는 제거한다. 오류·미발행·0표본·30건 이하 상태 안내는 유지한다. 기존 설명의 ‘전체 채점 기록’ 표현은 ‘답안이 저장된 풀이 기록’으로 필요한 만큼만 정정하고 긴 새 설명으로 확장하지 않는다. 통계 대응/버전 문제를 개인 정답 오류처럼 안내하지 않는다.

계산 불가인 과거 분야에는 새 안내 UI를 추가하지 않고 잘못된 분야 수치를 표시하지 않는다. 전체 성적·답안·메모는 유지한다. 정상 기록의 레이아웃은 유지한다. 현재 실제 데이터에서 이 분기가 발생하는 기록은 0건이다.
