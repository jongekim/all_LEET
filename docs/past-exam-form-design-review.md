# 문형 대응 설계 검토

검토일: 2026-10-12. 대상은 [통합 설계안](past-exam-form-implementation-plan.md)이다. 구현 전 문서 검토이며 운영 DB·앱·UI·통계는 변경하지 않았다. 현재 로컬 코드와 2026-10-11의 원격 스키마 보존본을 근거로 검토했다. 아래 장애는 해당 조건으로 구현할 때 생길 수 있는 문제이며, 아직 존재하지 않는 v2 구현에서 발생했다고 주장하는 것은 아니다.

**확정 설계 반영 완료:** 사용자 정책 결정과 실제 이력의 읽기 전용 집계 확인 후 R1~R8을 [확정 설계](past-exam-form-implementation-plan.md)에 반영했다. 아래 내용은 초안에 대한 검토 이력으로 보존한다. 실제 확인된 5,717개 기록과 보정 대상 488개는 모두 재계산 가능했고 답안 미기록·정답 개수 불일치는 0건이었다. 향후 예외를 위한 검증 조건은 유지한다.

| 검토 항목 | 확정 설계 반영 위치 |
|---|---|
| R1 지원 범위 | 2장 |
| R2 범위 밖 기록·미기록 답안 | 4장 |
| R3 공통/화면 데이터 | 5장 |
| R4 호환·롤백·HTML | 6~7장 |
| R5 과거 분야 분석 | 3장 |
| R6 기준 데이터·버전 | 2·6장 |
| R7 사용자 표시 | 1·8장 |
| R8 반례 검증 | 10장 |

**결론: 공통 문항 기준의 분류·통계 구조는 타당하지만, 현재 설계안만으로 구현을 시작하기에는 예외와 전환 계약이 부족하다.** 저장 원본 보존, 건수 합산, 선지 역변환, 반복 풀이 정책 분리는 유지한다. 다음 8개 항목을 먼저 구체화한다. P1은 첫 적용 전 필수 경계, P2는 결과 해석·유지보수의 중요한 보완이다.

## R1 — P1: 2027 채점 지원과 통계 제외를 분리

설계안의 ‘2027 제외’가 레지스트리 조회 전체에 적용되면, 공통 분야 조회를 사용하는 현재 기본 학년도 2027 채점까지 실패할 수 있다. 기존 코드는 2027 단일 문형에 대해 분야표를 이미 갖고 있으며 두 과목 모두 5개 분야를 반환한다.

필요한 계약은 다음과 같다.

- 과거 두 문형의 대응 레지스트리: 09예비~2026.
- 채점·분야 조회: 위 레지스트리와 별도로 2027의 검증된 단일 문형 자료를 유지.
- 통계 v2 발행 범위: 첫 버전은 09예비~2026의 38개 과목 묶음.
- 2027의 odd/even은 기존 저장 키의 별칭으로 처리한다. 별칭 때문에 원본 기록 하나가 두 번 매칭되지 않도록 한다.

레지스트리 누락 시 모든 시험을 동일 대응으로 처리하는 fallback은 금지한다. 2027 단일 문형에 한해 명시적으로 정의한 조회 경로를 사용한다. 같은 학년도라는 이유로 채점·PDF·통계 지원 여부를 하나의 boolean으로 합치지 않는다.

완료 조건: 2027 만점 입력·미응답 입력의 현재 총점·분야·정답표 동작 유지, 2027 공개 통계는 아직 미발행, 2027 별칭 원본 기록 한 건당 집계 최대 한 건.

## R2 — P1: 범위 밖 정상 기록을 잘못된 기록으로 취급하지 않기

현재 집계는 전체 `history:%`를 읽고, 카탈로그에 매칭되지 않는 기록을 잘못된 데이터로 분류한다. 발행 검증도 `included_count == source_count`를 요구한다. 2027 통계를 제외하면서 이 검증을 유지하면 2027 저장 기록이 있는 경우 과거 통계 발행까지 막힌다. 2027 기록의 실제 운영 존재 여부는 이번에 조회하지 않았다.

새 발행 계약에는 검증된 범위 분할을 정의한다.

```text
전체 원본 기록 수
  = 집계 범위 안 정상 기록 수
  + 명시적 범위 밖 정상 기록 수
  + 잘못되었거나 미확인인 기록 수
```

첫 범위 밖 목록에는 2027을 명시한다. 실제 기록의 학년도·과목·문형·문항 수·답안 값이 정상인지 확인한 후 범위 밖으로 센다. 알 수 없는 학년도나 깨진 2027 기록은 이 목록에 넣어 숨기지 않는다. 배열이 아닌 이력 컨테이너는 별도 오류로 유지한다. 잘못되었거나 미확인인 기록이 하나라도 있으면 발행을 중단한다.

38개 공통 과목의 `sample_count` 합계는 집계 범위 안 정상 기록 수와 같아야 한다. 범위 밖 건수는 개발자 감사 정보에 별도 기록한다. 범위를 좁혔다고 개인 원본을 삭제하지 않는다.

완료 조건: 과거 기록과 정상 2027 기록이 함께 있어도 과거 집계를 준비할 수 있음, 잘못된 기록은 계속 차단, 총건수 분할식과 공통 표본 합계 일치.

## R3 — P1: 공통 통계와 화면용 통계를 서로 다른 타입으로 정의

현재 `QuestionRate`는 `snapshot.items[question - 1]`를 읽고 표시 문형의 정답 번호로 비율을 계산한다. 공통 문항 순서의 배열을 이 컴포넌트에 그대로 전달하면, 번호 이동 문항에서 다른 문제의 분포를 읽는다. 선지만 재배열해도 이 문제는 남는다.

합성 사례에서 2025 추리논증 홀수형 3번의 올바른 공통 문항은 짝수형 4번이며 정답률은 90%였다. 번호 투영을 생략하고 기존 인덱스 조회에 전달하면 0%가 계산됐다. 실제 서비스 정답률이 아니라 실패 방식 확인용 합성 값이다.

최소한 다음 세 가지 데이터 경계를 구분한다. 이름은 제안이며 현재 코드의 API가 아니다.

| 제안 타입 | 포함 정보 | 전달 대상 |
|---|---|---|
| 원본 문형 통계 | 원래 문형·문항 번호·선지 건수·원본 발행 메타데이터 | 비교용 변환 입력 |
| 공통 통계 | 공통 문항 ID·기준 선지 건수·통계 세대·레지스트리 버전 | 공통 캐시·발행 |
| 화면용 문형 통계 | 공통 문항 ID·실제 문형·실제 번호·현지 정답 번호·재배열된 선지 건수 | 정답률 버튼·분포 모달·HTML |

화면용 변환은 문항 번호와 선지 번호를 한 번에 처리하고, 모든 표시 문항에 대해 공통 ID가 맞는지 검사한다. 공통 선지 ID·정답 번호를 로컬 선지 번호로 오인하지 않는다. 화면에는 원래 문제지의 번호·정답·메모·PDF·포커스 이동을 유지한다.

공통 캐시는 문형을 공유할 수 있지만, 화면 결과의 식별 키에는 학년도·과목·실제 문형·발행 세대·대응 버전을 포함한다. 정답 문자열이 같은 두 문형도 선지 대응이 다를 수 있다. 선택 변경 후 늦은 요청·이전 화면의 열린 모달이 새 문형에 잘못 적용되지 않게 한다.

완료 조건: 이동 40문항과 선지 변경 187문항의 번호·정답·오답 분포 모두 올바름, 문형을 빠르게 바꿔도 옛 결과 미표시, 카드와 모달과 HTML이 동일한 변환 경로 사용.

## R4 — P1: 구버전 클라이언트·롤백·HTML을 위한 전환 규칙

설계안은 이전 버전 호환을 언급하지만 전환 시점의 동작이 정해져 있지 않다. 현재 클라이언트는 v1의 문형별 행과 `all_saved_records_v1`만 파싱한다. 기존 공개 포인터와 스냅샷을 38개 공통 묶음으로 바로 교체하면 이미 열려 있는 탭과 오래된 PWA가 통계를 읽지 못할 수 있다. 현재 HTML 빌드 검증도 기존 스냅샷 형태를 요구한다.

권장 전환은 다음과 같다.

1. v1 공개 읽기·현재 포인터·기존 발행본을 보존하면서 v2 계약을 추가한다. 실제 저장 방식과 RLS는 원격 확인 후 결정한다.
2. v1과 v2를 구분해 읽는 클라이언트·HTML 생성기를 먼저 준비한다. v1을 원본 문형 통계로 파싱하고, 검증된 변환 뒤 화면용 통계를 만든다. v1 데이터에 없는 대응 버전이 있다고 가정하지 않는다.
3. v2는 전체 카탈로그를 한 트랜잭션으로 발행한다. 단순히 38행이 있다는 확인을 넘어, 예상 학년도·과목·문항 ID 집합이 정확히 존재하는지 검사한다.
4. 새 클라이언트의 통합 기준 전환과 공통 안내를 함께 적용한다. 구버전 클라이언트의 v1 유지 기간과 지원 종료를 명시한다. 오래된 클라이언트까지 즉시 같은 수치를 보장하려면 별도 호환 출력과 업데이트 방침이 필요하다.
5. v2 오류 시 해당 버전의 검증된 이전 세대로 롤백한다. 구버전 원본으로 되돌아갈 경우 새 앱은 같은 변환 계약을 거쳐야 통합 의미를 유지한다. 문형별 통계를 통합 수치처럼 조용히 대체하지 않는다.

레지스트리가 수정되면 과거 통계 세대와 함께 그 당시 대응을 보존하거나, 지원 가능한 과거 버전을 명시해야 한다. 현재 대응표로 과거 세대를 무조건 재해석하면 롤백 결과도 변할 수 있다. 부정확한 매핑으로 만든 세대로의 롤백은 지원 목록에서 제외한다.

‘같은 문제의 정답률이 같다’는 같은 원본 표본·집계 정책·정답 버전·발행 세대에서의 계약이다. 이미 배포된 HTML·다른 세대의 브라우저 캐시까지 실시간으로 동일해지는 것은 아니다. 두 과목을 읽는 동안 발행 포인터가 바뀌면 다시 읽고 한 세대로 맞춘다.

완료 조건: 새 발행 시 구버전 앱 미중단, 빈/부분/혼합 세대 차단, 캐시 무효화, 지원하는 매핑 버전의 롤백, HTML 빌드·배포 실패 시 기존 공개본 보존.

## R5 — P2: 과거 분야 보정의 가능 여부와 실패 시 화면

저장 원본과 표시 분석 분리는 적절하다. 그러나 ‘불완전한 답안’의 정의와 계산 불가 시 표시 방식이 빠져 있다.

누락된 문항 키는 현재 서비스에서 미응답이다. `userAnswers`의 키 개수가 전체 문항 수보다 적다는 이유만으로 재계산 불가로 처리하면 정상 부분 답안까지 제외된다. 답안 객체 자체가 없는 기록과, 답안 객체가 있으나 일부 키가 없는 기록을 구분해야 한다. 존재하는 답안 객체에서 누락/null/0의 해석은 채점·통계의 정의와 같게 둔다.

현재 관리자 `mutationPatch`는 답안 재계산 없이 `correct`를 단독 수정할 수 있다. 실제 순수 함수 검증에서 전부 맞은 답안 40개를 유지하면서 `correct:39` 수정이 허용됐고, 분야 정답 합계는 40이었다. 이런 기록에 ‘전체 정답 수는 보존하면서 분야 합계도 같게 한다’는 조건을 동시에 강제할 수 없다. 원본 수정 없이 숫자를 맞추려 하지 않는다.

분야 표시 보정에 필요한 판정 결과를 구분한다.

| 상황 | 권장 처리 |
|---|---|
| 정상 답안 객체·완전한 저장 정답·문항 수 일치·답안에서 계산한 정답 수와 저장 정답 수 일치 | 최신 분야표로 표시 분석 생성 |
| 일부 문항 키 누락, 나머지 답안 정상 | 누락 키는 미응답으로 처리하고 위 일관성 검사 |
| 답안 객체 부재, 저장 정답 불완전, 문항 수 불일치 | 재계산 불가 |
| 관리자 수정 등으로 저장 정답 수와 답안 기반 정답 수 불일치 | 일관성 확인 불가. 보정 결과를 확정 표시하지 않음 |
| 설명용 예시 결과 | 실제 저장 기록의 보정 대상과 구분 |

보정이 필요한 기록을 계산할 수 없으면, 잘못된 기존 분야 분석을 최신 분석처럼 다시 보여 주지 않는다. 전체 성적·답안·메모는 유지하고 분야 분석에 자료 부족/일관성 확인 불가 상태를 제공하는 것을 권장한다. 문구 예시는 ‘분야별 분석을 다시 계산할 답안 자료가 부족하거나 저장 결과와 일치하지 않습니다.’다. 실제 UI 적용은 별도 구체적 승인을 받는다.

`ResultPanel`/`FieldAnalysis`에는 보정 분석을 별도 값으로 전달하고, `EditableAnswers`·일반 PUT·관리자 snapshot 비교에는 저장 원본을 그대로 전달한다. 새 보정 상태·버전 정보를 전체 원본 JSON에 덧붙여 충돌 검사 입력을 바꾸지 않는다.

완료 조건: 빈 답안 객체와 답안 부재 구분, 정상 부분 답안 지원, 관리자 수정 기록의 모순된 확정 분석 방지, 수정 전후 원본 동등성 유지, 저장·비저장·관리자 화면에서 같은 판정.

## R6 — P2: 정답·분야·매핑의 기준 데이터 중복 방지

공통 레지스트리에 기준 정답·분야를 저장하면서 기존 `ANSWER_DATA`도 독립 수정 가능하게 두면 기준이 두 개가 된다. 현재 설계는 배열 변환의 정답 일치를 검사하지만, 어떤 파일이 기준이고 어떤 것이 생성 산출물인지 명시하지 않았다.

첫 구현에서는 실제 채점 정답의 기준은 기존 문형별 정답 자료로 유지한다. 레지스트리의 기준 정답이 필요하면 해당 자료에서 생성하고 손으로 별도 수정하지 않는다. 분야도 기준 분류표 하나와 문형별 대응으로 생성한다. JSON·TypeScript·집계 입력은 한 생성 파이프라인과 동일한 버전·내용 해시에서 파생한다. 생성한 파일을 따로 편집하지 못하게 검사한다.

정답이 그대로인 채 오답 배열만 바뀌는 경우도 있으므로 정답 버전 일치만으로 통계 호환을 인정하지 않는다. 통계 버전·문항/선지 매핑 버전·질문 ID 집합을 모두 검사한다. 분야 버전은 분포 건수가 같아도 분야 분석의 변경을 설명하기 위해 분리한다. 지원하지 않는 매핑 버전은 해당 통계의 표시를 중단하고 개인 채점·답안·메모는 계속 제공한다.

실패 사유도 구분한다. 대응 버전 미지원·부분 통계·정답 버전 불일치를 모두 현재의 ‘정답 버전이 달라…’ 안내로 처리하면 사용자가 자신의 정답이 잘못됐다고 오해할 수 있다. 내부 상태에는 실제 원인을 보존하고, 사용자 안내는 개인 성적과 무관한 통계 표시 문제임을 설명한다. 실제 문구 적용은 별도 승인 범위다.

원본 PDF와 표시 PDF의 수정판이 생길 때는 문형 대응의 문서 버전 관계를 남긴다. 문항 내용이 달라졌는데 기존 ID를 영구 유지해야 한다는 이유로 다른 문제를 묶지 않는다. 단순 번호 재배치는 같은 ID로, 실질적 문제 교체는 새 ID 또는 명시적 수정판 관계로 다룬다.

완료 조건: 손으로 수정한 생성 파일·잘못된 버전 매핑 거절, 같은 정답 문자열/다른 오답 배열 사례에서 버전 불일치 감지, 수정판의 다른 문제 합산 방지.

## R7 — P2: 통합 정답률의 의미·경고·갱신 경험

합산은 표본의 정의를 일관되게 만들지만 문항의 실전 정답률을 추정하는 문제를 해결하지는 않는다. 회독이 많은 사용자·부분 답안·미응답·문항 위치가 섞인다. 문형별 화면 설명은 ‘선택한 문형의 정답률’로 읽히지 않아야 한다.

권장 공통 안내의 내용은 다음과 같다. 이는 제안 문구이며 실제 앱 변경은 아니다.

> 같은 문제의 홀수형·짝수형 저장 기록을 합산한 정답률입니다. 선지별 선택률은 현재 문제지 순서로 표시합니다. 미응답을 포함하며, 같은 사람의 여러 풀이가 반영될 수 있습니다.

짝수형만의 기존 안내를 대체하고 결과·기출 정답표·모달·HTML에 같은 의미를 적용한다. 상세 모달에는 문항 번호·문형을 계속 보여 준다. 표본 부족 경고의 기준은 합산한 저장 기록 수이며, 31건 이상을 독립된 31명의 응시나 높은 신뢰도로 설명하지 않는다. 한 문형이 0건인 경우에도 다른 문형 표본으로 통합값이 있을 수 있음을 지원한다.

0건이 검증된 문형과 데이터가 누락된 문형을 구분한다. 양쪽 중 하나가 누락됐다고 0건으로 가정해 ‘통합’ 값을 표시하지 않는다. 같은 세대의 완전한 카탈로그에서 0건이 확인될 때만 합산한다.

개인 답안 수정은 기록 하나를 갱신하지만 공개 통계는 수동 발행본이므로 즉시 바뀌지 않는다. v2에서도 이 정책을 유지한다면 수정 완료를 통계 실시간 갱신처럼 안내하지 않는다. 반복 저장 기록 기준 통계이며 최초 응답 시도 전체를 복원한 지표라고 표현하지 않는다. 예고 없이 자동 발행이나 최초 풀이 중복 제거를 같이 추가하지 않는다.

현재 SQL은 `userAnswers` 객체 전체가 없거나 null인 정상 형식의 기록도 전 문항 미응답으로 센다. 이런 기록이 실제로 얼마나 있는지는 확인하지 않았다. 답안이 저장되지 않은 상태와 사용자가 전부 비워 제출한 상태는 의미가 다르다. 통합 후 정확도가 개선됐다고 주장하기 전에 답안 객체 미기록 건수를 읽기 전용 감사 항목으로 확인해야 한다. 기존 정책을 유지하더라도 이 한계를 명시하며, 미기록 답안 제외는 별도 집계 정책 변경으로 다룬다. 원본에 없는 답안을 저장 정답 개수로 복원하지 않는다.

완료 조건: 두 문형의 동일 기준 안내, 합산 표본 경고·0건·누락 분리, 정답률 표시 설정 유지, 개인 수정 직후 성적/통계 갱신 시점의 설명 일관성.

## R8 — P2: 기존 검증으로 잡히지 않는 반례 추가

현재 검수된 선지 순열은 모두 자기 자신의 역순열과 같다. 동일 배열·역순·`[4,5,3,1,2]`만으로 검사하면 앞으로의 구현에서 정방향과 역방향을 혼동해도 통과할 수 있다. 이는 현재 대응표가 잘못됐다는 뜻이 아니다.

다음 사례를 구현 검증에 추가한다.

| 사례 | 확인할 결과 |
|---|---|
| 가상 순열 `[2,3,1,5,4]`, 역순열 `[3,1,2,5,4]` | 양방향 함수의 정확한 방향과 두 번 변환 방지 |
| 정답은 둘 다 ③, 오답 배열은 다른 두 문형 | 같은 정답만으로 분포를 호환 처리하지 않음 |
| 번호 이동 두 문항에 완전히 다른 분포 부여 | 선지뿐 아니라 문항 ID도 변환 |
| 정상 부분 답안·객체 부재·전체 미응답·관리자 정답 개수 수정 | 분야 재계산 가능/불가 상태 정확 |
| 정상 2027·손상된 2027·알 수 없는 학년도 | 범위 밖 정상/발행 차단 오류 구분 |
| 한 문형 0건·한 문형 행 누락 | 합산 가능과 불완전 데이터 구분 |
| 지원되지 않는 매핑 버전·과거 세대 롤백 | 잘못된 최신 매핑으로 재해석하지 않음 |
| 빠른 문형 전환·통계 숨김·열린 모달·HTML 이후 새 세대 조회 | 늦은 응답·수치/문형 불일치·불필요한 조회 방지 |

합성 순열별 총건수 검사는 좋은 기초지만 원본 기록 검증 → 번호·선지 변환 → 집계 → 공개 DTO → 화면·HTML까지 연결된 사례 검증을 대체하지 못한다.

## 판단과 다음 작업

최종 공통 통계 구조를 유지하되, R1~R4의 범위·DTO·전환 계약을 설계안에 먼저 반영하고 R5~R8의 상태·사용자 설명·검증 조건을 구체화하는 것을 권장한다. 이번 검토만으로 미확정 운영 스키마를 정하거나 기존 사용자 기록을 고치지 않는다. 추가 메모 DB·문항 편집 UI·최초 풀이 지표는 첫 구현의 필수 범위에서 제외한다.

읽기 전용 순수 함수·합성 계산으로 번호 투영 실패, 관리자 단독 정답 개수 수정 허용, 2027 현재 채점 유지, 범위 분할식, 비대칭 순열의 필요성을 확인했다. 실제 v2 구현·발행·브라우저 전환은 아직 실행하지 않았으며 별도 통합 검증이 필요하다. 검토 문서는 별도 커밋으로 보존할 수 있고 이 작업 자체에는 push·배포가 필요하지 않다.
